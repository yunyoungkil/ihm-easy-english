# 적용 추적과 학습 루프

## 목표

조사에서 발견한 아이디어를 비교 시트에 적는 데서 끝내지 않는다. 실제 결과물에 적용했는지, 공개 후 어떤 결과가 나왔는지, 다음 기획이 무엇을 배웠는지 잇는다.

## 1. 출처에서 다음 판단까지 연결

| 단계 | 추적 내용 |
|---|---|
| 원천 | 출처·원본 식별자·게시/수집 시점·조건 |
| 해석 | 관찰 사실과 추정, 우리 시청자·학습 가치와의 연결 |
| 결정 | 채택·변형·보류·배제 이유와 자료의 한계 |
| 적용 | 실제 제목·썸네일·대본 문장·컷 등 결과물 위치 |
| 공개 | 영상 ID·날짜·형식·길이·함께 바뀐 요소 |
| 결과 | 지표·측정 기간·비교 기준·표본·한계·다음 행동 |

현재 비교 시트의 필드와 실제 검사 기능부터 확인한다. 이미 있는 연결을 모른 채 중복 필드를 추가하거나 시트만 복잡하게 하지 않는다. “영상에 반영함”처럼 위치를 확인할 수 없는 기록은 적용 증거가 아니다. 적용하려던 요소가 렌더에서 빠지면 상태와 이유를 갱신한다.

## 2. 성과 해석의 한계

조회수·CTR 하나가 성공이나 원인을 설명하지 않는다. 노출량, 유입 경로, 게시 시점, 영상 길이·형식, 주제 적합도, 시청자 구성, 동시 변경을 함께 살핀다.

- 클릭 지표는 노출과 표본을 확인한 뒤 해석한다. 쇼츠 피드 등 다른 유입을 클릭률 하나로 설명하지 않는다.
- 유지·완주·구독·롱폼 연결 등은 서로 다른 목표다. 어느 하나로 영상의 모든 품질을 대표하지 않는다.
- 가능한 한 같은 형식·역할·측정 기간끼리 비교하고 차이가 있으면 한계를 쓴다.
- 표본이 작거나 결과가 흔들리면 가설 또는 초기 신호로 남기며 성공 패턴·기준선으로 승격하지 않는다.
- 실험 중 시안이 섞였으면 실제 노출 시안과 측정 창을 확인한다.
- 사전 예측은 결과가 나온 뒤 맞춰 고치지 않는다. 당시 가설과 사후 해석을 구분해 보존한다.
- 수치가 좋아도 영상이 학습 약속·브랜드를 해치면 전체 성공으로 판정하지 않는다.

## 3. 다음 편에 환류

결과는 “좋았다/나빴다”로 끝내지 말고 관찰, 가능한 설명, 아직 모르는 점, 다음에 확인할 선택지로 적는다. 이전 결과를 재사용할 때는 원래 맥락과 한계를 다시 확인한다. 다른 주제의 결과를 무리하게 일반화하지 않는다.

실패·미적용·부적합 데이터도 학습 자산이다. 단, 근거 없는 “성공 공식”을 쌓아 다음 창작을 좁히지 않도록 검증된 사실과 가설을 구분한다. 비교 시트의 적용 기록과 공개 영상, 성과 정산의 연결이 끊기면 루프 완료로 보지 않는다.

## 4. 구현 전 부수 영향 점검

워크플로 변경은 화면·보고서·오래된 데이터·캐시·백필·검사·문서에 연쇄 영향을 줄 수 있다. 코드를 고치기 전 다음을 조사한다.

- 기존 형식과 과거 기록 호환, 원본 보존·재계산·복구 방법.
- 결측·실패·중복·낡은 값이 화면과 자동 판정에 미치는 영향.
- 서버와 브라우저, 리포트와 시트의 계산 일치.
- 사람이 계산값을 중복 입력하거나 수집 원본을 검증된 판단처럼 보게 하는 위험.
- 실제 소비처 없는 수집 증가 여부, 비용·쿼터·외부 약관·실패 처리.
- 데이터 소비 지도·문서 인덱스·검사·인수인계 누락 여부.

현재 AGENTS.md 및 해당 작업의 테스트·확인 조건을 따른다. 이번처럼 문서 전용 요청에 구현을 끼워 넣지 않는다. 자동화나 코드 적용은 별도 요청의 범위를 확인한 뒤 진행한다.

## 제미나이 분석 실행 지시



이 절은 감사 관점의 참고 지침이다. 실제 코드 감사·수정·전체 분기 검증을 요청할 때는 [04 Gemini 워크플로우 루프 구현 프롬프트](04-gemini-workflow-loop-implementation-prompt.md)를 실행 진입점으로 사용한다. 04를 전달받으면 구현까지 명시적으로 요청한 것이므로 이 절의 분석 전용 범위보다 04의 실행 지시를 따른다.

1. 범위와 기준 브랜치를 확인하고 관련 문서만 읽는다. knowledge/index.md, 데이터 소비 지도, 브랜드/전략 원본, 비교 시트 플레이북, 관련 코드와 검사를 필요한 만큼 대조한다.
2. 조사 데이터→유효성/비교→기획 입력→비교 시트→실제 제작→공개 성과→다음 판단의 현재 흐름을 그린다.
3. 오염 데이터·배율 계산·한국 트렌드·다중 레퍼런스·브랜드 적합성·적용 추적·환류를 점검한다. 이미 수정된 부분은 실제 상태를 확인하고 중복 제안하지 않는다.
4. 각 문제에 재현 근거, 영향 데이터/화면/파일, 채널 영향, 최소 수정 방향, 부수 영향, 수용 확인 방법을 붙인다. 사실·추정·제안·미확인을 구분한다.
5. 제안이 단일 기준 채널, 고정 창작 유형·제목 공식, 근거 없는 수치 문턱, 무조건적인 트렌드 삽입을 새로 만들지 않는지 비판적으로 재검토한다. 하드코딩 금지 자체를 새 고정 분류표로 바꾸지 않는다.
6. 기존 확정 원칙과 충돌하면 조용히 덮어쓰지 말고 영향과 선택지를 보고한다. 결과는 확인된 문제·수정안·부수 영향·수용 조건·사용자 결정 필요 항목으로 정리한다.

## 완료 판단

출처에서 결과물의 실제 적용 위치로 이어지고, 성과의 해석 한계가 남으며, 다음 편의 구체적 판단으로 연결돼야 한다. 확인하지 않은 데이터나 적용을 완료처럼 표현하지 않는다.
