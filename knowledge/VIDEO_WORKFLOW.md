# 영상 제작 표준 워크플로우

마지막 갱신: 2026-08-24

이 문서는 롱폼, 시즌 Track A·B, 채널 쇼츠 C를 제작할 때 공통으로 따르는 단계와 완료 조건이다. 각 영상 프로젝트는 루트에 `STATUS.md`를 두고 이 문서의 10단계 상태를 기록한다. 채팅 기억이나 작업자의 추측보다 `STATUS.md`의 현재 단계와 다음 행동을 우선한다.

## 상태 값

| 상태 | 의미 |
|---|---|
| `not_started` | 아직 시작하지 않음 |
| `in_progress` | 현재 작업 중 |
| `review` | 자동 작업은 끝났고 사용자 확인 대기 |
| `approved` | 사용자가 방향·내용을 승인함 |
| `complete` | 해당 단계의 산출물과 검증이 모두 완료됨 |
| `blocked` | 외부 입력이나 사용자 결정 없이는 진행할 수 없음 |
| `skipped` | 이 영상에는 불필요하며 이유가 기록됨 |

한 단계가 끝났다고 다음 단계가 자동 승인되는 것은 아니다. 일정, 공개, 최종 렌더처럼 중요한 판단은 사용자 확인 후 상태를 변경한다.

## 전체 흐름

```text
1. 제작 우선순위
→ 2. 기획·콘셉트
→ 3. 대본·구성안·스토리보드
→ 4. 음성·타이밍
→ 5. 디자인·모션 명세
→ 6. 미디어 준비
→ 7. HyperFrames 제작
→ 8. 동기화·사운드
→ 9. 검수·렌더링
→ 10. 업로드·성과 분석
→ 다음 영상의 1단계
```

## 1. 제작 우선순위 결정

### 순서 (2026-08-26 확정)

1. **아이디어 추천** — 유튜브 리서치(경쟁 채널 동향)와 채널 자체 성과 데이터(`npm run content-opportunity`,
   `data/youtube/`)를 근거로 소재 후보를 뽑는다. 감으로 정하지 않는다.
2. **5개를 표로 제시** — 소재/각도별로 5개, 사용자가 하나를 고른다.
3. 고른 소재로 아래 "확정할 것"을 채운다.

### 확정할 것

- 콘텐츠 유형: 롱폼 / Track A / Track B / 채널 쇼츠 C.
- 지금 제작해야 하는 이유와 채널에서의 역할.
- 연결할 롱폼 또는 이전·다음 영상.
- 기존 제작물·예약 일정·공개 공백을 고려한 우선순위.

### 산출물

- `knowledge/now.md`의 현재 우선순위.
- 프로젝트 `STATUS.md`의 `content`, `objective`, `current_stage`, `next_action`.

### 완료 조건

- 다른 미완성 영상보다 먼저 해야 하는 이유를 한 문장으로 설명할 수 있다.
- 소재 선택이 리서치/성과 데이터 또는 그걸 근거로 한 5개 후보 중 사용자 선택에서 나왔다.

## 2. 기획·콘셉트 확정

### 확정할 것

- 기획 의도와 한 편을 본 뒤 얻어야 할 한 가지 이해.
- 핵심 시청자와 영상의 역할: 도달, 구독, 롱폼 이동, 시청 시간 중 우선 목표.
- 콘셉트·톤앤매너·색감·스타일·리듬.
- 레퍼런스와 각 자료에서 참고할 것·사용하지 않을 것.
- 성공 판단 지표.
- 제작 시작일, 초안 검토일, 렌더 목표일, 업로드 예정일.
- 외부 TTS·이미지·음악·유료 소스 비용과 승인 필요 여부.
- **제목·썸네일(문구+이미지)을 대본보다 먼저 확정한다.** `knowledge/thumbnail-strategy.md` 체크리스트
  (효과/숫자/타깃/명확성/길이/궁금증/역할분리, addiction-loop, 3-step viewer psychology)로 6열 표
  (제목/썸네일 문구/프롬프트 한글·영문/하이퍼프레임 스토리보드/내 생각) 5안을 제시하고 사용자가 고른다.
  이미지는 사용자가 직접 생성해서 고른다(Claude가 API로 대신 생성하지 않음).
- **썸네일 이미지 파일을 저장할 위치도 이 단계에서 함께 정한다.** 썸네일이 확정된 순간 아이디어
  단계는 끝난 것이므로, 저장 위치를 나중 단계에서 물어보지 않는다. 업로드 패키지ID(`s{시즌}-ep{NN}-{종류}`)가
  아직 없으면(콘텐츠 JSON·업로드 패키지 미생성 단계) `videos/<프로젝트>/thumbnail.png`에 즉시 저장하고,
  10단계에서 `build-upload-package.mjs` 실행 시 `output/upload-packages/<패키지ID>/thumbnail.png`로 옮긴다.

### 산출물

- HyperFrames 프로젝트의 `BRIEF.md`.
- 레퍼런스는 원본 경로와 적용 판단을 `BRIEF.md` 또는 에피소드 문서에 기록.
- 확정된 제목·썸네일 문구·이미지(다음 단계인 대본이 이 훅에 맞춰 쓰인다).
- 저장된 썸네일 이미지 파일(`videos/<프로젝트>/thumbnail.png`, 위치는 `BRIEF.md`에 기록).

### 완료 조건

- 목적, 대상, 결과물, 레퍼런스, 일정, 비용, 금지 사항에 미확정 값이 없다.
- 미확정 값은 추측하지 않고 `미확정`으로 표시한다.
- 제목·썸네일이 확정됐다 — 대본 단계로 넘어가기 전에 완료돼야 한다.
- 썸네일 이미지 파일이 실제로 저장돼 있다 — "나중에 저장 위치를 정한다"로 미루지 않는다.

## 3. 대본·구성안·스토리보드

### 확정할 것

- 내레이션, 화면 문구, 자막, 강조 철자·한글 음절, CTA.
- 도입→전개→결론 또는 질문→생각→정답→원리→복습→CTA 구조.
- 각 장면의 목적, 초점, 발화, 동작, 전환.
- **나레이션 구조에 중독 루프(Stakes → Big Question → Head Fake → Rehook)를 적용한다.** 도입에서
  이해관계(Stakes)를 만들고, 구체적인 질문(Big Question — 막연한 티저 금지)을 던지고, 예상을 깨되
  납득되는 반전(Head Fake)으로 답하고, **결말을 완전히 닫지 않고 다음 편으로 이어지는 구체적인 여운
  (Rehook)을 남긴다.** 결말을 다 닫아버리는 실수를 반복했으니(EP10 롱폼, 시즌2 WANT TO 테스트) 매번
  확인할 것.
- **대본은 2단계에서 이미 확정된 제목·썸네일 훅에 맞춰 쓴다** — 순서가 중요하다: 썸네일이 먼저,
  대본은 그다음(2026-08-26 확정, 이전엔 "대본 단계에서 같이 정한다"고 잘못 적었었음). Head Fake의
  반전 문구와 Rehook 문구는 썸네일 캡션·제목과 같은 표현을 그대로 재사용해 일관성을 만든다.
- **길이는 "썸네일·제목이 약속한 걸 충분히 풀어주는 데 필요한 만큼"이지, 다른 편 길이를 참고하는 게
  아니다.** 시즌1 다른 편 분량에 맞추려고 관련 없는 소재를 끼워 넣지 않는다 — 특히 **다음 편 Rehook의
  소재를 이번 편에서 먼저 설명해버리면 안 된다**(실제로 WANT TO·GOTTA를 같은 영상에 넣으려다 걸러낸
  사례 있음, 2026-08-26). 분량을 늘려야 하면 같은 주제를 더 깊게 판다 — 예외 상황, 예측형 미니 퀴즈,
  격식·캐주얼 구분, 리스닝 트레이닝(실제 속도 문장에서 직접 찾기), 소리 내어 따라 하기 같은 항목을
  후보로 제시하고 사용자가 고른다.
- **종결어미를 다양하게 섞는다.** 존댓말 안에서도 문장마다 "~요"로만 끝나면 TTS로 들었을 때 단조롭다
  — "~습니다/입니다", "~죠", "~네요", "~요"를 섞어 리듬을 만든다.

### 산출물

- `SCRIPT.md`: 시간, 내레이션, 화면 동작이 연결된 확정 원고. Head Fake/Rehook 대사가 2단계에서 정한
  썸네일 문구·제목과 동일한 표현을 쓴다.
- `STORYBOARD.md`: 두 장면 이상이면 필수. 한 프레임 실험도 비트가 여러 개면 작성한다.
- `BRIEF.md`의 `storyboard`와 실제 파일 상태를 일치시킨다.

### 완료 조건

- 화면 문구와 발화 문구가 구분되어 있다.
- 퀴즈 질문 발화에는 목표 영어 단어의 정답 발음이 없고, 정답은 생각 시간 뒤의 별도 발화로만 공개된다.
- 왕초보 기준으로 한 문장에 하나의 정보만 있다.
- 나레이션에 Rehook(다음 편으로 이어지는 구체적 여운)이 있는지 확인했다 — 시즌 마지막 편처럼 정말
  다음이 없는 경우만 예외로 남기고 이유를 기록한다.
- Head Fake·Rehook 대사가 2단계에서 확정한 썸네일 문구·제목과 표현이 맞는다.
- 대본과 스토리보드가 `approved` 상태다.

## 4. 음성 제작·타이밍 분석

### 작업

- 확정 대본으로 TTS 또는 실제 음성을 준비한다.
- 발음, 목소리 일관성, 앞뒤 무음, 속도를 실제로 듣고 확인한다.
- 문장·핵심 철자·한글 음절·정답 공개 타이밍을 기록한다.
- 실제 발화 길이를 영상 시간축으로 사용한다.

### 산출물

- 프로젝트 내부의 최종 음성 파일.
- `SCRIPT.md` 또는 별도 타이밍 데이터의 문장·강조 큐.

### 완료 조건

- 잘못 읽힌 TTS가 없고, 화면을 추정 길이에 억지로 맞추지 않는다.
- 질문 TTS만 따로 들어도 정답 발음이 노출되지 않으며, 질문 뒤 생각 시간이 확보돼 있다.

## 5. 디자인·모션 명세

### 확정할 것

- 화면비, 안전영역, 팔레트, 폰트, 위계, 외곽선, 카드 사용 규칙.
- 고정 브랜드 요소와 이번 영상에서 실험할 자유 영역.
- 어떤 이해 순간에 어떤 모션이 필요한지.
- 장면 전환과 카메라 이동을 사용하는 이유.

### 산출물

- `frame.md`를 색상·폰트·강조 관계의 단일 기준으로 사용.
- `STORYBOARD.md`에 장면별 모션과 전환을 기록.

### 완료 조건

- `고급스럽게`, `역동적으로` 같은 추상어만 남아 있지 않다.
- 요소·위치·스타일·동작·타이밍이 필요한 수준까지 구체화돼 있다.

## 6. 미디어 준비

### 작업

- 음성, 이미지, 영상, 폰트, 아이콘, 효과음, 음악을 프로젝트 내부에 고정한다.
- 원본과 가공본을 파일명으로 구분한다.
- 생성 이미지나 레퍼런스에는 역할과 출처·생성 여부를 기록한다.

### 완료 조건

- 임시 URL, 브라우저 세션, 렌더 시점 네트워크 파일에 의존하지 않는다.
- 필요한 자산 누락이 없다.

## 7. HyperFrames 제작

### 작업

- 입력과 목적에 맞는 워크플로를 선택한다.
- `BRIEF.md`, `SCRIPT.md`, `STORYBOARD.md`, `frame.md`를 기준으로 구성한다.
- 기존 승인본을 덮어쓰지 않고 실험안은 별도 프로젝트로 보존한다.
- Studio 미리보기를 유지하며 작은 단위로 수정한다.
- **스케치 패스(와이어프레임, 빈 타임라인) 단계에서 `npx hyperframes snapshot --at <시간들>`로
  콘택트시트를 찍어 사용자에게 보여준다.** `STORYBOARD.md` 텍스트만으로는 실제 구성·타이밍의
  느낌이 안 잡힌다는 게 확인된 문제라, 디자인·모션을 다 입히기 전에 실제 렌더 프레임으로
  한 번 먼저 확인한다 — 2026-08-25 결정.

### 완료 조건

- 모든 장면과 음성 트랙이 Studio 타임라인에서 확인된다.
- 디자인·구조 초안이 사용자 검토 가능한 상태다.
- 스케치 패스 콘택트시트를 사용자가 확인했다(레이아웃·비트 순서 승인, 최종 룩앤필은 다음 단계에서 확인).

## 8. 음성·자막·모션·사운드 동기화

### 우선순위

```text
음성 → 철자 강조 → 한글 발음 강조 → 자막 → 핵심 모션 → 전환 → 효과음 → 음악
```

### 완료 조건

- 실제 발화와 강조색·자막·정답 공개가 맞는다.
- 효과음은 질문·정답·핵심 연결·CTA에만 사용한다.
- 설명 구간에서 장식 모션이 학습 초점을 빼앗지 않는다.

## 9. 검수·수정·렌더링

### 자동 검수

- `npx hyperframes check` 통과.
- 런타임, 넘침, 충돌, 모션, 대비 오류가 없다.

### 사람 검수

- 소리를 켜고 처음부터 끝까지 한 번 재생한다.
- 무음으로 다시 재생해 자막과 시각적 이해를 확인한다.
- 시작·중간·끝 프레임과 모바일 가독성을 확인한다.
- TTS 발음과 음량 균형을 확인한다.
- 각 퀴즈에서 질문 음성 → 생각 시간 → 정답 음성 순서를 실제 청취로 확인한다.

### 완료 조건

- 사용자 `render_approved: true` 기록 전에는 최종 렌더하지 않는다.
- 렌더 후 파일 존재, 크기, 길이, 재생 가능 여부를 확인한다.

## 10. 업로드·성과 분석

### 업로드

- 제목, 썸네일, 설명, 태그, 고정 댓글, 관련 영상, 재생목록, 예약 시각을 확정한다.
- 콘텐츠 원본 JSON과 통합 업로드 요약 HTML을 함께 갱신한다.
- 공개 후 고정 댓글, 엔딩 화면, 관련 영상 연결을 확인한다.

### 분석

- 48시간, 7일, 28일 성과를 같은 역할·유사 길이 영상과 비교한다.
- 조회수만 보지 않고 유지율, 시청 시간, 구독 전환, 롱폼 이동, 제작 시간을 함께 본다.
- 유지할 요소, 개선할 요소, 폐기할 요소, 다음 검증 가설을 기록한다.

### 완료 조건

- 분석 결과가 다음 영상의 1단계 우선순위와 2단계 기획에 반영된다.

## 매 작업 시 상태 갱신 규칙

1. 작업 시작 전 프로젝트 `STATUS.md`에서 `current_stage`와 `next_action`을 확인한다.
2. 단계가 바뀌거나 승인·실패·새 결정이 생기는 즉시 `STATUS.md`를 갱신한다.
3. 사용자 승인이 필요한 값은 임의로 `approved` 또는 `complete`로 바꾸지 않는다.
4. 같은 정보는 `STATUS.md`에 짧게, 상세 근거는 `BRIEF.md`·에피소드 문서·월별 로그에 둔다.
5. 작업 완료 전 `npm run wiki:lint`를 실행한다.

## 템플릿
