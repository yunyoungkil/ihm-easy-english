# Phase 12: 쇼츠 파생과 다음 영상 연결

롱폼 한 편을 만들면 거기서 끝내지 않는다. 쇼츠로 새 시청자를 데려오고, 롱폼끼리 이어 보게 만들어 구독으로 연결한다.

**왜 필요한가 (2026-11-06 점검)**: 최근 90일 조회수의 96%가 쇼츠에서 나왔는데, 9월 2일 이후 쇼츠 공개는 0개다(`knowledge/now.md`). 채널 전략도 "쇼츠는 신규 도달과 구독 획득, 롱폼은 신뢰와 시청 시간"으로 역할을 나눈다(`knowledge/channel-strategy.md` 성장 구조). 롱폼만 내면 새 시청자가 들어올 길이 거의 없다.

**언제 하나**: 이미 완성했거나 공개한 롱폼은 새 기획 없이 바로 장면을 고른다. 형식 배분 판정이 쇼츠를 가리키면 새 롱폼 기획보다 먼저 한다. 새 롱폼은 대본(Phase 8)이 확정된 뒤 제작 단계에서 함께 계획하고, Phase 5에서 "세트"로 정했으면 그 설계를 따른다. 공개 요일과 주간 공개 수는 `knowledge/channel-strategy.md` "주간 목표" 표를 따르고, 미정이면 사용자에게 묻는다.

**올리는 방법 (2026-11-06)**: 자동 예약 업로드는 쇼츠와 롱폼을 구분하지 않는다. 쇼츠 패키지의 `status.json`을 `ready_to_upload`로 두면 롱폼과 같은 대기열에 들어가 월·목 칸을 차지하고 롱폼을 뒤로 밀어낸다. 자동 업로드가 쇼츠를 따로 다루기 전까지 쇼츠는 그 상태로 두지 않고, 사용자가 스튜디오에서 직접 예약한다. 렌더링한 쇼츠는 `output/upload-packages/ep<번호>-shorts-<이름>/`에 검색어 이름 영상, 제목·설명·고정 댓글, 자막과 함께 넣고 `status.json`은 만들지 않는다(2026-11-07, 상세: `knowledge/production-rules.md` 렌더 저장 위치 관례). 그러면 대시보드의 같은 번호 롱폼 카드에 쇼츠 탭으로 보이고, 스튜디오에서 예약하면 대시보드가 제목으로 찾아 `shorts-status.json`에 상태를 적어 "예약 · 날짜"로 보여 준다(2026-11-08).

**쇼츠 제작 순서와 썸네일 시점 (2026-11-09 사용자 지적, EP27~29 쇼츠에서 썸네일 단계를 빠뜨려 대시보드 썸네일이 비었다)**:

1. 소재 후보와 장면 고르기 (`SHORTS.md`)
2. 대본 쓰기, `FACT-CHECK.md` → 비교 시트 승인(대본 확정)
3. **그림 프롬프트(`visual-prompts.md`)와 썸네일 프롬프트(`thumbnail-prompts.md`)를 함께 쓴다.** 쇼츠 제목이 이미 정해져 있어 제목·롱폼 썸네일과 말이 겹치는지 바로 비교할 수 있고, 사용자가 이미지를 한 번에 만들 수 있으며, 이미지 생성을 기다리느라 렌더링과 업로드가 늦어지지 않는다. 소재 후보 단계나 대본을 쓰는 중에는 만들지 않는다(대본이 바뀌면 다시 써야 한다).
4. Gate 1(비교 시트 승인) 후 AI Studio 자동 생성(`scripts/generate-aistudio-speech.mjs`, `npm run image`, `npm run video`)으로 음성과 시각 에셋을 준비한다 → 화면 제작, 검수, Gate 2(렌더 승인) 후 렌더링
5. 업로드 패키지를 만들 때 `thumbnail.jpg`가 있는지 확인한다. 없으면 패키지를 만들었다고 보고하지 않고 "썸네일 없음"을 먼저 알린다. 시작 브리핑(`growth-check`의 `missingThumbnails`)도 썸네일이 없는 패키지를 알려 주며, 공개된 패키지는 뺀다.

## 1. 쇼츠 파생 (롱폼 1편당 2개 기본)

`knowledge/content-formats.md`의 쇼츠 형식을 쓴다.

| 형식 | 구조 | 이 롱폼에서 고를 장면 |
|---|---|---|
| Track A 퀴즈형 | 발음 판별 → 생각 시간 → 정답 → 최소 원리 → 롱폼 연결 | 롱폼의 퀴즈·짝단어 비교 구간 |
| Track B 반전·발견형 | 익숙한 단어의 예상 밖 발음 → 원리 발견 | 롱폼 훅(F01)이나 "반전 꿀팁" 구간 |
| 채널 쇼츠 C | 롱폼과 독립된 확장형 | 여러 편에 걸친 공통 원리 |

1. 롱폼 `SCRIPT.md`에서 쇼츠로 뺄 장면 2개를 고르고, 각각 어느 형식인지 정한다. A와 B는 같은 화면을 복제하지 않는다(`content-formats.md` Track B 규칙).
2. **첫 1초 훅**을 장면마다 한 줄로 적는다. 쇼츠는 첫 화면에서 넘겨지면 끝이다.
3. **제목 비교**: 최근 쇼츠 5개 제목과 나란히 보여 주고, 앞부분이 같은 틀이면 다시 쓴다(`knowledge/legacy/agents-archive-2026-11-27.md` "같은 틀의 영상을 찍어 내지 않는다" 절 3번).
4. 화면 규칙은 `knowledge/production-rules.md` "쇼츠 화면" 절, 금지어는 SKILL.md 상단 표를 따른다.
5. 산출물: `videos/<프로젝트>/SHORTS.md`(장면, 형식, 훅, 제목 시안, 연결할 롱폼).
6. 쇼츠 대본을 쓰면 롱폼과 같이 `FACT-CHECK.md`를 만든다(`03-script-and-narration.md` 5절). 롱폼 대본에 있던 설명을 가져와도 다시 확인한다.
7. 대본이 확정되면 썸네일 프롬프트도 이어서 쓴다(위 "쇼츠 제작 순서" 3번, 아래 2절 쇼츠 썸네일 규칙).
8. **기획 근거 기록 (2026-11-11, 묻지 않고 적는다)**: 쇼츠 프로젝트 `BRIEF.md`에도 `01-topic-and-data.md`와 같은 형식의 `## 기획 근거` 절을 둔다. 쇼츠는 7일 조회가 편당 1,000회 안팎이라 우리 숫자로 판정이 나오는 유일한 형식이다(롱폼은 지금 크기로는 보류). 이 칸이 없으면 대시보드 "기획 근거 성적표"와 경쟁 채널 상태가 쇼츠 결과에서 아무것도 배우지 못한다.
   - `경쟁 영상`: 쇼츠 장면을 고를 때 참고한 경쟁 쇼츠(`market-demand.json`의 `topOutliersByFormat.short`). 없으면 "경쟁 근거 없음".
   - `시청자 고민`: 이 쇼츠가 답하는 `audience-dna.json` 항목. 없으면 "없음".
   - `형식`: Track A 퀴즈형 / Track B 반전·발견형 / C 확장형 중 하나. 형식별 성적을 비교할 때 쓴다.

## 2. 롱폼으로 연결하기

쇼츠를 본 사람이 롱폼으로 넘어와야 시청 시간과 구독이 쌓인다.

- **눌리는 링크는 스튜디오의 "관련 동영상" 설정이다(2026-11-07 확인)**: 쇼츠의 설명란과 댓글 링크는 2023년 8월 31일부터 눌리지 않는다(https://tubefilter.com/2023/08/10/youtube-shorts-comments-spam/). 관련 동영상은 채널 이름 아래 눌리는 링크로 보이며, 고급 기능 권한이 필요하고 공개나 일부 공개 영상만 고를 수 있다(https://support.google.com/youtube/answer/14075157). 설명란 첫 줄과 고정 댓글에는 링크 대신 롱폼 제목을 적는다.
- **쇼츠 마지막 5초에는 말, 아래를 가리키는 손 그림, 롱폼 썸네일을 함께 넣는다(2026-11-07)**. 유튜브 공식 블로그의 권장 사항이고 효과 수치는 없다(https://blog.youtube/creator-and-artist-stories/youtube-related-videos-traffic-guide/). 손 그림은 화면 가운데에 두고(사용자 결정), 움직임은 위아래로 튀는 것과 효과음 1번으로 둔다. 화면 깜빡임은 넣지 않는다(`knowledge/script-rules.md` 1·4번 차분한 톤).
- **쇼츠 썸네일 (2026-11-08)**: 2026년 7월부터 스튜디오에서 쇼츠에도 직접 만든 썸네일을 올릴 수 있지만, 제목·썸네일 테스트(A/B)는 쇼츠에서 되지 않아 1장만 만든다. 세로 9:16(1080×1920)으로 만들고, 곳에 따라 잘려 보이므로 글자와 그림은 높이 15~75% 안에 두고 아래 25%(쇼츠 목록에서 제목이 겹치는 자리)는 비운다. 그림체는 쇼츠 화면과 같은 마커 손그림, 글자는 굵은 고딕, 큰 글자와 알약 합쳐 5단어 이하, 퀴즈의 정답은 넣지 않는다. 쇼츠 제목·롱폼 썸네일과 같은 말을 쓰지 않는다. 문구 5안을 표로 보여 주고 추천 1안의 프롬프트를 `videos/<쇼츠 프로젝트>/prompts/thumbnail-prompts.md`에 쓴다. 완성본은 쇼츠 패키지의 `thumbnail.jpg`로 둔다(대시보드 쇼츠 탭에 보임). 예시: `videos/ep24-shorts-sheep-ship/prompts/thumbnail-prompts.md`.
- **스튜디오에서 올릴 때 언어 두 칸 (2026-11-08)**: 세부정보의 "동영상 언어"와 "제목 및 설명 언어"를 둘 다 한국어로 고른다. EP24 쇼츠는 스튜디오로 올렸는데도 "제목 및 설명 언어"가 비어 있었다. 자동 업로드는 코드가 둘 다 ko로 보낸다.
- 쇼츠에는 직접 만든 한국어 자막을 올린다(2026-11-07 사용자 결정, 자동 자막이 "셜"을 "혈"로 적은 사례). 문제를 내는 동안에는 정답 단어를 자막에 적지 않는다.
- 롱폼은 **제목이나 내용으로** 가리킨다("-ED 소리 3가지 전체 영상"). 화면에 `EP28` 같은 내부 번호를 쓰지 않는다(`production-rules.md` 공개 일정 절).
- 효과는 롱폼 유입 경로 `SHORTS_CONTENT_LINKS`로 본다. 2026-06-01~11-07 기준은 쇼츠 조회 52,546회에 이 경로의 롱폼 조회 33회다(그 기간의 쇼츠 전부에 링크가 있던 것은 아니다).
- 롱폼이 아직 공개 전이면 체크리스트에 "롱폼 공개 후 관련 동영상 지정"을 적는다. 자리표시자 링크를 넣은 채 올리지 않는다(업로드 전 금지어·빈 링크 검사가 막는다).

## 3. 다음에 볼 영상 설계 (구독 전환)

구독은 보통 한 편을 보고 다음 편으로 이어서 볼 때 생긴다. 소재 단계(Phase 4~5)에서 이 편이 어디로 이어질지 미리 정한다.

1. **엔드스크린 연결**: 기존 규칙대로 **직전 편**을 건다(`production-rules.md` "엔딩 화면 연결 영상은 항상 직전 편"). 여기에 같은 주제 묶음의 다른 편이 있으면 두 번째 칸 후보로 적는다.
2. **재생목록**: 이 편이 들어갈 재생목록을 정한다(예: "짝단어 소리 구분", "끝소리 규칙"). 맞는 재생목록이 없으면 새로 만들지 제안한다.
3. **주제 묶음**: 비슷한 소재 2~3편을 묶음으로 보이게 하되, 같은 틀 반복 규칙은 그대로 지킨다. 묶음은 "주제가 이어진다"는 뜻이지 "구성이 같다"는 뜻이 아니다.
4. 끝 화면, 재생목록, 댓글 고정은 자동 업로드 범위가 아니므로 업로드 체크리스트에 사용자가 스튜디오에서 할 일로 적는다(`AGENTS.md` 1절 실수 정원표 4번, 상세는 `knowledge/legacy/agents-archive-2026-11-27.md` "대시보드 및 클라이언트 스크립트 개발 절대 규칙" 절).

산출물: `BRIEF.md`에 "연결" 칸(엔드스크린 2칸, 재생목록, 묶음 이름)을 적는다.

**멈춤 지점**: 없음. 쇼츠 제작 착수와 렌더는 롱폼과 같은 렌더 승인 게이트를 따른다.
