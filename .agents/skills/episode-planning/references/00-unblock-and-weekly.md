# Phase 0: 막힌 곳 풀기 (0-A 대청소 · 0-B 주간 점검 · 0-C 시작 브리핑)

새 영상을 기획하기 전에 "이미 만든 것이 시청자에게 닿고 있는지"부터 본다. 영상이 대기열에 쌓여 있거나 리뷰가 밀려 있으면, 새 기획보다 그걸 푸는 게 조회수에 먼저 영향을 준다.

- **0-A 대청소**: 쌓인 일이 많을 때 한 번 크게 치운다. 업로드 대기 3편 이상, 또는 밀린 리뷰 3편 이상이면 0-A로 간다.
- **0-B 주간 점검**: 대청소가 끝난 뒤 매주 가볍게 돈다.
- **0-C 시작 브리핑**: 새 대화의 첫 답변마다 짧게 보고한다.

공통 규칙:
- vidIQ는 쓰지 않는다. 우리 채널 숫자는 대시보드(`npm run analytics`, 포트 3001), 상태 확인은 프로젝트 자체 YouTube 연동을 쓴다(`knowledge/legacy/agents-archive-2026-11-27.md` "우리 채널 자체 유튜브 데이터는 vidIQ보다 프로젝트 자체 연동을 먼저 쓴다" 절).
- 숫자는 `POST /api/sync` 직후 `GET /api/dashboard`, `/api/episodes/summary` 응답 값만 쓰고 `range`를 같이 적는다.
- `status.json`은 손으로 고치지 않는다(`knowledge/production-rules.md` "4번째 원인 — status.json을 에이전트가 손으로 고칠 때").
- 업로드는 대시보드 자동 예약 업로드(`decideNextUpload`)나 사용자가 스튜디오에서 직접 한다. 에이전트가 우회 경로를 만들지 않는다(`AGENTS.md` 1절 실수 정원표 4번, 상세는 `knowledge/legacy/agents-archive-2026-11-27.md` "대시보드 및 클라이언트 스크립트 개발 절대 규칙" 절).

## 0-A. 대청소 (쌓였을 때 한 번)

1. **실제 공개 상태 확인**
   - `npm run growth-check`를 돌린다. 이 스크립트는 `data/youtube/catalog.json`(대시보드 동기화 결과)을 기준으로 공개 여부를 본다.
   - 동기화가 오래됐으면 `/api/sync`부터 하고 다시 돌린다. 그래도 맞지 않으면 `knowledge/production-rules.md` "업로드 후 대시보드 자동 동기화가 안 될 때" 절을 순서대로 확인한다.
2. **공개 일정표와 업로드 체크리스트**
   - 미공개 편을 언제 올릴지 표로 만든다. 롱폼은 **월·목 밤 11시, 주 2회**다(2026-11-06 사용자 확정, `knowledge/production-rules.md` "공개 일정과 엔딩 화면 연결 규칙"). 대시보드 예약 설정(`data/youtube/publish-rules.json`)이 다르게 바뀌어 있으면 그 값을 따르고 바뀐 사실을 알린다. 쇼츠 공개 요일은 `knowledge/channel-strategy.md` "주간 목표" 표를 따르고, 미정이면 사용자에게 묻는다.
   - 편마다 업로드 전에 남은 일을 `upload-checklist.txt`와 `knowledge/now.md`에서 읽어 함께 적는다(새 메인 썸네일, 썸네일 승인, 금지어 항목 등).
   - 같은 방식·형식이 연달아 나가면 "같은 틀 반복"으로 보일 수 있으니, 사이에 쇼츠를 끼울 수 있는지 함께 제안한다(Phase 12).
3. **밀린 리뷰 끝내기 (2026-11-11 개정)**
   - 공개 7일·28일이 지난 영상마다 Phase 11을 끝까지 한다. 숫자, 판정, 기획 근거 판정, 통한 요소 기록, 소재 이력까지 묻지 않고 기록한다(`05-performance-review.md` 2절). 예전처럼 숫자만 채우고 판정을 미루지 않는다.
4. **전후 비교**: 마지막에 `npm run growth-check`를 다시 돌려 막힌 곳이 얼마나 줄었는지 보여 준다.

**멈춤 지점**: 2번 공개 일정표는 사용자 확인을 받는다. 나머지는 보고하고 계속한다.

## 0-B. 주간 점검 (매주)

1. `npm run growth-check -- --save`로 새로 막힌 곳만 찾는다. 결과는 `knowledge/growth/check-YYYY-MM-DD.md`에 저장된다. 형식 배분과 표본 판정도 여기서 나온다.
2. `/api/sync` 직후 숫자로 이번 주를 본다: 조회수·구독자 증감, 롱폼 vs 쇼츠 비중, 상위 트래픽 소스 3개, 검색 유입 비중, 최근 영상 시청 지속률. `knowledge/channel-strategy.md` "주간 목표"와 나란히 적는다.
3. 공개 7일·28일이 된 영상이 있으면 Phase 11 진행 (48시간 판정은 작은 표본 노이즈 방지로 폐지됨).
4. Phase 11의 **중단 규칙**에 걸린 방식·형식이 있는지 확인한다(`05-performance-review.md` 4절).
5. **데이터 신선도 (2026-11-11)**: SKILL.md "데이터 되먹임 루프" 표의 "오래됐을 때" 기준을 하나씩 본다. 걸린 것은 묻지 않고 갱신한다(Gemini 호출만 비용·한도를 먼저 알린다). 공개·예약됐는데 `idea-board-history.json`에 없는 편도 여기서 등록한다. 갱신한 파일과 마지막 갱신일을 요약 표에 한 줄씩 넣는다.
6. `marketing:performance-report` 스킬로 한 장 요약: 핵심 숫자 표(출처·범위 포함) → 잘된 것 1~2개 → 막힌 것 1~2개 → **이번 주 할 일 최대 3개**. 할 일은 "EP25 썸네일 승인"처럼 이번 주 안에 끝낼 수 있는 행동으로 쓴다.
7. 결과는 `knowledge/growth/weekly-YYYY-MM-DD.md`에 남긴다(같은 날짜 파일이 있으면 읽고 갱신).

**멈춤 지점**: 없음. 보고하고 끝낸다.

## 0-C. 시작 브리핑 (하루 1회, 그날 첫 새 채팅)

**하루 1회(KST 기준, 그날 첫 새 채팅)**만 자율 브리핑과 데이터 수집을 수행한다. 같은 날 이어 가는 새 채팅에서는 브리핑과 수집을 반복하지 않고 `knowledge/handoff/LATEST.md`만 확인해 바로 사용자 요청으로 들어간다(수동 요청 시 `npm run briefing -- --force`).
상세한 운영 지침, 3단계 권한선, 자율 진화 원칙의 단일 원본은 **[00-autonomous-briefing.md](../../../../knowledge/playbooks/briefing/00-autonomous-briefing.md)**이다.

1. `git pull` 확인과 대시보드 서버(포트 3001) 실행 상태를 먼저 확인한다.
2. 훅이 있는 환경(Claude Code)은 SessionStart 훅이 안내와 점검 결과를 넘겨준다. 훅이 없는 환경(Gemini 등)은 **`npm run briefing` 한 번으로** 동기화 확인과 브리핑 컨텍스트를 일괄 확보한다.
3. 브리핑 전에 `knowledge/handoff/LATEST.md`(최근 요약)를 읽어 이전 대화와 다른 PC의 맥락을 이어받는다.
4. 시작 문구는 **`업데이트를 요약해서 먼저 보고드립니다.`** (동기화 시각 · 통계 기준일)로 시작한다.
5. 보고 순서와 권한선:
   - **1순위 (채널·성장)**: 최근 7일 성과, 최근 공개 영상 반응, 7일 정산 도래 영상, 다음 예약 현황, 승인 대기 항목.
   - **2순위 (AI 자율 보수·진화)**: 실제 데이터상 근거가 있을 때 자동 보수 결과 또는 진행할 업그레이드·삭제·기능 추가 보고.
   - **3순위 (시스템 예외)**: 실패 단계나 Git 변경 특이사항이 있을 때만 알림(정상 시 생략).
   - **권한선**: 🟢 무과금·복구·밀린 리뷰·버그/문구/미참조 정리는 즉시 실행 후 보고 / 🟡 기능 추가·구조 개선·기획 초안은 근거 보고 후 추진 / 🔴 3대 승인 관문(시트·렌더·업로드)·비용·규칙 변경은 대표님 승인 필수.
   - **환경 이상**: 플러그인·MCP·Git 훅 누락 등 실제 환경 이상이 감지될 때만 1줄 경고한다.
6. 브리핑은 대화당 한 번만 수행한다. 이어 가는 대화에서는 반복하지 않으며, 사용자가 생략을 요청하면 건너뛴다.

**멈춤 지점**: 없음 (승인 관문 대상 영상 제작이 아니면 브리핑 후 자율 실행 또는 사용자 요청 처리).

초등학생도 알아듣게 한 줄 풀이를 붙인다.

|---|---|
| 노출 클릭률(CTR) | 썸네일을 본 사람 중 누른 비율 |

| 추천 유입 | 다른 영상 옆이나 홈에 떠서 들어온 조회 |
| 구독 전환 | 이 영상을 보고 구독한 수 |
