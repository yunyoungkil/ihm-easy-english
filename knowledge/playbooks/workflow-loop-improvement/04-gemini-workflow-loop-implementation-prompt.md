# 제미나이 실행 프롬프트: 워크플로우 루프 감사·수정·완주

> **사용 방법:** 이 문서 전체를 Gemini(Antigravity)에 전달해 저장소 작업을 시작한다. 이 지시는 감사 보고서만 작성하라는 뜻이 아니다. 저장소의 현재 상태를 확인하고, 승인된 범위에서 문제를 코드로 고치고, 전체 영향을 검증해 워크플로우 루프를 실제로 닫으라는 실행 요청이다.

## 0. 목표와 책임

너는 「이해하면 쉬운영어」의 코드·데이터·콘텐츠 운영 흐름을 함께 책임지는 구현자다. 모든 판단의 목적 기준은 채널 제1 슬로건이다.

> 여러 명작의 장점을 흡수하고 우리 강점과 융합하여, AI 템플릿 냄새가 전혀 안 나는 압도적인 영상을 완성한다. 그리고 이 모든 과정은 AI가 주도적으로 생각하고, AI가 채널을 성장시킨다.

목표는 자료 수집이나 감사 보고서에 그치지 않는다. 신뢰할 수 있는 조사 근거가 기획에 쓰이고, 채택한 요소가 비교 시트와 실제 결과물에서 추적되며, 결과가 다음 판단으로 환류되는 흐름을 실제 시스템에서 확인하고 완성한다. 이미 충족된 부분은 중복 수정하지 않는다. 문제가 재현되면 원인을 고치고 전체 영향을 끝까지 검증한다.

## 2. 겉핥기·성급한 완료 금지

- 첫 검색 결과나 요약만으로 결론 내리지 않는다. 데이터가 어디서 만들어지고, 변환되고, 저장되고, 표시되고, 소비되는지 실제 호출 경로와 대표 원본 레코드를 추적한다.
- 필드·형식·단위·날짜 기준·결측 표현은 실제 파일과 코드에서 확인한다. 예상한 스키마나 가짜 구조를 실제 계약처럼 만들지 않는다.
- 확인한 사실, 자료에 근거한 추론, 검증할 가설, 모르는 것을 구분한다. 상관관계를 원인으로 과장하거나 시험하지 않은 동작을 단정하지 않는다.
- 변경 전 현재 동작과 오류를 재현하고, 영향 범위와 과거 데이터·사용자 호환성을 확인한다. 분석만 하고 구현을 생략하지 않는다.
- 한 지점의 로컬 검사가 통과했다는 이유로 완료 처리하지 않는다. 완료 기준은 5절의 모든 영향 경로를 끝단과 다음 루프까지 확인하는 것이다.
- 가장 쉬운 정상 경로만 확인하지 않는다. 기본 입력 계약과 오류 처리부터 확인한 다음, 영향 분기·화면·후속 소비처·다음 주기까지 검증한다.
- 실패 원인을 고쳐 영향받은 검증을 다시 수행한다. 검사 기준을 낮추거나 실패를 숨기거나 미실행 검사를 통과로 보고하지 않는다. 기본 오류를 남겨 사용자가 찾아내게 하지 않는다.
- 단계마다 스스로 반문한다: 실제 코드를 끝까지 읽었나? 반대 분기와 부수 소비처를 놓치지 않았나? 증거보다 강하게 해석하지 않았나? 창작 선택을 고정하지 않았나? 다음 실행 주기에서 결과가 실제로 소비되나? 답을 근거와 함께 남긴다.

## 3. 절대 경계: 신뢰 가드레일과 창작 자율성

현재 저장소의 승인 규칙과 브랜드 원본을 찾아 확인한다. 이미 합의된 안전·사실성·품질·승인·실제 데이터 보장 장치는 지킨다. AI 자율성을 이유로 제거하지 않는다.

창작을 코드나 정책에 고정하지 않는다. 특정 제목 문법, 썸네일 문구 유형, 화면 구성, 나레이션 전개, 장면 순서, 레퍼런스 개수나 혼합 비율을 선택지·분류표·기본 공식으로 강제하지 않는다. “권장”, “예시”, “기본값”이라 부르며 사실상 강제하는 것도 금지한다. 하드코딩 금지 자체를 새 목록이나 창작 메뉴로 만들어 경직성을 되살리지 않는다.

AI가 여러 참고작의 관찰 가능한 장점을 조사하고 이번 주제·시청자·학습 목표·브랜드에 맞는 근거를 설명한 뒤 새 결과물로 융합하도록 한다. 단일 벤치마크 채널을 정체성의 고정 기준으로 만들지 않는다. 다중 채널 자료도 무목적 혼합으로 정체성을 흐리게 두지 않는다. 자료의 역할과 채택 이유를 해당 결정에 맞춰 정하고 실제 적용 위치와 결과를 추적한다. 창작 판단을 사용자의 감각 선택으로 떠넘기지 않는다.

## 4. 감사·구현 범위

현재 기능을 기준으로 다음 연결을 실제 코드·데이터에서 추적한다. 문제가 재현되면 원인을 최소 수정으로 고치고, 불필요한 수집·중복 기능·화면을 늘리지 않는다.

- **조사 자료 적합성:** 원천·식별자·수집/게시 시각·형식·측정 창·필드·결측·중복·실패 상태가 보존되는지 확인한다. 부적합·미검증 자료가 비교·점수·순위·기준선에 섞이는 경로와 영향을 찾아 격리하고 기존 기록은 안전하게 처리한다.
- **배율·비교 안정성:** 분자·분모 정의, 0·결측·소표본, 형식·기간·집단 차이, 제외 사유, 계산 버전과 원본 추적을 확인한다. 그럴듯한 대체 숫자를 만들지 말고 비교 불가를 표현한다. 기존 결과와 새 계산을 섞거나 원본 과거 자료를 파괴하지 않는다.
- **한국에서 실제 관심을 얻은 해외 트렌드:** 해외에서 발생한 사실과 한국 내 관심 근거를 구분한다. 한국어 보도·검색·국내 반응 등 확인 가능한 출처·시점·유효성을 추적하고 영어 학습·채널 약속과 연결되는 경우에만 반영한다. 해외에서 화제라는 이유만으로 한국 트렌드라 단정하거나 매일 소재에 억지로 넣지 않는다. 새 데이터원이 필요하면 연결·권한·비용·약관·실패 동작을 확인하고 무단 유료 사용이나 외부 서비스 추가를 하지 않는다.
- **레퍼런스와 정체성:** 단일 채널 고정을 피하면서 다중 자료의 혼합 편향도 찾는다. 조사 결과가 대본·화면·제목·썸네일 등 실제 산출물에 어떤 근거로 반영됐는지 확인한다. 조회수만으로 원인을 단정하거나 원본을 복제하지 않는다.
- **비교 시트에서 실제 결과까지:** 기존 필드와 연결을 먼저 파악한다. 출처→관찰/가설→채택·변형·보류·배제 이유→실제 적용 위치→공개 콘텐츠/ID→측정 조건과 결과→다음 판단이 이어지는지 확인한다. 중복 필드를 만들지 말고 끊긴 연결을 고친다.
- **부수 영향:** 소비자 코드, API·저장 형식, 화면, 리포트, 캐시, 과거 데이터, 일일 루프, 예약 작업, 테스트, 문서 색인, 복구·백필에 미치는 영향을 조사한다. 서버와 브라우저 계산이 다르거나 잘못된 값이 장기간 재사용되거나 예외가 성공처럼 표시되는지 확인한다. 미사용 경로는 영향을 확인한 뒤 정리한다.

비용·권한·약관 변경, 기존 승인 관문 변경, 되돌리기 어려운 삭제·대량 재작성, 미확정 전략 선택은 임의 결정하지 않는다. 영향과 선택지를 제시하고 사용자 판단을 요청한다. 그 외 저장소 안에서 되돌릴 수 있는 구현과 검증은 진행한다.

## 5. 분기에서 최종 결과와 다음 루프까지 검증

정책·규칙·워크플로 판단 지점은 그 지점의 단위 검사만으로 완료가 아니다. 각 영향 분기를 조건부터 끝 결과까지 추적한다.

**입력/트리거 → 규칙·조건 판단 → 실제 분기 → 분기별 실행 또는 건너뜀 → 저장·표시 결과 → 후속 소비처 → 최종 사용자 결과 또는 다음 루프 입력**

1. 코드에 실제 존재하는 모든 영향 분기를 식별한다. 정상, 보류/자료 부족, 제외/종료, 실패/재시도, 중복/기처리 등은 코드에 존재할 때 각각 본다. 이름과 상태를 미리 가정하지 않는다.
2. 각 분기에서 실행·건너뛰는 작업, 저장값·상태·로그·화면·알림을 확인한다. 조기 종료, 누락, 중복 처리, 잘못된 성공 표기를 찾는다.
3. 결과를 읽는 모든 주요 소비처를 따라간다. 화면만 보고 저장·다음 처리 경로를 생략하지 않는다. 함수 검사만 하고 화면·리포트·일일 루프를 생략하지 않는다.
4. 루프라면 결과가 다음 실행의 입력으로 실제 읽혀 올바르게 판정·사용되는지 확인한다. 현재 한 번 실행으로 끝내지 않는다. 격리된 테스트 데이터나 안전한 드라이런으로 다음 주기 소비까지 재현한다.
5. 실패 경로도 종료 상태·사용자 결과·재시도 가능성·다음 주기 복구까지 확인한다. 시험 자료가 운영 기록을 오염시키거나 외부 공개·과금을 일으키지 않게 한다.
6. 영향 분기의 조합도 검토한다. 모든 조합 실행이 불가능하면 동작 동등성 근거, 묶은 조합, 생략한 조합, 위험과 추가 확인을 밝힌다. 일부만 보고 전체 검증이라 하지 않는다.

완료 전에 아래 증거표를 작성한다. 상태는 통과·실패·미검증으로 표시한다. 미검증이 남으면 완료 선언을 하지 않는다.

|---|---|---|---|---|---|---|

## 6. 수정과 검증 순서

1. **상태 확인:** 저장소 지침에 따라 최신 상태를 받고 브랜치·변경 파일을 확인한다. 기존 작업물을 덮어쓰지 않는다. 현재 상태와 최신 인수인계를 읽되 낡은 메모를 현재 사실로 오해하지 않는다.
2. **재현:** 실제 입력·데이터에서 문제와 정상 기준을 확인한다. 재현이 안 되면 관찰 범위를 기록하고 가정을 사실처럼 구현하지 않는다.
3. **경로 지도:** 입력부터 다음 실행까지 호출·데이터 흐름과 분기표를 만든다. 코드·화면·검사·문서 중 영향을 확정한다.
4. **수용 조건:** 슬로건, 데이터 정확성, 승인 경계, 적용 추적, 다음 루프 환류, 실패 안전성 기준으로 사용자 결과를 검증 가능하게 정의한다. 창작 표현을 고정 조건으로 만들지 않는다.
5. **최소 수정:** 원인을 해결하는 일관된 변경을 한다. 새 임의 문턱·기본값·우회·오류 무시·기준 완화로 증상을 가리지 않는다. 기존 데이터와 형식 호환을 보존한다.
6. **전체 확인:** 현재 AGENTS.md가 요구하는 모든 명령과 관련 검사를 실행한다. 입력 계약부터 영향 분기, UI·주요 소비처, 오류 흐름, 다음 주기 재소비까지 확인한다. 사용자 화면이 바뀌면 브라우저에서 직접 확인한다. 관련 검사가 없다면 회귀를 잡는 최소 검증을 추가한다.
7. **반대 입장 검토:** diff를 처음 보는 검토자처럼 읽는다. 요구 누락, 경로 단절, 숨긴 실패, 고정 창작 규칙, 데이터·문서 후속 작업을 반례로 확인한다. 추가 수정하면 영향 경로와 검사를 다시 수행한다.
8. **기록·정리:** 저장소 로그·현재 상태·인수인계 규칙에 따라 확인된 사실만 기록한다. 변경 파일을 검토하고 저장소 규칙에 따라 커밋·푸시한다.
9. **보고:** 아래 형식으로 근거를 제시한다. 실패·미실행 검사, 검증하지 못한 분기, 다음 주기 재현 여부를 숨기지 않는다. 기본 QA를 사용자에게 넘기지 않는다.

## 7. 완료 보고 형식

- **수정한 파일:** 경로와 해결한 원인
- **현재 동작과 변경 동작:** 재현 근거
- **전체 흐름:** 입력부터 화면·후속 소비처와 다음 주기 재소비까지
- **분기 검증표:** 5절 표와 각 상태
- **실행한 확인:** 저장소가 요구한 명령과 실제 결과
- **미검증/제약:** 경로·이유·영향
- **기록 및 커밋:** 수행한 경우에만 SHA와 파일
- **남은 사용자 결정:** 실제 결정이 필요한 전략·비용·권한·승인 경계만

“완료”, “전부 검증”, “루프가 닫힘”이라고 말하려면 모든 영향 분기의 끝 결과와 다음 주기 재소비 증거가 있어야 한다. 미검증이 있으면 범위를 정확히 보고하고 통과로 과장하지 않는다.
