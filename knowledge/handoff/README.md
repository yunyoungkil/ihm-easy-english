# 인수인계 (다른 PC·다음 대화의 Claude에게)

사용자는 여러 PC에서 작업한다(2026-11-13 사용자 결정). 한 대화에서 나눈 **맥락·핵심·사용자가 한 말의 뜻**이 그 PC에만 남으면 다른 PC의 Claude는 같은 실수를 되풀이한다. 그래서 대화에서 정한 것은 이 폴더에 날짜별 파일(`YYYY-MM-DD.md`)로 적고 커밋·푸시한다.

- **읽는 때**: 새 대화를 열면 `git pull` 다음에 **`LATEST.md`(현재 상태 요약, 60줄 안팎)만** 읽는다(2026-11-16 토큰 절약: 날짜 파일은 하루 조각이 쌓여 수만 토큰). 날짜 파일은 통째로 읽지 말고 `grep -n`으로 필요한 절만. Claude Code에서는 시작 훅이 파일 이름을 알려 준다(`scripts/handoff.mjs`). 그다음 `knowledge/now.md`의 다음 할 일(훅이 앞 8개만 넘긴다).
- **`LATEST.md` 관리**: 날짜 파일에 절을 더할 때마다 `LATEST.md`도 **고쳐 쓴다**(더하지 않는다). 결정되거나 끝난 일은 지우고, 60줄을 넘기지 않는다. 날짜 파일은 상세 기록(기록 보관소)이다.
- **쓰는 때**: 사용자와 무언가를 정했을 때, 사용자가 방향을 고쳐 줬을 때, 작업 한 덩어리를 커밋할 때. 마무리 뉘앙스("여기까지")가 나오면 반드시. 같은 날 여러 대화는 같은 파일 아래에 `##` 절을 더한다.
- **안 쓰는 것**: 코드 구조나 git 기록으로 알 수 있는 것, 바로 지워질 임시 상태. 상세 근거와 숫자는 `knowledge/logs/YYYY-MM.md`, 결정의 이유는 `knowledge/decisions/`에 두고 여기서는 가리키기만 한다.

## 한 파일에 담을 것 (이 틀을 쓴다)
1. **한 줄 요약**: 이 날 무엇을 하려 했고 어디까지 왔나.
2. **사용자가 한 말의 뜻**: 지시·정정·반박·선호를 그 **이유**와 함께. 인용 대신 뜻을 적는다. 사용자가 틀린 내 제안을 고쳐 준 것, 내가 반박했는데 사용자가 인정한 것을 구분한다.
3. **결정된 것 / 결정 대기**: 결정은 날짜와 함께, 사용자 결정이 필요한 것은 따로.
4. **한 일**: 커밋 해시와 한 줄씩. 실행한 확인 명령과 출력(`# pass N`).
5. **이어서 할 일**: 순서대로, 막힌 이유와 함께. 다른 PC에서 먼저 해야 할 준비(서버 재시작 등).
6. **함정**: 겪은 실수와 다시 안 하는 법.

## Claude 전용: 어려운 판단은 Opus에게
`CLAUDE.md` "어려운 판단은 `opus-expert`에게" 절. Opus에게 물은 질문·답·채택 여부도 그날 인수인계 파일에 한 줄로 남긴다(다른 PC가 같은 질문을 다시 하지 않게).
