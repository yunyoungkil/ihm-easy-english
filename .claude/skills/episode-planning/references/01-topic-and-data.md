# Phase 1~5: 데이터 분석, 유형 선택 및 소재 발굴 가이드

이 문서는 에피소드 기획의 초기 단계(Phase 1 ~ Phase 5)를 상세히 규정합니다.

---

## PHASE 1 — 라이브 데이터 분석 (캐시 금지)

이번이 몇 번째 기획이든, **이 단계의 숫자는 이번 세션에서 직접 다시 받아온 값만 쓴다.**

1. **우리 채널 현재 상태(라이브)**: 분석 대시보드 서버(포트 3001)가 떠 있는지 확인하고, 없으면 `npm run analytics`로 띄운다.
   - `POST http://localhost:3001/api/sync` 로 강제 새로고침을 먼저 호출한다(캐시된 스냅샷이 아니라 지금 유튜브 API에서 새로 받아오게 하기 위함).
   - 그 직후 `GET http://localhost:3001/api/dashboard`, `/api/episodes/summary`로 조회수·구독자·트래픽 소스·검색어·영상별 시청 지속률을 받는다.
   - `data/youtube/analytics-latest.json` 등 파일을 열어서 그 안의 숫자를 바로 인용하지 않는다 — 반드시 `/api/sync` 직후 응답값을 근거로 쓴다. 범위(최근 N일/3개월/누적)를 혼동하지 않도록 매번 응답의 `range` 필드를 확인하고 표에 명시한다.
2. **이미 다룬 소재 확인(라이브)**: `GET /api/catalog` 또는 `/api/episodes/summary`의 실제 제목 목록, 또는 `videos/*/BRIEF.md`를 직접 스캔해서 지금까지 다룬 발음 규칙 목록을 새로 뽑는다. `idea-board-history.json`은 참고만 하고 그 파일의 완결성을 신뢰하지 않는다(과거에 등록 누락 버그가 있었음).
3. **시청자 페인포인트(웹 검색, 라이브)**: WebSearch를 실제 실행해서 한국 성인 영어 학습자가 발음 관련해서 실제로 검색하고 질문하는 표현을 확인한다. 경쟁 채널 분석은 여기서 하지 않고 Phase 3에서 한다. `audience-dna.json` 등 과거 스냅샷은 "그때 한 번 모은 참고 자료"로만 취급하고, 이번 분석에서 재확인되지 않은 내용을 근거로 쓰지 않는다.
4. **산출물**: 아래 표로 "지금 채널의 진짜 현실"을 정리한다 — 숫자마다 어느 API 호출/어느 검색에서 나왔는지 출처를 반드시 붙인다.

   | 항목 | 값 | 출처 |
   |---|---|---|
   | 조회 범위 | (API 응답의 range) | /api/sync 응답 |
   | 롱폼 vs 쇼츠 조회수 비중 | | |
   | 최근 에피소드 시청 지속률 추이 | | |
   | 상위 트래픽 소스 3개 | | |
   | 검색 유입 비중 | | |
   | 이미 다룬 발음 규칙 목록 | | |

5. **대기 중인 리뷰 확인**: `videos/*/REVIEW.md`가 없고 `output/upload-packages/*/status.json`의 `publishedAt`(또는 `scheduledFor`)이 7일 또는 28일 이상 지난 영상이 있는지 본다. 있으면 Phase 2로 가기 전에 **Phase 11을 먼저 진행한다**고 알리고, 그 결과를 Phase 4의 근거로 쓴다.

끝나면 정확히 다음으로 마무리한다:
> **"다음은 콘텐츠 유형 선택입니다. 기본값(강의 방식, 형식은 소재별로 결정)으로 가려면 '계속'을 입력하세요. 다르게 정하려면 방식과 형식을 말씀해 주세요."** (멈춤)

## PHASE 2 — 콘텐츠 유형 선택

두 가지를 정한다. 이 선택이 **스캔 대상 채널, 아웃라이어 기준, 나중의 성과 비교**를 모두 정한다.

### ① 방식 — 영상이 무엇을 하는지
- **강의**: 규칙을 설명하고 가르친다. 예: "왜 CAT은 캣인데 KING은 킹일까?" (우리 채널 기본)
- **듣기**: 계속 틀어놓고 들으면서 익히는 콘텐츠다(2026-10-04 사용자 정의). 긴 대화·팟캐스트, 또는 같은 문장 패턴을 반복해서 들려주는 집중 연습이 해당한다. **나레이션은 설명이 필요한 프레임과 반복 시작 전 한 줄에만 넣는다**(2026-10-04 사용자 지침). 설명 프레임은 규칙, 예외, 정리다. 단어와 문장을 반복하는 동안에는 나레이션을 넣지 않는다. 초등학생에게 가르치듯 핵심만 말한다. 음성은 학습 대상 음성(원어민 음성)이다. 이 영상이 어떤 학습용인지는 제목·썸네일·화면 카드로 알린다. 듣기형 채널 상위 영상은 전부 26~30분 롱폼이었다.
- **혼합**: 듣기 자료에 규칙 해설을 음성으로 붙인다. 나레이션 규칙을 그대로 적용한다. 검증된 채널이 아직 없어서 **가설로만** 쓴다.

### ② 형식 — 영상 길이와 역할
- **롱폼**: 신뢰 형성, 깊은 학습, 수익화 시청 시간 확보 (`knowledge/channel-strategy.md`).
- **쇼츠**: 신규 시청자 도달, 구독자 획득.
- **세트**: 쇼츠로 들어와서 관련 롱폼으로 연결한다(채널 전략의 "쇼츠 CTA는 롱폼으로 연결" 원칙).

### 기본 추천
- **방식은 강의가 기본이다.** 우리 채널이 강의형이고, 이번 스캔의 토픽 근거는 강의형 채널에서만 나오기 때문이다.
- **형식은 소재마다 역할로 고른다.** 도달이 목적이면 쇼츠, 깊이가 목적이면 롱폼이다. 우리 쇼츠 상위 5개 중 4개가 테스트형이라서, 도달형 소재는 테스트 쇼츠가 근거가 있다.

### 방식에 따른 스캔 대상 매핑
| 방식 | 스캔 대상 | 쓰는 근거 |
|---|---|---|
| 강의 | 강의형 채널 (`채널 방식 태그` 표 참고) | 토픽 + 형식 |
| 듣기 | 듣기형 채널 | **형식만.** 토픽 근거로 쓰지 않는다 |
| 혼합 | 두 그룹 모두 | 형식 + 토픽 (가설로 표시) |

### 형식별 주의
- **롱폼**: 현재 스캔 방식(채널별 상위 5개) 그대로 쓸 수 있다.
- **쇼츠**: 스캔은 롱폼과 쇼츠의 상위 5개를 따로 저장한다(`topOutliersByFormat`). 쇼츠 판정은 **길이 60초 이하** 기준이다. 유튜브 Data API는 쇼츠 분류값을 주지 않으므로 근사치를 쓴다. 최근 50개 중 쇼츠가 0개인 채널은 "쇼츠 근거 없음"으로 적는다.
- **세트**: 같은 소재로 쇼츠와 롱폼을 함께 만든다. 스캔은 형식마다 한 번씩 본다.

선택 결과(방식, 형식, 이유)를 스캔 문서 맨 위에 적고, `videos/<프로젝트>/REVIEW.md`의 "예측" 칸 위에도 적는다.
끝나면 **"이 유형으로 스캔을 진행하려면 '계속'을 입력하세요."**라고 안내하고 멈춘다.

## PHASE 3 — 경쟁 채널 스캔 (틈새 찾기)

**채널은 사용자가 준 주소만 쓴다.** 스킬이 임의로 채널을 골라 분석하지 않는다. 주소가 없으면 여기서 멈추고 달라고 요청한다. 같은 채널의 주소가 여러 개면 한 번만 스캔한다.

### 채널 방식 태그
- **강의**: 제목에 규칙·수업·총정리·"N강"·"읽는 법" 같은 표현이 있고, 영상이 규칙을 설명한다.
- **듣기**: 제목에 Conversation·Podcast·Practice·Listening 같은 표현이 있고, 27분 이상 대화나 팟캐스트 형식이다.
- **혼합**: 듣기 자료에 해설이 붙은 것이 확인될 때만 쓴다.

| 채널 | 방식 태그 | 근거 |
|---|---|---|
| 우리 채널 (이해하면 쉬운 영어) | 강의 | 규칙 설명 시리즈 (쇼츠 테스트형은 혼합 가설의 출발점) |
| 9988영어 | 강의 | "읽는 법", "총정리", "이중모음 1 of 6" |
| 본즈 기초 영어 | 강의 | "기초 파닉스 수업", "까막눈 탈출" |
| 봄날영어학교 | 강의 | "수업", "덩어리철자 공부" |
| 어션영어 BasicEnglish | 강의 | "기초영어 1강: Be동사" 강의 번호 |
| learn english online | 듣기 | "English Conversation Practice", 27분 대화 |
| Speak English With Class | 듣기 | "English Podcast For Learning English" |

### 스캔 절차
1. **실행**: 채널마다 `node scripts/market-demand.mjs --channel="<주소>"`를 실행한다. **매번 다시 돌린다**(캐시 금지). 채널당 할당량 1이라 비용이 거의 없다.
2. **근거**: 이번 실행이 출력한 JSON만 쓴다. `data/youtube/market-demand.json`의 옛 값을 인용하지 않는다. 롱폼 근거는 `topOutliersByFormat.long`, 쇼츠 근거는 `topOutliersByFormat.short`를 읽는다.
3. **거르기**:
   - 선택한 방식에 맞는 채널만 본다. 듣기형 채널은 토픽 판정에서 빼고 형식 참고용으로만 쓴다.
   - 올린 지 7일 이상인 영상만 배율로 판단한다. 7일 미만은 "관찰 중"으로 따로 둔다.
   - 기준선(평소 하루 조회수 중앙값)이 10회 미만인 채널은 배율 대신 절대 조회수로 본다.
   - **구독자 수는 거르는 기준으로 쓰지 않는다.**
4. **아웃라이어 기준**: 기준선 대비 배율 **5배 이상**, 올린 지 **7일 이상**인 영상.
5. **주제 묶기 (2단계)**:
   - **넓은 주제** (예: "영어 읽기: 철자를 소리로")
   - **좁은 주제** (예: "긴 단어 덩어리", "이중모음", "기초 파닉스 입문")
6. **판정**:
   - **니치 수요 있음**: 넓은 주제에서 아웃라이어를 낸 채널이 **2곳 이상**이고, 그중 **올린 지 30일 이내** 아웃라이어가 있다.
   - **좁은 수요 있음**: 같은 조건을 좁은 클러스터에서 2곳 이상 만족한다.
   - **단일 채널 신호**: 좁은 클러스터에서 1곳만 만족한다. 소재 근거로 단독 사용하지 않는다.
7. **분석 품질 체크**: 분석 채널 수(2곳 이상), 7일 이상 비율, 한계 명시, 쇼츠 근거 여부를 적는다.
8. **스캔 문서**: `knowledge/competitor-channels-YYYY-MM-DD.md`를 작성한다.

끝나면 **"틈새 후보를 만들려면 '계속'을 입력하세요."**라고 안내하고 멈춘다.

## PHASE 4 — 소재 후보 (10개)

Phase 1(채널 현실), Phase 2(유형), Phase 3(클러스터), Phase 11(과거 교훈), `data/youtube/success-patterns.json`만 근거로 쓴다.
**웹 검색 결과는 근거 칸에 "웹"이라고 표시한다.** **듣기형 채널은 토픽 근거로 쓰지 않는다.**

| 후보 | 핵심 검색 키워드(실제 검색창 입력 문구) | 타겟 페인포인트 | 근거 클러스터(판정 등급) | 근거 영상(채널·제목 앞부분·배율·올린 지) | 우리 커버(BRIEF 대조) | 차별 각도 | 예측(우리 최근 조회 중앙값 대비 예상 범위와 이유) |
|---|---|---|---|---|---|---|---|

- 이미 다룬 규칙과 **70% 이상 겹치는 소재는 제외**한다(제외 이유 명시). **30~70% 겹치는 소재는 차별 각도를 반드시 명시**한다.
- "일상에서 자주 쓰는 단어" 같은 막연한 라벨 금지, 실제 검색 가능한 구체적 키워드로 적는다.
- 경쟁 채널 제목 방식을 참고하되 문장을 베끼지 않는다.
- **예측 칸은 나중에 Phase 11에서 쓰므로 반드시 작성한다.**
- **쇼츠 후보는 쇼츠 근거 부족 사실을 함께 적는다.**

선택되면 `videos/<프로젝트>/REVIEW.md`를 만들고 "예측" 칸을 적는다(기존 파일 존재 시 `view_file` 후 이어서 작성).
멈춘다.

## PHASE 5 — 분량/포맷 세부 결정

- **롱폼을 고른 경우**: 기본 길이는 8~10분이다. **프레임 수는 고정돼 있지 않다** (비트에 맞춤, 11~15개 등 다양). 길이를 늘릴지(15~30분) 사용자가 직접 결정한다.
- **쇼츠를 고른 경우**: 훅으로 쓸 장면을 정한다. 롱폼 연계형(세트)이면 마지막 장면이 어느 롱폼 에피소드로 이어지는지 미리 설계한다.

사용자 확인 후 다음 단계로 진행한다.
