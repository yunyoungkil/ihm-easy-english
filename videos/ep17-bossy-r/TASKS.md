### 5. 전체 재검토 중 스스로 발견한 버그 — Frame 6·7·8 단어 카드 seek-비결정성

사용자가 "영상 어떤 것 같아?"라고 물어서 여러 시점을 스냅샷으로 다시 훑어보다가 발견.
Frame 6의 5개 단어 카드(`car, park, star, farm, card`)가 로컬 t=10초·20초 스냅샷에서는
전혀 안 보이는데 t=17초에서는 보이는 이상한 현상을 확인. 원인은 `.f06-word-card`에 남아
있던 `transition: all 0.2s ease;` — GSAP가 seek(임의 시각으로 순간이동) 시 최종 opacity/
transform 값을 즉시 계산해서 넣어주는데, 이 CSS 트랜지션이 그 순간 다시 끼어들어 "이전
DOM 상태 → 새 값"으로 0.2초짜리 실제 시간(wall-clock) 트랜지션을 새로 시작해버림 — 그
결과 화면 캡처가 정확히 언제 일어나느냐에 따라 카드가 보이거나 안 보이거나 하는, **영상
타임라인과 무관하게 결과가 갈리는 비결정성 버그**였음. 이 프로젝트(HyperFrames)는
"단일 paused 타임라인, seek-safe, deterministic"이 핵심 전제인데 이 버그는 그 전제를
정면으로 깨는 것이었고, 실제 렌더 파이프라인이 프레임마다 seek하는 방식이라면 최종
영상에도 카드가 빠진 채로 나갔을 수 있었음. Frame 7·8에도 똑같은 트랜지션이 복사돼 있어
셋 다 제거. 이후 t=10/17/20초 전부 카드가 안정적으로 보이는 것 재확인.

있었지만(사용자가 직접 준비), 대시보드 서버는 이 파일들을 전혀 모르는 상태였음.

- **정적 자산 라우트 확장**: `/api/upload-package-asset/`가 원래 "폴더/파일명" 정확히 2구간만
  받았는데, 자막이 `subtitles/` 한 단계 하위 폴더에 있어서 막히고 있었음 — 구간 수 제한을
  풀어 임의 깊이의 하위 경로를 허용하도록 수정(각 구간의 `..`/`\\` 금지는 그대로 유지,
  `curl`로 정상 서빙 + 경로 이탈 시도 둘 다 재확인). `srt` 확장자 Content-Type
  (`application/x-subrip`)도 추가.
- **`getEpisodesSummary()`**에 `multilingual-metadata.json`을 읽어 언어 코드별로
  `subtitles/subtitles-<코드>.srt` 파일과 매칭한 `youtube.multilingualVariants` 배열
  (`{code, lang, title, desc, srtUrl}`) 추가.
- **`renderTrackDetail()`** 모달에 "🌍 다국어 자막 & 번역 메타데이터" 카드 섹션 추가 — 언어별로
  국기 이모지 + 제목(복사 버튼) + `.srt` 다운로드 버튼 + 설명문(접이식 `<details>`, 복사 버튼).
- 서버 재시작 → `test-client-syntax.mjs` 10/10 통과 → `/api/episodes/summary`로 5개 언어
  전부 정상 파싱 확인 → 실제 `.srt` 다운로드 URL도 `curl -I`로 200 OK 확인.
- `production-rules.md`의 "두 군데 다 나와야 완료" 규칙이 이번에도 그대로 적용된 사례 —
  콘텐츠 파일을 프로젝트 폴더에 넣는 것과 대시보드에 노출하는 것은 별개 작업이라는 걸
  다시 한번 확인.

### 10. 다국어 자막 언어(lang) 표기에서 영문 설명 → 한국어로 정정

사용자: "🇹🇼 繁體中文 (Traditional Chinese - 台灣/香港) 이렇게 나오잖아. 여기서 내가 알 수
있겠 (Traditional Chinese - 台灣/香港) 이걸 한국어로 전부 바꿔줘. 다른 언어도 마잖가지로".
`multilingual-metadata.json`의 `lang` 필드가 "원어 표기 (English)" 형식이라 한국어 사용자
입장에서 괄호 안이 안 읽혔음 — 7개 언어 전부 괄호 안을 한국어로 교체(원어 표기 자체는
유튜브 Studio 언어 목록과 매칭용으로 그대로 유지):
`한국어 (한국)`, `English (영어 · 미국)`, `日本語 (일본어)`, `Español (스페인어)`,
`Tiếng Việt (베트남어)`, `繁體中文 (번체 중국어 · 대만/홍콩)`, `简体中文 (간체 중국어 ·
싱가포르/전 세계 화교)`. 같은 패턴이 `multilingual-guide.txt`의 섹션 헤더에도 있어서 같이
수정(CLAUDE.md의 "내용을 고칠 땐 같은 내용을 담은 다른 문서도 같이 확인" 원칙 적용).
`index.html`은 애초에 국기+원어 표기만 써서 해당 없음. 서버는 이 JSON을 그대로 읽으므로
코드 변경 없이 API/대시보드에 바로 반영 확인.

### 11. 다국어 자막 제작을 채널 표준 규칙으로 승격

사용자: "예약, 자막까지 추가했어. 앞으로 자막도 계속 만들꺼니깐. 규칙에 넣어줘." EP17에서만
쓰고 끝날 일회성 작업이 아니라 앞으로 모든 롱폼에 적용될 표준임을 확정 — 언어 세트(한국어
기본 + 영어/일본어/스페인어/베트남어/중국어 번체·간체), 파일 3종의 이름·구조, `lang` 필드
한국어 표기 규칙(위 10번)까지 전부 `production-rules.md`의 "업로드 패키지 변경 완료 조건"
절에 정식 규칙으로 기록. `CLAUDE.md`/`AGENTS.md`(HyperFrames 기본 적용 요소 목록에 짧은
포인터 추가) · `VIDEO_WORKFLOW.md`(10단계 업로드 체크리스트에 항목 추가)에도 반영 —
다음 에피소드부터는 파일명 규칙만 지키면 대시보드 쪽 추가 개발 없이 자동으로 노출된다는
점을 명시해, "만들었는데 안 보인다"는 지적(9·10번)이 반복되지 않도록 했다.

### 12. 실제 유튜브 업로드 후 "동기화해도 예약/완성으로 안 뜨는" 버그 2건 발견·수정

사용자: "데이터 동기화를 했는데 아이디어 보드 완성으로 안뜨고 패키지도 업로드 대기로
뜨네?" 사용자가 이미 실제로 유튜브 Studio에 업로드·예약까지 마친 상태였는데(비공개,
publishAt 2026-09-22T11:00:00Z — 우리가 제안한 날짜와 정확히 일치, 확인 완료) 대시보드가
계속 옛 상태로 멈춰 있었음. API로 채널의 최근 업로드 25개를 직접 조회해서 원인 두 개를
분리해서 찾음:

1. **`syncUploadPackageStatusFromYouTube`의 제목 정확 일치 매칭 버그**: 이 함수는
   `videoId`가 없으면 "내 채널 최근 영상 중 `title.txt`와 제목이 정확히 같은 것"을 찾아서
   연결하는데, 실제로 유튜브에 올라간 영상은 **title-variants.txt의 시안 A**("저도 이제
   안 막힙니다...")였고 `title.txt`엔 시안 B가 들어있어서 영원히 못 찾고 있었음(6~7번에서
   제목 A/B 테스트 기능을 지원하기 시작한 뒤 처음 실전에서 드러난 버그 — 시안을 여러 개
   두는 기능을 만들어놓고 "그중 하나로 실제 업로드될 수 있다"는 경우는 놓쳤던 것).
   `syncUploadPackageStatusFromYouTube(pkgPath, statusData, title, titleVariants)`로
   시그니처를 확장해 기본 제목 + 모든 시안 제목을 후보 배열로 모아 매칭하도록 수정.
2. **`idea-board-history.json`의 `episodeSlug`가 계속 `null`로 남아있던 문제**:
   `syncIdeaBoardHistoryFromPackages()`는 `entry.episodeSlug`로 패키지 폴더를 찾는데,
   업로드 패키지 조립 시점(3번)에 "실제 예약 등록 완료 시점에 채운다"고 미뤄둔 걸 실제
   예약 등록 후에도 아무도 채우지 않았음 — `episodeSlug: "ep17-bossy-r"`,
   `episodeLabel: "단편 EP17"`, `status: "scheduled"`, `producedAt: "2026-09-18"`로 수동
   채움(VIDEO_WORKFLOW.md 10단계 규칙대로).
3. **검증**: 서버 재시작 → `test-client-syntax.mjs` 10/10 통과 → `status.json`의
   `lastSyncedAt`을 초기화해 5분 스로틀 우회 → `/api/episodes/summary`로 EP17이
   `status: "scheduled"`, `statusLabel: "예약 · 9/22(화) 20:00"`, `videoId:
   "VwEkIUluszw"`로 정상 노출 확인 → `/api/idea-board/history`로 아이디어 보드 배지도
   "✅ 이미 제작됨"으로 뜨는 `status: "scheduled"` 반영 확인.

**다음 영상에도 적용될 일반 교훈**: 제목 A/B 테스트처럼 "여러 후보 중 하나가 실제로
쓰일 수 있는" 기능을 추가할 때는, 그 값을 나중에 매칭/검색해야 하는 다른 코드(이번엔
YouTube 동기화)에도 전부 같은 후보 목록을 넘겨야 한다 — 기본값 하나만 매칭하는 코드가
숨어있으면 실사용 단계에서야 발견된다.
