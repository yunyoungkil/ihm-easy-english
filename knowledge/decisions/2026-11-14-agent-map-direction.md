# 2026-11-14 방향 기록: 에이전트 맵 회의와 전체 자동화 (처음 읽는 Claude를 위한 한 장)

> 이 문서는 **2026-11-14 하루 동안 사용자와 나눈 긴 논의를 한 흐름으로 다시 쓴 것**이다. 그날 인수인계(`knowledge/handoff/2026-11-14.md`)는 시간순으로 쌓은 조각 모음이라, 처음 읽으면 "왜 그렇게 정했는지"가 흩어져 보인다. 새 대화에서 이 방향의 일을 이어받는 Claude는 **이 문서를 먼저 읽는다.** 사용자가 처음부터 다시 설명하지 않아도 되게 하는 것이 이 문서의 목적이다.
> 표기: **[합의]** 사용자가 명시적으로 동의했다. **[제안]** Claude가 권고했고 사용자가 반대하지 않았다. **[대기]** 아직 정해지지 않았다. 숫자 기준은 근거 데이터가 없는 가설이다.

## 1. 사용자는 누구이고, 왜 이렇게 하려 하나
- 사용자는 **50대, 콘텐츠 제작 초보, 얼굴 공개를 원하지 않는다**(본인 출연 안 함). 아바타 이미지는 써 본 적이 있다.
- 사용자가 직접 밝힌 것: **데이터 분석, 아이디어 생산, 선택, 디자인을 보는 눈, 글쓰기, 글이 잘 쓰였는지 판단하는 것이 모두 어렵다.** 그래서 **전체 자동화로 AI가 콘텐츠를 만들게 하려는 것**이다. 이 전제가 이 문서의 모든 결정을 정한다.
- 사용자가 할 수 있는 것과 잘하는 것: **눈에 띄는 결함 찾기**(나레이션 끊김, 글자와 소리 불일치, 간격·줄바꿈 이상, 디자인이 확 이상한 것)와 **한국어 원어민의 귀**(나레이션이 한국 사람이 보기에 어색한지). 지금까지 렌더 전 시안을 이렇게 직접 검토해 왔다. 가장 자주 나온 결함은 **간격·넘침**과 **어색한 문장**이었다.
- 사용자의 마음: **지금까지의 기획부터 영상 제작까지를 전부 실패로 보고 처음부터 다시 시작하는 마음으로 이 시스템을 만들고 있다.** 그래서 이런 방법도 저런 방법도 생각하고 적용해 본다. 비교 시트는 벤치마킹, 데이터 근거, **사용자 본인이 배우는 교재**를 겸한다. 기존 대본·영상·그래픽은 실패작이지만 **그대로 쓰고, 새 방식은 다음 기획부터 적용한다.**
- 사용자는 "어쩔 수 없이 승인"해 왔다. 시안을 보고 영상을 만들어 봤지만 **어디를 어떻게 고쳐야 좋은 영상이 되는지 몰라서** 승인만 눌렀다. 어색한 문장은 고쳐도 계속 나와 **반쯤 포기한 상태로 승인**했다. → 지금까지 사람의 승인은 품질 판단이 아니었다.

## 2. 문제 진단 (왜 지금 영상이 템플릿처럼 보이나)
사용자의 불만: 영상이 **"일러스트에 글자만 찍어 내는 쉬운 템플릿형, 모션은 살짝 움직이는 정도"**이고 특별한 영상미가 없다. 시중에는 모션 그래픽으로 속도·템포를 살려 잘 만든 영상이 많다. 기획부터 제작까지 **비슷한 스타일 반복이고 창의성이 없다**(혼자 생각하고 정했으니 당연하다는 자각 포함).
Opus 검토(`opus-expert`)와 직접 대조로 확인한 원인:
- 이웃한 편끼리 영상 생성기 코드(`generate-frames.mjs`)의 같은 줄이 **약 70% 안팎** 같다(EP28→29를 직접 세니 75.4%, Opus는 71.0%, 세는 방식 차이). 프레임 이름 10개가 7편에서 같다.
- 반복 듣기 카드 프레임이 영상 길이의 **48%(EP29)~65%(EP24)**를 차지하고 이미지가 0장이다(Opus 계산, 직접 대조는 못 함).
- HyperFrames 도구를 거의 안 썼다(Opus: 부품 약 450개 중 EP14 이후 0개, 컴포지션에 배경음·효과음 0개 — **이 둘은 내가 직접 확인하지 못했다**).
- "일러스트 40% 이상" 규칙은 원인이 아니다(Opus: 카드 프레임에서 지켜지지도 않았다. 내가 처음에 이 규칙을 원인으로 의심한 것은 틀렸다).
- 레퍼런스 측정(`knowledge/reference-measurements.md`): 화면이 실제로 바뀐 프레임이 초당 **레퍼런스 15~25개 vs 우리 EP24 2.7개**, 무음 비율 레퍼 0.5~8% vs EP24 70.9%.
- **현재 규칙이 만든 정적임**: AGENTS.md 영상 도파민 절 3번이 "나레이션 구간만큼 이미지 한 장을 붙들고 0.2~0.3초 크로스페이드, 하드 컷 금지"다. 사용자가 "시간에 맞춰 한 장면씩 딱딱 바뀌는 건 우리가 이미 적용한 것 아닌가"라고 물은 것이 정확히 이것이다. 차이는 "나레이션에 맞춰 바꾸느냐"가 아니라 **한 장면 안에서 움직이느냐**와 **장면 종류가 다양하냐**다.

## 3. 결정 (왜 그렇게 정했나)

### 3-1. 실험 변수에는 정해진 것이 없다 [합의]
영상 스타일, 제목 틀, 썸네일, 훅, 아바타 유무는 **하나도 정해진 것이 없다.** B롤이 들어간 실사 영상, 모션 그래픽, 애니메이션형 모두 같은 무게의 후보다. 내가 규칙의 세 층을 설명하며 든 예(아바타, 일러스트 스타일)를 사용자가 후보 목록처럼 읽을 수 있다고 정정했다. **이유**: 사용자는 에이전트 맵의 담당 회의로 형태를 도출해 적용할 계획이라, 미리 정해진 것처럼 말하면 그 과정을 가둔다. → AGENTS.md의 일러스트 40% 이상·아바타 중단 등은 "기본값 층"이고 근거가 있으면 바뀐다. 이 문구를 고칠지는 에이전트 맵 논의에서 정한다(아직 안 고침).

### 3-2. 사용자가 판단하지 못하니, 품질은 사람이 아니라 장치가 맡는다 [합의]
- 사람이 승인하는 세 곳(렌더·썸네일·업로드)은 **품질 관문이 못 된다**(1절). 안전(금지어, 규정, 거짓 경험)과 사용자의 호불호를 보는 자리로 본다.
- 품질 장치(제안): ① 숫자로 재는 것은 코드(컷/분, 글자 체류 시간, 이웃 편과의 코드 유사도, 문장 틀 반복) ② 글의 질은 항목별 기준표 채점 ③ 최종 심판은 시청자 데이터(실험 루프) ④ 사용자는 **판단이 아니라 "반응"**만 한다.
- Claude는 사용자에게 "이 글/영상이 괜찮은지 판단해 달라"고 **맡기지 않는다.** 전문 판단은 기준표·측정·데이터로 하고 "AI가 이 안을 골랐고 이유는 이 숫자"라고 쉬운 말로 알린다.
- 같은 AI끼리 점수를 매기면 쏠린다. 그래서 점수는 AI의 느낌이 아니라 **외부 기준**(레퍼런스 측정값, 말투 비교, 자동 점검 결과, 실제 댓글·결과 데이터)에 묶는다.

### 3-3. 에이전트 맵과 회의 방식 [합의: 방향, 제안: 세부]
**목적**: 영상미와 창의성을 올린다. 그래픽·모션·편집 전문 담당 AI를 두고 회의로 영상 형태를 도출한다. (일반 유튜브 제작사의 CP·PD·작가·편집자·썸네일 디자이너·채널 매니저 구조를 참고했지만, 촬영감독·출연자·AE·크리에이터 매니저·커뮤니티 매니저는 지금 의미가 없다.)
**담당(Opus 검토 반영)** — 형식별 옹호자(실사 담당, 일러스트 담당)로 나누지 않는다. 답을 쥐고 시작해 서로 영업만 하기 때문이다. **기술 영역별**로 나눈다.
| 담당 | 역할 |
|---|---|
| 구성 작가 | 장면 순서, 고유 코너, 훅, 오픈 루프를 직전 3편과 다르게 |
| 그래픽 디자이너 | 화면 체계(레이아웃·색·타이포), 핵심 화면 3장 |
| 모션 디자이너 | 움직임 문법(등장·전환·키네틱 글자), 컷 리듬 |
| 편집·사운드 | 컷 길이, 비트 싱크, 배경음 템포, 효과음 |
| 비판자(Opus 1명) | 3060 가독, 불변 규칙, 같은 틀 여부를 외부 기준으로 채점 |
| 측정·기록(코드) | 레퍼런스·시안을 같은 자로 재고 7일 뒤 결과를 이어 붙임 |
**회의 방식**: 창의성은 같은 모델 여럿의 토론이 아니라 **담당마다 다른 레퍼런스, 숫자로 정한 강제 제약, 실제로 만든 시안끼리의 비교**에서 나온다(Opus 판단, 확신 중간). 그래서 담당마다 다른 레퍼런스 묶음과 강제 제약 하나를 받아, **서로 보지 않고 같은 15초 구간 시안**을 스냅샷과 수치로 만든다(렌더 없음). **회의는 큰 결정에서만** 연다(첫 1회, 대기열이 빌 때, 좋은 결과·신뢰 하향이 나왔을 때, 사용자 요청). 서브에이전트 하나를 부를 때마다 규칙 문서 약 78KB가 실려 비싸다(AGENTS.md 0번 10항 토큰 절약과 충돌).
**회의 산출물은 새 고정 규칙이 되지 않는다.** "이번 편의 시험 변수"로만 남는 실험 대기열이다. 이긴 스타일도 구성·코너는 매 편 달라야 한다("같은 틀 찍어 내지 않는다" 원칙).

### 3-4. 시안을 보고 사용자가 하는 일 [합의]
- 질문은 "승인하시겠습니까"가 아니라 **"보고 싶은 순서는?"** 또는 **"레퍼런스와 가까운 쪽은?"**. 평가가 아니라 취향 반응이라 전문 지식이 필요 없다.
- **"전부 별로"가 정식 선택지**다(불이익·설명 의무 없음). 이유는 전문 지식 없이 고르는 **한 단어**(느리다·답답하다·유치하다·복잡하다·밋밋하다·싸 보인다·정신없다·기타).
- 전부 별로면 **점수가 가장 높은 안으로 진행**한다. 사용자가 합의한 이유: "나는 보는 눈이 없어 좋은 걸 놓칠 수 있고, 점수 높은 안이 시청자에게는 좋을 수도 있다." 사용자가 별로라 했지만 공개한 안의 성과를 기록해, **사용자 반응이 시청자 반응을 얼마나 예측하는지** 나중에 숫자로 본다.
- **"별로"와 "절대 안 됨"을 구분**한다. 절대 안 됨(얼굴 공개, 채널 이미지, 안전·정책)은 거부권이고 점수와 상관없이 막고 다시 만든다.
- 사용자의 고유한 역할은 **나레이션을 귀로 듣는 검수**(한국어 어색함)와 첫인상이다.

### 3-5. 시험 → 승격 → 평준화 [합의]
- 매 편 대부분은 **현재 가장 잘 나오는 방식**, 한두 가지만 **새로 시험**한다(한 번에 많이 바꾸면 원인을 못 가린다).
- 결과별 행동(가설 숫자): 평소의 **1.5배 이상** → 소재를 바꿔 한 번 더 시험해 또 넘으면 기본값 승격 / **0.5~1.5배** → 보류하고 다음 스타일 시험(나중에 재시험 가능) / **0.5배 미만** → 신뢰 하향 표시(지우지 않음). 한 번의 결과로 버리거나 굳히지 않는다.
- **평준화되면**: 신선함이 식어 평소 수준이 되는 것은 자연스럽다. 그 수준이 새 "평소"가 되어 다음 시험은 그 1.5배를 넘어야 한다. 승격된 기본값도 연속으로 이전 기준선 아래면 내려 다시 시험한다.
- **스타일 시험은 쇼츠에서 먼저**: 롱폼은 7일 조회 중앙값이 6회(n=27)라 판정이 안 되고, 쇼츠는 1,141회(n=51)다.
- 사용자가 "무슨 말인지 모르겠다"고 한 것(쇼츠 먼저, 승격 조건, 대기열·측정표 파일 위치)은 쉬운 말로 설명했고, **Claude가 권고대로 정해 알리기로 했다**(파일 위치는 구현할 때 정해 알림).

### 3-6. 영상 표현의 방향 [합의]
- **역동성 제한은 시험 변수로 연다.** 사용자: 리듬감에 필요하다. 요즘 30~60대는 미디어·SNS에 익숙해 힘들어하지 않고 사용자(50대)도 전혀 상관없다. (AGENTS.md의 "어지러운 컷 전환 금지"는 나레이션 톤의 "틱톡 하이퍼 텐션 금지"와 별개이니 **나레이션 톤은 따로 확인한다**.)
- **실사·아바타·스톡 모두 같은 무게의 후보.** 본인 출연은 없다. 아바타와 짧은 무표정 실사는 필요하면 쓴다. 무료 생성 도구의 워터마크는 **화면을 크롭해 가리는 방법**이 이미 문서에 있다(`knowledge/free-generation-tools.md` 영상 행: 잘려도 되는 여백이 있는 장면에만, 화질·구도 손실, 소리 제거).
- **"전부 움직이면 안 된다"** [사용자 확인]: 나레이션에 동기를 맞춰 화면이 바뀌는 것은 유지하되, **장면 안에서도 움직임**(순서대로 등장, 선 그리기, 단어별 강조, 확대·이동)과 **장면 종류의 다양성**(표·목업·지도·캐릭터)을 늘리고, **정적이 필요한 곳(퀴즈 정답 공개, 집중 듣기)은 남긴다. 정적/동적 리듬을 설계한다.** 레퍼런스 중 샘 호트만(레퍼5)은 사람이 나오는 게 아니라 카드·표·선을 움직이는 애니메이션 인포그래픽 형태로, HyperFrames(HTML·GSAP)로 만들 수 있는 종류다.

### 3-7. 나레이션 말투 [합의: 방향]
- 사용자가 원하는 것은 **한국 유튜버가 실제로 쓰는 말투·문장**이다. 일반 사람은 "귀를 뚫어 드리겠습니다", "이렇게 배운 건 속으신 겁니다" 같은 말을 하지 않는다. 어색한 문장은 고쳐도 계속 나왔는데 **문장 목록을 기록하지 않았다.**
- **금지 표현 목록(규칙 기반)을 늘리는 방식은 근본 해결이 못 된다.** 그래서 기준을 **같은 분야 실제 한국 유튜버의 말투 측정**으로 삼는다. 레퍼런스 5편(AI·개발 영상)을 재 보니 **"한국 유튜버의 하나의 말투"는 없었다**(어떤 채널은 습니다체 59~68%, 어떤 채널은 해요체 84%). 그래서 **영어 학습 분야**의 잘된 영상 10편을 따로 재고 있다(결과는 handoff 마지막 절).
- 앞으로 사용자가 어색한 문장을 짚으면 **Claude가 문장과 이유를 대화 중에 바로 기록**해 규칙에 반영한다(사용자가 손으로 적지 않는다).

### 3-8. 스튜디오 "조사" 목록으로 소스 교체 [합의: 방향, 속도는 설계안]
- 사용자의 판단: 손으로 넣은 키워드·채널과 프로그램이 거기서 찾은 영상은 **"검증 안 된 자료"**("노이즈"는 소음이 아니라 이 뜻이다). 유튜브 조사 데이터는 우리 채널에 맞게 유튜브가 직접 골라 준 것이라 더 정확하다고 본다.
- 사실 조사(Sonnet·Opus): 옛 자료는 키워드 17(손입력 13)·채널 6개 전부 `candidate`, 승격·차단·졸업 0건, 최근 BRIEF 13개 중 인용 2건, 조사 후보와 영상 겹침 0. 다만 판정 코드는 매일 돌았고(결과 0건의 원인은 근거 없이 기획됐고 7일 조회가 낮았기 때문), **지금 만들고 있는 소재(`SbQVBQoRciA`)는 옛 자료에서 나왔다.**
- **속도: "기존에 계획했던 대로(설계안 7일+14일)"** [사용자 결정]. 단축안(2단계 11/17, 3단계 11/22)은 채택하지 않았다. 2단계(리포트 대상을 조사 후보로 전환)는 수집 7일 중 6번 정상 뒤(약 11/21 이후), 3단계(손입력 삭제, 경쟁 분석 탭 교체)는 2단계 14일 기준 뒤(약 12/5 이후)이며 **삭제 직전에 설계 9절 결정 2·3·4를 사용자에게 다시 확인**한다. 지금 바꾸면 `old-reports-done`이 잘못 떠 대체되지 않은 예전 리포트 9편이 지워진다.
- 조사 목록도 걸러야 한다(수능·모의고사, 연예 클립 노이즈). 유튜브 배수(`studioFolds`)와 우리 배수(`outlierRatio`)는 정의가 달라 섞지 않는다.

### 3-9. 이미 만든 영상은 고치지 않는다 [합의]
EP24~29를 포함해 이미 만든 영상·대본·그래픽에는 새 방식을 적용하지 않는다(사용자: 어차피 실패작이고 그대로 쓸 것). **EP29의 줄바꿈 결함 5건**(07번 장면 `?` 외톨이, `bow.` 외톨이, 끝 화면 `[f] vs / [p]`, `완성 / 하기`)도 고치지 않는다(재렌더 안 함). 새 방식은 **다음 기획부터** 적용한다.

## 4. 논의가 흘러온 순서 (왜 이 순서였나)
1. 사용자가 "다음 할 일"을 물음 → 조사 목록 수집기 1단계(승인됨)를 에이전트 맵 병렬 구성(순수 함수 / 화면 정찰 / 루프 연결)으로 구현하고 첫 수집(롱폼 27편·쇼츠 49편 통과, 후보 76편).
2. 대시보드가 구버전이어서 서버를 재시작(pull로 서버 코드가 바뀌었는데 이전 서버가 떠 있었음).
3. 사용자가 "키워드·경쟁 채널을 지우고 유튜브 자료로 가기로 했다"고 기억 → 문서에는 1단계만 승인으로 남아 있었음 → Opus·Sonnet에게 지금 교체해도 되는지 물음 → 설계안(7일+14일)대로 가기로 결정.
4. 사용자가 **에이전트 맵 회의**를 제안 → 제작사 구조 비교 → 1차 Opus 검토 → 사용자 정정("B롤만이 아니라 모든 가능성, 모션그래픽, 영상미, 창의성") → Opus 검토를 넓혀 재작성.
5. 사용자가 **품질 판단 능력이 없다**고 밝힘 → 사람의 승인이 품질 관문이 못 됨 → 자동 점검·기준표·데이터가 품질을 맡는 설계.
6. 사용자의 **렌더 전 검토 방식**(끊김, 글자 불일치, 간격·넘침, 디자인 이상, 어색한 문장)을 듣고 가장 잦은 3·4번을 자동 점검으로 구현.
7. 사용자가 **레퍼런스 5편**을 줌 → 같은 자로 측정 → 정적/동적 리듬 방향 합의 → **영어 학습 분야** 레퍼런스 추가 측정.
