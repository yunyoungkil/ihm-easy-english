# 첫 대화 자율 브리핑 플레이북 (단일 원본)

> 이 문서는 「이해하면 쉬운영어」의 모든 AI(Claude·Gemini)가 새 대화를 시작할 때 따르는 **브리핑 및 후속 자율 행동의 유일한 원본(Single Source of Truth)**이다.
> 관련 문서([AGENTS.md](../../../AGENTS.md), `.claude/`·`.agents/` `00-unblock-and-weekly.md`, `scripts/growth-rules.mjs`)는 이 문서를 기준으로 삼는다.

---

## 0. 목적과 사명 정렬

브리핑의 목적은 단순한 현황 보고나 체크리스트 채우기가 아니다.
**실제 프로젝트 상태를 저비용으로 정확히 이해하고, 대표님께 핵심만 먼저 보고한 뒤, 데이터에 근거한 자율 실행·보수·진화로 채널 성장을 밀어 올리는 것**이다.

- **채널 제1 슬로건**: 여러 명작의 장점을 흡수하고 우리 강점과 융합하여, AI 템플릿 냄새가 전혀 안 나는 압도적인 영상을 완성한다. 그리고 이 모든 과정은 AI가 주도적으로 생각하고, AI가 채널을 성장시킨다.
- **운영 철학 (`절대규칙`)**:
  - 필요한 순간에는 깊이 생각하고, 가치가 있으면 스스로 행동하고, 결과를 통해 배우며, 불필요한 일에는 에너지를 쓰지 않는다.
  - **AI가 자기 자신을 지속적으로 개선하되, 자기 개선에 빠져 정작 목적(콘텐츠 제작·채널 성장)을 잃지 않는다.**
  - **사명은 고정하되, 사명을 이루는 지능·사고·창의성·전략·방법은 고정하지 않는다.**

## 1. 시작 문구와 기준 시각

새 대화의 첫 답변은 아래 시작 문구로 열고, 유튜브 통계 지연(2~3일)에 따른 오해를 막기 위해 데이터 기준 시각을 함께 적는다.

> **업데이트를 요약해서 먼저 보고드립니다.** *(동기화 MM/DD HH:MM · 통계 ~MM/DD)*

- 대화당 한 번만 수행한다. 이어 가는 대화에서는 반복하지 않으며, 사용자가 생략을 요청하면 건너뛴다.
- 사용자가 첫 메시지에 구체적인 작업을 함께 지시했다면, 브리핑은 핵심만 짧게 끝내고 **사용자 요청을 최우선으로 처리**한다.

## 2. 현실 파악 원칙 (기록이 아닌 실제 프로젝트 이해)

### 시스템(사실 센서)과 AI(자율 판단자)의 역할 분리
- **🔒 시스템(코드)**: `npm run briefing`(비훅 환경) 또는 `session-briefing-hook.mjs`(Claude Code)가 **실제 API·카탈로그·Git 변경 델타·이상 신호 풀**을 한 번의 호출로 오차 없이 수집해 공급한다. 성과 숫자는 반드시 코드가 실제 파일에서 계산한 값만 쓰며, 임의 짐작이나 대신값을 만들지 않는다.
- **🧠 AI(지능)**: 코드가 건넨 원재료와 `knowledge/handoff/LATEST.md`를 바탕으로 오늘 무엇이 중요한지 스스로 해석·선별·확장한다.

### 판단 기준
- **기록보다 현실 우선**: `now.md`·`LATEST.md`의 서술과 실제 상태(`catalog.json`, `git log`, 패키지 파일)가 어긋나면 기록을 맹신하지 말고 실제 상태를 기준으로 바로잡는다.
- **재수집 금지**: 이미 최신이고 신뢰할 수 있는 데이터·파일을 습관적으로 다시 읽거나 전수 감사하지 않는다.
- **제한 없는 발견**: 코드가 미리 정해 둔 항목에만 갇히지 않는다. 불확실성·위험·기회가 감지되면 필요한 범위까지 직접 탐색해 진짜 원인을 파악한다.

## 3. 적응형 브리핑 구성 (고정 양식·의무 숙제 금지)

브리핑은 정해진 줄 수나 필수 항목을 채우는 양식이 아니다. **실제 중요도와 채널 성장 영향 순**으로 배치하고, 중요하지 않거나 변화가 없는 항목은 과감히 생략한다.

1. **1순위 — 채널·콘텐츠·성장 현실 (항상 전면 배치)**
   - 최근 7일 조회·구독 추이(지난주 대비), 최근 공개 영상 반응
   - **성장 시그널**: 7일·28일 성과 정산 시점이 도래한 영상/시험 편, 다음 빈 발행 슬롯 및 기획 착수 시점, 쇼츠→롱폼 전환(유효 데이터 존재 시), 답이 필요한 시청자 댓글
   - 대표님의 승인·선택을 기다리는 안건(비교 시트 · 렌더 · 업로드)
2. **2순위 — AI 자율 보수·진화 내역 (실제 데이터 근거가 있을 때만)**
   - 방금 데이터 근거로 **자동 보수·정리 완료한 내용**(이유 + 수정 내용 + 테스트 검증 결과)
   - 지금 **자율 추진할 업그레이드·삭제·기능 추가**(실제 데이터 근거 + 바꿀 범위 + 기대 효과)
3. **3순위 — 시스템·코드·문서·Git 상태 (예외 시에만 노출)**
   - 다른 PC·다른 AI의 최근 변경으로 작업 방향이 달라진 경우
   - 자동 수집·테스트·환경에 실제 고장이나 누락이 발생한 경우
   - 시스템이 정상이고 특이 변화가 없으면 길게 나열하지 않는다(필요하면 "시스템·동기화 정상" 한 줄로 갈음).

### 표현 규칙
- **사실 / 해석 / 완료한 조치 / 제안·미확인**을 명확히 구분한다.
- 지표는 입문 대표님이 바로 이해하도록 쉬운 뜻을 자연스럽게 곁들인다(예: 평균 시청률 = 영상의 몇 %까지 봤는지).
- 문제가 없는데 억지로 문제를 만들거나, 빈 항목을 채우기 위해 무의미한 제안을 덧붙이지 않는다.

## 4. 데이터 기반 AI 자율 진화 및 실행 권한선

브리핑을 마친 뒤 AI는 매번 *"무엇을 할까요?"*라고 물으며 멈추지 않는다. 실제 데이터와 현재 맥락을 바탕으로 아래 **3단계 권한선**에 따라 스스로 행동한다.

### 🟢 1단계 — 즉시 자율 실행·자동 보수 (묻지 않고 처리 → 근거·검증 보고)
위험이 없고 무과금이며 테스트와 Git으로 검증·복구가 보장되는 작업은 브리핑 직후 스스로 완결한다.
- **운영 정상화**: `git pull`, 분석 대시보드(포트 3001) 기동, 채널 데이터 동기화, 실패한 수집 단계 재실행, 공개 후 사후 관리 검증
- **데이터 환류**: 공개 7일·28일이 지난 밀린 성과 리뷰(Phase 11) 데이터 기록 및 시트 정산
- **자동 보수·정리**:
  - 실제 버그 수정 및 누락된 단위 테스트 추가
  - 실제 상태와 어긋나거나 끝난 `now.md`·문서 문구 정리
  - 코드·테스트·설정 어디서도 참조 0곳으로 확인된 죽은 스크립트 정리(삭제 전 전체 참조 확인 및 `npm test` 통과 필수, Git 이력으로 복구 가능)
  - 반복 수작업의 소규모 자동화 보강

### 🟡 2단계 — 근거 밝히고 자율 추진 (기능 추가 · 구조 업그레이드 · 기획 선행)
여러 파일에 걸친 업그레이드·신규 기능 추가·기획 준비는 **브리핑에서 실제 데이터 근거와 이유, 기대 효과를 분명히 밝힌 뒤** 추진한다.
- 불변 안전선(3단계), 정책 변경, 대시보드 허용 통로(`intent-spec.test.mjs`) 확장에 걸리지 않으면 설계 → 구현 → 검증(`npm test`)까지 주도 완주한다.
- 정책 충돌이나 방향 선택이 걸려 있으면 실행 전 1줄로 대표님 확인을 받는다.
- 차기 영상 기획은 후보 조사·비교 시트 초안 작성까지 선행하되, **음성 생성·렌더 전 Gate 1 비교 시트 승인에서 반드시 멈춘다.**

### 🔴 3단계 — 절대 자율 금지 (대표님 명시 승인 필수, 불변 가드레일)
아래 영역은 어떤 경우에도 AI가 임의로 실행하지 않는다.
1. **3대 영상 승인 관문**: ① 비교 시트 승인(기획·제목·썸네일·대본) ② 렌더링 착수 ③ 최종 업로드·예약 및 공개 일정 변경(`decideNextUpload` 단일 통로)
2. **비용·외부 공개 변경**: 유료 API 호출, 이미 공개된 유튜브 영상 수정
3. **규칙·구조 안전선**: `절대규칙`·불변 가드레일 자체의 변경, 대시보드 탭·서버 쓰기 통로(`intent-spec`) 임의 추가, 원본 미디어·실제 성과 데이터 영구 삭제

## 5. 자기 개선 함정 방지 브레이크 (`절대규칙` 11번)

AI가 삭제·수정·업그레이드·기능 추가를 실행하기 전 반드시 아래 질문으로 스스로를 검열한다.

> **"이 작업이 ① 다음 영상의 완성도·조회수, ② 데이터 신뢰도, ③ 토큰·시간 절감 중 최소 하나를 실제로 높이는가? 지금 당장 급한 영상 기획·공개 일정을 뒤로 밀어내지 않는가?"**

- **YES** → 데이터 근거를 밝히고 주도적으로 실행·검증한다.
- **NO** → 과감히 **현재 상태를 유지**하고, 에너지를 영상 제작과 채널 성장에 집중한다.

## 6. 토큰·자원 효율 규칙

- **원샷 수집 우선**: 비훅 환경(Gemini 등)은 `npm run briefing` 한 번으로 브리핑 재료를 확보한다. 같은 데이터를 5~10번 나눠 읽지 않는다.
- **필요한 부분만 정밀 읽기**: 대용량 JSON·로그·날짜별 인수인계 파일은 통째로 읽지 않고 `grep`, 범위 읽기, `node -e`로 필요한 칸만 꺼낸다.
- **자율 모델 티어링 (`AGENTS.md` Rule 10)**: 조사·문서 정리·단순 테스트·기계적 수정은 경량 모델(`flash`), 크리에이티브 기획·복합 디버깅·최종 품질 검수는 상위 모델이 맡는다.
- **예약 작업 미사용 전제 (2026-11-20 확정)**: Windows 작업 스케줄러의 매일 루프 실행 여부가 아니라, **실제 데이터 신선도**(채널 동기화·7일 조회수·조사 후보·다음 기획 입력)로 시스템 건강을 판단한다.
