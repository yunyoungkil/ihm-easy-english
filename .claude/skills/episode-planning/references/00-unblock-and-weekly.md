# Phase 0: 막힌 곳 풀기 (0-A 대청소 · 0-B 주간 점검)

새 영상을 기획하기 전에 "이미 만든 것이 시청자에게 닿고 있는지"부터 본다. 영상이 대기열에 쌓여 있거나 리뷰가 밀려 있으면, 새 기획보다 그걸 푸는 게 조회수에 먼저 영향을 준다.

- **0-A 대청소**: 쌓인 일이 많을 때 한 번 크게 치운다. 업로드 대기 3편 이상, 또는 밀린 리뷰 3편 이상이면 0-A로 간다.
- **0-B 주간 점검**: 대청소가 끝난 뒤 매주 가볍게 돈다.

공통 규칙:
- vidIQ는 쓰지 않는다. 우리 채널 숫자는 대시보드(`npm run analytics`, 포트 3001), 상태 확인은 프로젝트 자체 YouTube 연동을 쓴다(`CLAUDE.md` "우리 채널 자체 유튜브 데이터는 vidIQ보다 프로젝트 자체 연동을 먼저 쓴다").
- 숫자는 `POST /api/sync` 직후 `GET /api/dashboard`, `/api/episodes/summary` 응답 값만 쓰고 `range`를 같이 적는다.
- `status.json`은 손으로 고치지 않는다(`knowledge/production-rules.md` "4번째 원인 — status.json을 에이전트가 손으로 고칠 때").
- 업로드는 대시보드 자동 예약 업로드(`decideNextUpload`)나 사용자가 스튜디오에서 직접 한다. 에이전트가 우회 경로를 만들지 않는다(`CLAUDE.md` Client Script Integrity 5번).

## 0-A. 대청소 (쌓였을 때 한 번)

1. **실제 공개 상태 확인**
   - `npm run growth-check`를 돌린다. 이 스크립트는 `data/youtube/catalog.json`(대시보드 동기화 결과)을 기준으로 공개 여부를 본다.
   - 동기화가 오래됐으면 `/api/sync`부터 하고 다시 돌린다. 그래도 맞지 않으면 `knowledge/production-rules.md` "업로드 후 대시보드 자동 동기화가 안 될 때" 절을 순서대로 확인한다.
2. **공개 일정표와 업로드 체크리스트**
   - 미공개 편을 언제 올릴지 표로 만든다. 간격은 `knowledge/production-rules.md` "공개 일정과 엔딩 화면 연결 규칙"과 대시보드 예약 설정 중 현재 쓰는 쪽을 따르고, 어느 쪽을 따랐는지 적는다.
   - 편마다 업로드 전에 남은 일을 `upload-checklist.txt`와 `knowledge/now.md`에서 읽어 함께 적는다(새 메인 썸네일, 썸네일 승인, 금지어 항목 등).
   - 같은 방식·형식이 연달아 나가면 "같은 틀 반복"으로 보일 수 있으니, 사이에 쇼츠를 끼울 수 있는지 함께 제안한다(Phase 12).
3. **밀린 리뷰 숫자만 먼저 채우기**
   - `npm run evaluate-48h`를 한 번 돌린다.
   - 공개 7일이 지난 영상의 `REVIEW.md` "실제" 칸에 `/api/sync` 직후 숫자만 채운다. 판정과 `success-patterns.json` 승격은 이 단계에서 하지 않는다. 판정은 Phase 2에서 그 형식이 필요할 때 Phase 11로 한다.
4. **전후 비교**: 마지막에 `npm run growth-check`를 다시 돌려 막힌 곳이 얼마나 줄었는지 보여 준다.

**멈춤 지점**: 2번 공개 일정표는 사용자 확인을 받는다. 나머지는 보고하고 계속한다.

## 0-B. 주간 점검 (매주)

1. `npm run growth-check -- --save`로 새로 막힌 곳만 찾는다. 결과는 `knowledge/growth/check-YYYY-MM-DD.md`에 저장된다.
2. `/api/sync` 직후 숫자로 이번 주를 본다: 조회수·구독자 증감, 롱폼 vs 쇼츠 비중, 상위 트래픽 소스 3개, 검색 유입 비중, 최근 영상 시청 지속률.
3. 공개 2일이 지난 영상이 있으면 `npm run evaluate-48h`, 7일·28일이 된 영상이 있으면 Phase 11.
4. Phase 11의 **중단 규칙**에 걸린 방식·형식이 있는지 확인한다(`05-performance-review.md` 4절).
5. `marketing:performance-report` 스킬로 한 장 요약: 핵심 숫자 표(출처·범위 포함) → 잘된 것 1~2개 → 막힌 것 1~2개 → **이번 주 할 일 최대 3개**. 할 일은 "EP25 썸네일 승인"처럼 이번 주 안에 끝낼 수 있는 행동으로 쓴다.
6. 결과는 `knowledge/growth/weekly-YYYY-MM-DD.md`에 남긴다(같은 날짜 파일이 있으면 읽고 갱신).

**멈춤 지점**: 없음. 보고하고 끝낸다.

## 지표를 사용자에게 말할 때

초등학생도 알아듣게 한 줄 풀이를 붙인다.

| 지표 | 쉬운 뜻 |
|---|---|
| 노출 클릭률(CTR) | 썸네일을 본 사람 중 누른 비율 |
| 평균 시청률 | 영상의 몇 %까지 봤나 |
| 검색 유입 | 검색해서 들어온 조회 |
| 추천 유입 | 다른 영상 옆이나 홈에 떠서 들어온 조회 |
| 구독 전환 | 이 영상을 보고 구독한 수 |
