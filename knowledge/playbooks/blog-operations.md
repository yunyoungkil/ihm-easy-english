# 쿠팡 블로그 운영 지침 (`tech.d40m.com`)

이 문서는 쿠팡 파트너스 연동 블로그(`tech.d40m.com`)의 주간 경고 점검, 긴급 멈춤·재개, 주제 보충 절차를 정리한다.

---

## 1. 주 1회 경고 화면 점검 순서

시작 브리핑에서 `경고 화면 점검 필요`가 뜨거나 일주일에 한 번 아래 세 곳을 순서대로 확인한다.

1. **구글 서치 콘솔** (`sc-domain:d40m.com`)
   - **직접 조치** 메뉴와 **보안 문제** 메뉴에 경고·안내 문구가 없는지 확인한다.
2. **구글 애드센스 정책 센터**
   - 사이트별·계정별 정책 위반이나 광고 제한 경고가 없는지 확인한다.
3. **쿠팡 파트너스 공지 및 이메일**
   - 공지사항과 연결된 이메일함에 제재·대가 문구·링크 위반 경고가 없는지 확인한다.

확인이 끝나면 `data/blog/signal-checks.json` 배열 끝에 아래 형식으로 한 줄을 추가한다.

```json
[
  {
    "date": "2026-11-25",
    "searchConsole": "ok",
    "adsense": "ok",
    "coupang": "ok",
    "note": "특이사항 없음"
  }
]
```

- 이상이 없으면 `'ok'`, 경고나 제한 알림이 있으면 `'warning'`으로 적고 `note`에 화면 문구 요약을 남긴다.

---

## 2. 경고 발견 시 즉시 처리

세 화면 중 하나라도 `'warning'`이 확인되면 **그 자리에서 자동 발행을 멈춘다.**

1. `scripts/blog/blog-store.mjs`의 `writePause`로 `data/blog/tech-paused.json`을 멈춤 상태로 기록한다.
   - `reason`에 어느 화면에서 어떤 경고가 떴는지 구체적으로 적는다.
2. `data/blog/signal-checks.json`에도 해당 항목을 `'warning'`으로 기록한다.
3. 확인한 화면 문구(원인·근거)와 멈춤 사실을 사용자에게 보고한다.

---

## 3. 다시 켜기 규칙 (사용자 승인 필수)

- `tech.d40m.com`은 **유튜브 채널과 같은 애드센스 계정**을 쓴다.
- 따라서 어떤 사유로든(`점검 실패 3회 연속` 또는 `경고 감지`) `data/blog/tech-paused.json`의 `paused`가 `true`가 된 뒤에는, **반드시 사용자의 명시적 승인을 받은 뒤에만** `paused`를 `false`로 바꾸고 다시 켠다.
- AI나 자동화 스크립트가 임의로 멈춤 상태를 해제하지 않는다.

---

## 4. 주제 보충 방법 (대기열 6개 미만일 때)

시작 브리핑에 `대기열 N개(주제 보충 필요)`가 뜨면 아래 순서로 주제를 채워 `data/blog/tech-queue.json`에 추가한다(목표: 2~4주 분량 유지).

0. **주제는 갈래 안에서 고른다 (2026-11-27 사용자와 논의, AI 판단)**
   - 지금 갈래는 둘이다. **A `휴대폰 결제·교통카드·액세서리`**(교통카드·애플페이·삼성페이·맥세이프·케이스·보조배터리), **B `큰 가전 설치 전 확인`**(세탁·건조기·식기세척기·냉장고 설치 공간·조건, 홈캠, 가전 포인트). 대기열 항목마다 `cluster`에 갈래 이름을 적고, A·B를 번갈아 놓는다.
   - 근거: 구글 공식 점검 질문이 "사이트에 주된 목적이나 초점이 있는가", "여러 다른 주제로 글을 많이 만들어 일부가 검색에 걸리길 바라는가", "많은 주제의 글을 자동화로 대량 생산하는가"를 묻는다(Search Central "Creating helpful, reliable, people-first content"). 우리는 자동으로 쓰니 주제가 흩어지면 바로 이 경고에 해당한다. 옛 서치 콘솔 검색어(499개, 클릭 490)에서 맥세이프·교통카드 묶음과 설치 공간·홈캠 묶음이 클릭이 가장 많았고, 2026-11-27 구글·네이버 자동완성에서도 "안됨·오류·조건·비용·키트" 같은 문제·구매 전 검색어가 살아 있었다.
   - 옛 글을 살리는 것이 목적이 아니다(사용자). 키워드·수익·유입에 도움이 되는 주제만 넣고, 갈래 밖 주제는 넣지 않는다. 11/27에 뺀 주제: 공기청정기 필터(옛 클릭 0), 쿠팡 반품마켓, 레노버 Y700 게임 모드(옛 클릭 42지만 기기 하나에 묶임, 세 번째 갈래 후보), 쿠진아트 열선 청소(옛 클릭 31, 주방가전 갈래 후보), LG TV 모델명.
   - **같은 갈래 글끼리 링크 (2026-11-27 사용자 결정)**: 새 글이 같은 갈래로 이미 올린 글 중 정말 이어지는 글에만 본문 링크 1~2개를 단다. 이미 올린 글은 다시 고치지 않는다(12/24 점검 때 다시 봄). 링크 글자는 그 글 내용을 말하는 문구로 쓴다(구글 Link best practices). 게시 기록 `tech-posts.json`의 `cluster`로 후보를 고르고, 지침은 `scripts/blog/prompts/tech-post.md` 6절, 점검은 `check-post.mjs`의 `internal-link-*`(목록에 없는 주소·3개 이상·"여기" 같은 글자면 탈락).
   - 갈래를 바꾸거나 늘리는 것은 12/24(4주 점검)에 서치 콘솔·쿠팡·애드센스 실측으로 정한다(지금 갈래는 가설).

1. **옛 서치 콘솔 검색어 내보내기**
   - 프로젝트 크롬 첫 번째 계정(`/u/0/`)으로 서치 콘솔에 들어가 `sc-domain:k-posting.info`·`sc-domain:costcatcher.k-posting.info`의 **실적 → 검색어 → 기간 최대 → 내보내기(CSV)** 를 받아 `data/blog/sources/`에 둔다.
2. **지금도 찾는 문제 해결 주제 고르기**
   - 클릭·노출 상위 검색어 가운데 사람들이 실제로 불편을 겪어 찾는 문제를 고른다.
   - 구글·네이버 자동완성과 지식인 질문으로 현재 검색 수요가 살아 있는지 확인한다.
   - **실제 월 검색 수로 표현을 고른다 (2026-11-27 사용자 결정)**: `node scripts/blog/keyword-volume.mjs check <표현1>, <표현2>, ...`로 같은 뜻의 표현을 견주고, `related <낱말>`로 관련 검색어를 본다(네이버 검색광고 키워드 도구, `.env`의 `NAVER_SEARCHAD_*`). 네이버는 **입력한 표현 그대로**만 세므로 긴 문장형은 거의 늘 10회 미만이다(11/27 실측: "애플페이 교통카드" 13,600회 / "애플페이 교통카드 안됨" 10회). 그래서 주제의 핵심 표현을 `targetKeyword`(주 검색어)로 따로 적고, 글쓰기 AI는 그 낱말을 제목·첫 문단에 자연스럽게 넣는다(`tech-post.md` 1절 6항). `searchQuery`는 출처 찾기용으로 둔다.
   - **우리 글의 구글 실제 성적부터 본다 (2026-11-27 사용자 결정)**: 무인 실행(월·수·금)마다 `data/blog/search-console.json`이 새로 쌓인다(손으로는 `node scripts/blog/search-console.mjs collect`). 최근 28일 검색어×글별 노출·클릭·평균 순위와 글마다 색인 상태가 들어 있다. 우리 글이 이미 노출되는 검색어 가운데 아직 따로 다루지 않은 질문은 같은 갈래 새 주제나 `targetKeyword` 후보로 쓴다. 네이버 숫자(수요 가늠)보다 이 실측이 앞선다. 색인 안 된 글이 오래 남으면(구글이 "발견됨 - 현재 색인이 생성되지 않음") 주제를 늘리기보다 글 품질·내부 링크를 먼저 본다. 구글 트렌드는 공식 API가 신청제 시험판이라 붙이지 않고, 계절 흐름이 필요할 때만 자동화 크롬으로 웹 화면을 몇 번 본다. 구글 키워드 플래너는 광고 계정·개발자 승인이 필요해 쓰지 않는다(11/27 결정).
   - 숫자를 읽는 법: 몇 회 이상이어야 한다는 고정 기준은 두지 않는다(근거 없음). 같은 갈래 후보끼리 견줘 많이 찾는 주제를 앞에 두고, 아주 적은 주제(10회 미만이 섞인 것)는 더 나은 표현이 없으면 보충 때 바꿀 후보로 본다. `compIdx`(경쟁)는 **광고 입찰 경쟁**이라 검색 노출 난이도로 쓰지 않는다. 우리 유입은 구글이 크므로 네이버 숫자는 '수요가 있는지'만 가늠한다. 관련 검색어 목록에는 상관없는 낱말도 섞여 나오니 같은 뜻만 골라 본다.
3. **다루지 않는 위험 주제 제외**
   - 감전·화재·가스·분해 수리·비공식 개조 등 위험 단계만 남은 주제는 뺀다.
   - 안전하게 확인 가능한 자가 점검·설정·소모품/호환 부품 교체 안내 위주로 구성한다.
   - 옛 글 문장이나 표현은 그대로 가져오지 않는다.
4. **`data/blog/tech-queue.json` 추가**
   - `fix`(문제 해결 순서)와 `before-buy`(사기 전 호환·규격 확인) 유형(`kind`)을 섞고, `topicId`가 겹치지 않게 넣는다.
   - 모든 항목에 `sourceHints`(공식 지원/제조사 문서 경로 등 1개 이상)를 채운 뒤 저장한다.
   - `targetKeyword`를 적고 `node scripts/blog/keyword-volume.mjs queue`로 `searchVolume`(PC·휴대폰·조회 날짜)을 기록한다. 안 잰 주제가 있으면 브리핑 블로그 줄에 `검색량 미확인 N개`가 뜬다.

## 5. 블로그 정책·규칙 및 공통 안전선 (2026-11-26 사용자 확정)

상세 근거: `knowledge/decisions/2026-11-26-blog-policy-rules-loop-draft.md`.

1. **유튜브와 분리 및 공통 안전선**:
   - 블로그 고유 규칙(공정위 추천보증 심사지침 대가 문구, 쿠팡 금지행위 11가지 준수, 검색엔진 스팸 방지, 무인 일정 자동화)은 이 문서와 블로그 글쓰기 지침(`scripts/blog/prompts/tech-post.md`)을 원본으로 한다.
   - 유튜브와 공통 안전선(동일 애드센스 계정 보호, 경험 날조 금지, 성과 숫자 실제 데이터 원칙, AI 티 검사 필수, 저작권 준수)은 철저히 함께 지킨다.
2. **글 게시 전 팩트체크 (프로그램 1:1 대조 검사)**:
   - 사람의 수동 검토 피로를 방지하기 위해 사람이 검토하는 대신, 프로그램이 공식 출처 웹페이지 본문을 읽어와 인용문과 1:1 글자 단위로 대조한다(따옴표 정규화 포함).
   - 인용문 대조가 통과된 글만 자동으로 게시된다.
3. **성과 없는 글 수정 허용 (결과 루프)**:
   - 발행 후 4주 동안 검색 노출/유입이 0인 글은 검색 유입 개선을 위해 AI가 제목 및 도입부를 자동으로 보완·수정할 수 있다.
4. **쿠팡 파트너스 공식 서면 회신 보관 및 상품 이미지 미사용 확정 (2026-11-26, 파트너스 ID `AF4472063`)**:
   - 문의(2026-11-25 23:58): 오픈 API `productImage`·상세페이지·상품평 이미지 사용 허용 범위 서면 확인 요청.
   - 쿠팡 파트너스 공식 회신(2026-11-26):
     - 쿠팡 입점 공급사·판매자별 저작권 방침이 달라, 허용되지 않은 곳에 콘텐츠가 게재될 경우 **일부 공급사·판매자가 상표권 등 지식재산권 침해로 법적 조치**를 취할 수 있음.
     - 쿠팡 **상품평 등 게시물 무단 사용의 법적 책임은 파트너스 회원**에게 있으므로 무단 사용 금지.
     - 파트너스 활동은 제공되는 콘텐츠(배너 등) 위주로 안내하며, 상세페이지·제품 이미지 컷도 개별 판매자나 쿠팡으로부터 **블라인드 요청**이 발생할 수 있음.
   - 운영 기준 확정: 쿠팡 상품평·상세페이지·제품 이미지는 블로그 본문에 쓰지 않고, **자체 제작 대표 그림 1장(문제 순간만, 브랜드·로고·인물 추천 연출 없음) + 글자 링크** 원칙을 유지한다.
5. **애드센스 광고 배치 (2026-11-27, 사용자가 전략을 AI에 맡김)**:
   - 승인은 루트 도메인 `d40m.com`으로 받았다. 애드센스는 사이트로 루트 도메인만 받는다(공식 도움말 `support.google.com/adsense/answer/12169212`). `tech.d40m.com` 글 페이지에는 같은 게시자 코드(`ca-pub-7817…`)의 자동 광고가 이미 실린다(11/27 실측: 자동 광고 자리 1~2개, 한 번은 광고가 채워짐, `ads.txt` 있음).
   - 지금은 **자동 광고만** 쓴다. 블로거 레이아웃 '광고' 칸의 애드센스 가젯 2개는 숨김 그대로 둔다. 이유: 글 2편·방문 거의 없는 단계라 광고 수익보다 읽기 흐름과 쿠팡 링크가 먼저이고, 수동 광고를 더하면 자동 광고와 겹쳐 본문을 자른다.
   - 자동 광고 설정(광고 양·앵커·전면 광고)은 사이트로 등록된 `d40m.com` 전체에 걸리는 계정 설정이라 이 블로그 사정만으로 바꾸지 않는다.
   - 12/24 4주 점검에서 애드센스 수익·페이지 RPM을 서치 콘솔·쿠팡 수치와 같이 보고, 수동 광고(본문 중간 1개 등) 시험 여부를 정한다.
