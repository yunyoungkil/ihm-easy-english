# 영상 예약·공개 사후 마무리 (7단계 자동 체인)

> **권장 모델**: **경량 모델** (`Gemini 3.8 Flash` / `Claude sonnet-worker`·`haiku`). 렌더·업로드 승인 관문은 이 스킬에 포함되지 않으며, 이미 예약·공개가 끝난 뒤 후속 기록과 확인만 묻지 않고 끝까지 수행한다.

## 7단계 순서

1. **유튜브 실제 상태 · 필수 설정 확인**
   - `data/youtube/catalog.json`의 `privacyStatus`·`scheduledPublishAt`(동기화가 오래됐으면 대시보드 `/api/sync`) 또는 API로 실제 예약·공개 상태를 직접 확인한다.
   - **AI 사용 표시**(`containsSyntheticMedia: true`, 변형되었거나 생성된 콘텐츠 = 예) 확인.
   - **재생목록 연결** 확인:
     - 쇼츠: `이해하면 쉬운 영어 | 영어 읽는 법 테스트 시즌1 (30초 퀴즈)` (`PLCbnHG8SDRes`)
     - 롱폼: `이해하면 쉬운 영어 | 영어 읽는 법 기초 시즌1 (왕초보 영어 읽기)` (`PLdTWj5v6v8zE`)
   - **롱폼 제목+썸네일 A/B 테스트 확인 (2026-11-28 사용자 확정)**: 롱폼은 예약 직후 스튜디오 `A/B 테스팅` → `제목과 썸네일` 3쌍(`1안+A`, `2안+B`, `3안+C`) 저장 여부를, 공개 직후에는 '실행 중' 전환 여부를 확인한다(쇼츠 제외).
2. **패키지 상태 파일 일치 (손으로 고치지 않는다)**
   - 상태 파일(롱폼 `status.json`, 쇼츠는 대시보드만 읽는 `shorts-status.json`)은 **대시보드 동기화가 유튜브 값으로 맞춘다**(`/api/sync`, 코드 `scripts/package-status-sync.mjs`). 에이전트가 파일을 직접 고치지 않는다 — 필드 이름을 틀리게 써서 동기화가 조용히 멈춘 사고가 있었다(`knowledge/production-rules.md` "4번째 원인").
   - **쇼츠 패키지 폴더에는 `status.json`을 만들지 않는다**(자동 예약 업로드가 읽는 파일이라 롱폼 대기열에 끼어든다, `knowledge/production-rules.md` "쇼츠도 같은 두 곳에 남긴다").
   - 동기화 뒤에도 안 맞으면 고치지 말고 원인(제목이 후보 목록에 없어 영상을 못 찾는 경우 등)을 보고한다. 손으로 `videoId`를 적어야 하는 유일한 경우와 그 형식은 위 "4번째 원인" 절에 있으니 그대로 따른다.
3. **공개 직후 4대 사후 관리 (공개된 영상일 때)**
   - 고정 댓글 게시·상단 고정, 롱폼 마지막 7~10초 끝 화면(구독 + 다음 추천 영상), 짝 쇼츠 관련 동영상 연결, 한국어 수동 자막 게시 여부를 확인한다.
4. **월별 작업 기록**
   - `knowledge/logs/YYYY-MM.md` 오늘 날짜 절에 영상 ID, 예약/공개 시각, 핵심 설정과 확인 결과를 숫자로 남긴다.
5. **다음 할 일 갱신 (`knowledge/now.md`)**
   - 끝난 제작·예약 항목을 지우고, **공개 7일 뒤 성과 정산 날짜 항목**과 공개 직후 사후 관리 날짜 항목을 추가한다.
6. **실험표 · 인수인계 갱신**
   - 시험 편이면 `knowledge/style-experiments.md` 표에 기록한다.
   - `knowledge/handoff/<오늘 날짜>.md`와 `knowledge/handoff/LATEST.md`를 갱신한다.
7. **커밋 · 푸시 · PC 동기화**
   - 내가 바꾼 파일만 이름으로 담아 커밋·푸시하고, `npm run pc-sync`로 다른 PC에 자료를 올린다.
   - 못 끝낸 항목과 남은 미커밋 파일이 있으면 1줄로 보고한다.
