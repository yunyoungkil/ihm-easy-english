## 씬 데이터 (scripts/ep06.json)

각 씬: `id`, `title`(편집용), `duration`(초, 폴백값), `layout`, `words`, `content`, `caption`, `narration`.

`layout`은 5종: `quiz` | `wordList` | `ruleBox` | `compare` | `summary`.

`Word` 필드:

| 필드 | 용도 |
|---|---|
| `word` | 영어 원문 (화면 표시) |
| `stress` | 강세 음절 — 노란색 (quiz / wordList) |
| `pronunciation` | 한글 발음 |
| `meaning` | 한글 뜻 |
| `sound` | compare 하단 발음 라벨 (션/천/전) |
| `highlightPart` | **compare 전용** — 비교 대상 부분, 노란색 |
| `causeChar` | **compare 전용** — 차이를 만드는 원인 글자, 빨간색 |
| `narrationCue` | 화면에 안 나옴. 나레이션이 쓰는 한글 표기 (타임스탬프 매칭용) |
| `highlightAt` / `highlightEnd` | 스크립트가 자동 생성. 나레이션이 이 단어를 **말하기 시작/끝내는** 씬 기준 프레임 |

- 씬 길이는 **음성 파일 실제 길이 + 0.5초**로 자동 계산된다 (JSON `duration`보다 우선).
- `content`의 편집용 메모("채널 인트로," 등)는 `utils/contentFilter.ts`가 렌더링 시 걸러낸다.

## compare 레이아웃 규칙

**두 모드**가 있고 `sound` 필드 유무로 갈린다.

- **강세 이동 모드** (`sound` 없음, 예: EDUCATE → EDUCATION): 좌우 쌍 + 그려지는 화살표
- **발음 대조 모드** (`sound` 있음, 예: NATION vs QUESTION): 좌우 대조 + `vs`

지켜야 할 것:

1. **중앙 세로 구분선 없음.** `vs` 텍스트만으로 좌우를 나눈다.
2. **`vs` 수직 정렬**: 영어 단어와 정확히 같은 수직 중심선에 놓는다.
   단어 컬럼은 아래 발음 라벨 때문에 단어 자체보다 키가 크므로, 행을 `alignItems: flex-start`로 두고
   `vs` 박스에 단어와 **같은 높이**(`fontSize * SPACING.compareWordLineHeight`)를 줘서 중심을 맞춘다.
   → `CompareWord`의 단어 span에 `lineHeight`가 명시돼 있는 이유. 이 값을 바꾸면 `vs`도 같이 어긋난다.
3. **`vs` 스타일**: 회색(`COLORS.muted`), 단어 크기의 35%(`FONT_SIZES.compareVsRatio`).
4. **좌우 균형**: 양쪽 컬럼 `flex: 1`, 가운데는 고정폭 거터(`SPACING.compareVsGutterPct`).
   → `vs`가 화면 가로 정중앙에 온다. 거터 폭이 단어와의 좌우 여백 역할도 한다.

색상 규칙: `highlightPart`는 노란색, `causeChar`는 빨간색(원인 글자가 없는 쪽은 노란색만).
하단 발음 라벨은 `causeChar`가 있으면 빨간색, 없으면 노란색.

## motionStyle — 애니메이션 두 버전

`src/theme.ts`의 `MOTION_STYLES`에 정의. Composition prop으로 선택하고
`MotionStyleProvider`가 Context로 내려보내며, `utils/animation.ts`의 훅들이 읽는다.
씬 컴포넌트는 motionStyle을 몰라도 된다.

| | `calm` | `dynamic` |
|---|---|---|
| 등장 | 아래→위 20px 슬라이드 + fade | 좌우 교차 60px 슬라이드 + fade |
| spring damping | 20 (오버슈트 없음) | 13 (약한 오버슈트) |
| 요소 간격 | 0.3초 | 0.35초 |
| 등장 후 | **완전 정지** | **화면 내 순회 이동** (아래 참고) |
| 강세 pulse | 1회 scale 1→1.08→1 (0.4초) | 1회 scale 1→1.12→1 후 밝기 변동 (opacity 0.9↔1, 3초 주기) |

damping 20은 Remotion spring 기본값(mass 1 / stiffness 100)의 임계 감쇠값이라 오버슈트가 없다.
그래서 `spring()`에 `durationInFrames`를 넘기지 않는다 — 넘기면 damping이 의도대로 안 읽힌다.

Composition은 `EP06-calm` / `EP06-dynamic` 두 개가 등록돼 있고 JSON·음성은 동일하다.

### dynamic의 순회 이동 (travel)

`TRAVEL_WAYPOINTS`(4개 좌표 루프)를 `interpolate`로 순환한다. 구간마다 in/out easing이라
각 좌표에서 속도가 0에 가까워져 급격한 방향 전환이 없다. 주기 7초, 요소마다 위상 +1.6초씩 밀어
이웃끼리 같은 방향으로 동시에 쏠리지 않게 한다. 등장 구간 동안 0→1로 램프되므로
요소는 항상 원래 레이아웃 위치에 정확히 도착한 뒤 움직이기 시작한다.

이동 폭은 `TRAVEL_RANGES`의 레이아웃별 프로필로 정한다. **한도(15~20%)보다 실제 여백이 더 빡빡한
제약**이라 값이 작다 — 화면 밖으로 나가거나 이웃과 겹치면 안 되기 때문이다:

| 프로필 | 쓰는 곳 | 이유 |
|---|---|---|
| `default` | quiz 단어 | 가로 여유는 크지만 단어/화살표 스택의 세로 간격이 38px뿐 |
| `compare` | 발음 대조 모드의 단어 하나 | `vs` 거터까지의 거리가 가로 이동을 제한 |
| `compareRow` | 강세 이동 모드의 **행 전체** | 행을 통째로 움직여 좌우 단어가 화살표를 침범할 수 없게 함 |
| `list` | wordList 행 | 3개 이상 세로 배치, 행 간격 54px |

**회전은 프로필마다 다르다.** 회전이 잡아먹는 세로 공간은 요소 **너비에 비례**하기 때문이다 —
전체 폭 행에 3°를 주면 양 끝이 ±42px 흔들려 위 행과의 간격이 사라진다. 그래서 넓은 행은 0.5°다.

검증 기준: 이웃도 같이 움직이면 `2 × (세로이동 + 회전으로 인한 끝단 변위) < 간격`,
이웃이 고정이면 `1 ×`. 값을 바꾸면 이 식으로 다시 확인할 것.

`calm`은 `travelEnabled: false`라 이동·회전이 전혀 없다.

## dynamic 버전 전용 시그니처 모션

**`calm`에는 아무것도 적용되지 않는다.** 전부 `MOTION_STYLES.dynamic.signatureEnabled`로 잠겨 있고,
`SceneRenderer`가 이 값이 false면 세 컴포넌트를 아예 렌더링하지 않는다(스틸로 검증 완료).

`public/reference/anthropic_intro.gif`에서 **색상·폰트·로고 디자인은 배제하고 움직임 기법만** 가져왔다.
(레퍼런스는 Anthropic 단독 인트로가 아니라 Anthropic/IBM Carbon/Spotify 등을 다루는 7분짜리
한국어 디자인 시스템 소개 영상이었다. 실사 발표 구간과 모션 그래픽 카드 구간이 섞여 있다.)

추출한 기법 → 우리 채널식 재해석:

| 레퍼런스 기법 | 우리 적용 |
|---|---|
| 매 세그먼트를 중앙 발광 마크로 열기 | **전구 브릿지** |
| 코너에 섹션 표식 상주 | **우상단 상태 배지** |
| 배경에 옅은 대형 그래픽 | **Scene별 워터마크** |
| 자막 키워드를 발화 시점에 색으로 바꿈 | 이미 구현된 `highlightAt` 강조 (재확인) |
| 하드컷 없이 아주 느린 크로스페이드 | 기존 0.35초 씬 전환 유지 |

수치로도 확인했다: 2fps로 860프레임을 떠서 인접 프레임 차분을 계산하니 중앙값이 0.68로,
실사 구간 진입/이탈(135, 132)을 빼면 피크가 5~10에 불과했다. **즉 급격한 전환이 없는 영상**이라
브릿지도 0.4초로 짧게, 나머지는 완만하게 잡았다.

### 1) 전구 브릿지 (`SceneBridge`)

각 씬 시작 0.4초 동안 화면 중앙에서 전구가 켜졌다 사라지며 다음 화면으로 넘긴다.

- 0.3초에 걸쳐 opacity 0→1 + glow(`drop-shadow`) 0→64px 확산
- spring damping 9(임계값 20보다 낮음) → **한 번 살짝 흔들리고 안정화**
- 이후 남은 구간에 페이드 아웃
- `SceneFrame` **바깥**에 렌더링한다. 안에 넣으면 씬 자체의 0.35초 페이드에 눌려 흐려진다.

### 2) 상태 배지 (`StatusBadge`)

우상단에 `색상 원 + 한글 라벨`. 시청자가 지금 구간의 성격을 색으로 즉시 인지하게 한다.

### 3) Scene 워터마크 (`SceneWatermark`)

배경 중앙에 레이아웃별 도형을 opacity 4%로 깔았다. 콘텐츠가 아니라 질감으로만 읽혀야 하므로
`SIGNATURE.watermarkOpacity`를 올릴 때는 본문 대비를 반드시 다시 확인할 것.

### 색상·라벨·도형 매핑 (`utils/sceneKind.ts`)

기존 팔레트 의미를 그대로 따랐다 — 초록은 이미 예시 박스, 파랑은 이미 포인트/정리 박스 색이라
배지 색이 그 아래 콘텐츠와 어긋나지 않는다.

| layout | 색 | 라벨 | 워터마크 |
|---|---|---|---|
| `quiz` | 노랑 `#F5C518` | 퀴즈 | 물음표 |
| `wordList` | 초록 `#7DC242` | 예시 | 책 |
| `ruleBox` | 파랑 `#5B9BD5` | 규칙 | 전구 |
| `compare` | 노랑 `#F5C518` | 비교 | 화살표 |
| `summary` | 파랑 `#5B9BD5` | 정리 | 체크마크 |

새 레이아웃을 추가하면 `SCENE_KINDS`에도 항목을 넣어야 한다.

## cardStyle 레이아웃 규칙 (`card` 버전)

스토리보드(EP6 최종본)를 그대로 옮긴 스타일. `MOTION_STYLES.card.cardLayout: true`로 갈리며
`CardScene`이 전부 그린다 — calm/dynamic/reference와 렌더링 경로를 전혀 공유하지 않는다.

### 3단 구조 (고정 비율)

| 구역 | 비율 | 내용 |
|---|---|---|
| 상단 | **8%** | 좌: 에피소드 제목 + category 배지 / 우: 11개 진행 점 |
| 중앙 | **63%** | 카드 (좌상단 배지, 우상단 타임코드, 본문) |
| 하단 | **20%** | **그래픽 금지.** 자막(상단 쪽) + 화면 최하단 진행 점 |

- 남는 ~9%가 카드와 자막 사이 간격이다. 여기에 `CARD.safeAreaPx`(48px)를 더해
  **카드 하단과 자막 사이 최소 여백을 보장**한다. 카드 콘텐츠 높이에 의존하지 않는다.
- **자막은 화면 최하단이 아니라 카드 바로 아래**(하단 구역의 위쪽)에 붙는다.
  최하단은 진행 점 자리다.

### 상단 메타 정보는 영상에 표시하지 않는다

스토리보드의 `01 Scene 1`, `category: quiz`, `0:00~0:40` 라벨 중
**번호와 `category:` 캡션은 제작 참고용**이라 렌더링하지 않는다.
화면에 나가는 건 **배지**(`card.badge`)와 **카드 우상단 타임코드**뿐이다.

타임코드는 스토리보드의 계획값이 아니라 **실제 음성 길이 기준 누적 시각**으로 계산한다
(그래서 스토리보드의 0:00~0:40과 값이 다르다 — 실제 영상 길이가 410초라 더 짧다).

### 강세/발음은 색상만, 텍스트 라벨 금지

`(강세)`, `(강세: 케이)`, `(발음: 션)` 같은 라벨은 **쓰지 않는다.**

| 대상 | 색 |
|---|---|
| 강세 음절 | 노랑 `#F5C518` |
| 일반 음절 | 흰색 |
| 예외 발음(천/전) | 빨강 `#E84545` |

`CardWord`의 `stressIndex` / `pronStressIndex` / `pronDiffIndex`가 어느 셀에 색을 줄지 정한다.
음절 분해는 영어(`syllables`)와 한글(`pronCells`)을 **각각 독립 배열**로 둔다 —
INFORMATION처럼 영어 4음절 / 한글 5음절로 개수가 다른 경우가 있어서 1:1 정렬을 강제하지 않는다.

### 카드 넘침 방지

카드는 고정 높이라 내용이 많은 씬(예: Scene 6의 3쌍)은 그대로 두면 잘린다.
`estimateBodyHeight()`로 본문 높이를 추정해 **폰트·여백 크기 자체를 축소**한다.
CSS `transform: scale()`은 레이아웃 박스 크기를 안 줄여서 여전히 넘치므로 쓰지 않는다.

새 카드 유형을 추가하면 `estimateBodyHeight()`에도 항목을 넣어야 한다.

### 자막 — `subtitleGroups` (문장 단위, 빈 구간 없음)

화면에 띄우는 건 `scene.subtitleGroups` 하나뿐이다.

#### ⚠️ whisper를 **두 번** 돌리는 이유 (건드리지 말 것)

`transcribeScene()`은 같은 오디오를 두 번 전사한다.

| 패스 | 옵션 | 용도 |
|---|---|---|
| 토큰 | `tokenLevelTimestamps: true` | `highlightAt` (정밀 타이밍) |
| 세그먼트 | `tokenLevelTimestamps: false, tokensPerItem: 0` | **자막 텍스트** |

토큰 패스(`--max-len 1`)는 whisper.cpp가 **한글 한 글자(UTF-8 3바이트)를 토큰 경계로 쪼개서**
각 토큰이 깨진 UTF-8이 된다. 디코딩하면 U+FFFD가 되고, 그 글자는 복구가 불가능하다:

```
실제 나레이션 : 영어 발음과 강세를 원리로 배우는
토큰 패스     : 영어 발음과 강세??? 원?????? 배우는   ← 깨짐
세그먼트 패스 : 영어 발음과 강세를 원리로 배우는      ← 정상
```

예전에는 이 깨진 글자를 `.replace(/�/g, "")`로 지웠는데, 그러면 **글자가 통째로 사라진 자막**이
나왔다("폼에 있던 힘이 매로 이동했습니다" → "에 던 힘이 매 이했습니다").
지금은 세그먼트 패스의 온전한 문장을 쓴다.

`tokensPerItem: 0`이 핵심이다. 생략하면 라이브러리가 기본값 1을 넣어 `--max-len 1`이 되고,
`tokenLevelTimestamps: false`여도 다시 토큰 단위로 쪼개져 똑같이 깨진다.

세그먼트는 4~7초로 길어서 글자 위치에 비례해 시간을 나눠 준 뒤 아래 규칙으로 다시 자른다.

#### 그룹핑은 `@remotion/captions`의 `createTikTokStyleCaptions()`가 한다

직접 짠 절-분리 로직을 걷어내고 공식 함수로 교체했다. `buildSubtitleGroups()`가 하는 일:

1. 세그먼트를 **글자 타임라인**으로 펼침 (`segmentsToChars`)
2. 글자 → **어절 단위 `Caption[]`** 변환 (`charsToCaptions`)
3. `.`/`?`/`!` 기준으로 **문장별로 나눠** 각 문장에 `createTikTokStyleCaptions()`를 따로 호출
4. 나온 `pages`를 프레임 단위 `{text, from, to}`로 변환
5. **빈 구간 제거**: 각 그룹의 `to`를 다음 그룹의 `from`으로 늘리고, 첫 그룹은 0에서 시작,
   마지막 그룹은 씬 끝까지 유지 → 자막이 비는 프레임이 없다

2번이 필요한 이유: `createTikTokStyleCaptions()`는 **텍스트가 공백으로 시작하는 caption**에서만
페이지를 끊는다(whisper 영어 토큰이 그렇게 들어오기 때문). 그래서 한글도 같은 규약으로,
어절을 가르던 공백을 **뒤 어절 앞에 붙여서** 넘긴다.

3번이 필요한 이유: 이 함수는 문장 개념이 없고 **누적 시간이
`SWITCH_CAPTIONS_EVERY_MS`(3500ms)를 넘으면 다음 어절 경계에서** 끊을 뿐이다.
마침표를 걸쳐 한 페이지가 되면 읽기 나쁘므로 문장으로 먼저 자르고,
**한 문장이 길 때 몇 페이지로 쪼갤지**를 공식 함수에 맡긴다.

`SWITCH_CAPTIONS_EVERY_MS`는 실측으로 골랐다 (EP6 전체 기준):

| 값 | 페이지 수 | 1초 미만 깜빡임 | 글자수 중앙값 / 최대 |
|---|---|---|---|
| 2500 | 161 | 5 | 15 / 25 |
| **3500** | **133** | **1** | **18 / 33** |
| 4500 | 118 | 2 | 21 / 36 |

33자도 자막 영역에서 한 줄에 들어간다(스틸로 확인). 값을 바꾸면 이 표를 다시 뽑을 것.

5번은 여전히 우리 몫이다. 공식 함수의 `durationMs`는 **한 번의 호출 안에서만** 빈틈이 없는데,
문장마다 따로 호출하므로 문장 사이 쉼에는 구멍이 남기 때문이다.

#### 문장 시작 큐는 실제 발화 onset에 스냅한다 (`CUE_SNAP_WINDOW_MS`)

**문장을 여는 페이지는 쉼 뒤에 발화되므로 시작 시각을 오디오에서 직접 알 수 있다.**
whisper 추정치 대신 측정된 onset(250ms 이상 무음 뒤)으로 당긴다.
문장 중간에서 시작하는 페이지는 붙일 쉼이 없으므로 건드리지 않는다.

창 크기 500ms는 **양쪽에서 측정으로 묶인 값**이다:

- 보정 후 남은 whisper 오차의 p90 = **220ms** → 이보다 넓어야 실제 오차를 덮는다
- 인접 구절 onset 사이 **최소 간격 = 560ms** → 이보다 좁아야 옆 구절로 안 붙는다

넓히면 안 된다. 1200ms까지 늘려도 검증 지표는 안 나빠 보이지만, 그건 지표에 변별력이
없어서일 뿐이고 실제로는 600ms 어긋난 큐가 560ms 떨어진 **엉뚱한 구절**로 붙을 수 있다.

창 밖(500ms 초과)으로 어긋난 큐는 **일부러 그대로 둔다** — 그만큼 옮기는 건 근거 없는 추측이다.
EP6 기준 4곳이 남아 있고, whisper가 그 구간의 구절 경계를 크게 잘못 잡은 경우다.

#### 전사 결과는 `.whisper-scratch/sceneN_small.json`에 캐시된다

11개 씬 전사에 몇 분씩 걸려서 그룹핑 파라미터를 못 만진다. 원본 whisper 출력을 캐시해 두므로
재실행은 몇 초다. **음성을 다시 녹음했으면 `.whisper-scratch/`를 지워야** 새로 전사한다.

#### 원고(`scene.narration`)가 있으면 그게 우선

`scripts/ep06.json`의 각 씬 `narration`에 실제 원고를 넣으면 **자막 텍스트는 원고 그대로** 나가고,
whisper는 타이밍만 제공한다. 비어 있으면 whisper 전사문으로 폴백한다.
**EP6은 11개 씬 모두 원고가 채워져 있다** — "테턴이"/"강쇠"/"아픔절" 같은 오인식 14곳이 전부 사라졌다.

원고를 채워도 **타이밍 자체는 좋아지지 않는다.** 원고는 텍스트만 바꾸고 시계는 여전히
whisper 것이기 때문이다. 오히려 원고에는 문장 부호가 제대로 있어 짧은 문장이 늘고,
그만큼 문장 시작 큐가 늘어 꼬리가 나빠진다(EP6 기준 >300ms가 5/85 → 11/109로 증가했다).
이 부분을 실제로 잡아 주는 건 바로 위의 **onset 스냅**이다.

정렬은 `alignNarrationToTimeline()`이 한다:

- 원고 글자열과 whisper 글자열을 **LCS로 정렬** (공백은 무시하고 매칭)
- 일치한 글자는 whisper의 실제 타임스탬프를 그대로 가져감 (앵커)
- 못 맞춘 구간은 앞뒤 앵커 사이를 글자 수 비례로 보간

즉 whisper가 제대로 알아들은 대부분의 글자가 앵커가 되므로, 오인식 구간이 있어도
타이밍이 밀리지 않는다.

**주의**: 어절을 나눌 때 공백을 버리면 안 된다. 페이지를 이어 붙일 때 단어가 붙어버리고
(`"붙이면 어떻게"` → `"붙이면어떻게"`), 공식 함수의 페이지 분리 신호 자체가 사라진다.
`charsToCaptions()`가 공백을 뒤 어절 앞에 남기는 이유다.

### highlightAt 기반 단어 강조

카드 단어(`CardWord`)에는 시간 정보가 없고, whisper 타임스탬프는 `scene.words`에 있다.
`CardScene`이 **영어 철자로 두 배열을 매칭**해서 연결한다.

- 나레이션이 그 단어를 말하는 구간: scale 1→1.15(spring 0.15초), 제목·일반 음절이 노란색으로 전환
- 강세 음절은 원래 노란색이라 그대로, `causeChar` 빨간색도 의미가 있어 그대로
- 같은 카드의 **다른** 단어는 `CARD.dimOpacity`(0.6)로 낮춰 시선 유도
- `highlightAt`이 없는 단어는 아무 효과 없이 카드 등장 애니메이션만 (폴백)

### 엔드스크린 Scene 규칙 (필수)

**모든 에피소드의 마지막 씬은 `category: "endscreen"`이어야 한다.** 8초, 나레이션 없음.
`CardScene`이 `category === "endscreen"`을 보고 카드 대신 `EndScreen`을 그린다 —
카드도 배지도 타임코드도 진행 점도 없다.

#### ⚠️ 유튜브 카드 영역에는 아무것도 그리지 않는다

유튜브는 영상 마지막 구간에 **자기 엔드스크린 요소를 덮어씌운다.** 그 아래에 그린 건
그냥 가려지므로, 두 사각형은 사용 불가로 두고 그 바깥에 배치한다 (1920x1080 기준):

| 영역 | 좌표 | 크기 |
|---|---|---|
| 우측 하단 | x 1620~1920, y 910~1080 | 300x170 |
| 중앙 상단 | x 810~1110, y 0~170 | 300x170 |

그래서 콘텐츠가 전부 **좌측**에 있다. 가운데 정렬하면 상단 카드에 물린다.
`ENDSCREEN.zoneW/zoneH/zoneMargin`이 값의 단일 출처이고,
가용 폭은 `width - zoneW - zoneMargin*2`로 계산해 우측 카드를 피한다.

검증은 눈대중이 아니라 **픽셀로** 한다. 스틸을 떠서 두 사각형의 최대 휘도를 재면
배경만 있을 때 14.7이 나온다(대조군인 좌측 중앙은 255). 요소를 추가하면 다시 잴 것.

#### 전환은 항상 크로스페이드 (shape-wipe 예외)

엔드스크린은 앞 씬(teaser)과 category가 다르므로 원래대로면 shape-wipe 대상이지만,
**영상이 끝나는 참에 새 섹션을 여는 연출은 어긋난다.** `isCategoryChange()`가
`endscreen`을 명시적으로 제외해 0.3초 크로스페이드만 걸린다.

#### 무음 씬은 0.5초 버퍼를 받지 않는다

`END_BUFFER_SEC`는 나레이션 뒤 여백이라 나레이션이 없으면 의미가 없다.
그래서 음성 파일이 없는 씬은 JSON의 `duration`이 곧 화면 길이다(엔드스크린 = 정확히 240프레임).

**전체 길이는 8초가 아니라 7.7초 늘어난다** — 크로스페이드 0.3초만큼 앞 씬과 겹치기 때문이다
(EP6/7/8 모두 +231프레임으로 확인).

### category 비교 기반 Scene 전환

`TransitionSeries`를 쓰고, **앞뒤 씬의 `card.category`가 다를 때만** shape-wipe다.
같으면 0.3초 크로스페이드. EP6 기준 1→2, 2→3, 5→6, 7→8, 8→9, 9→10, 10→11이 shape-wipe.

shape-wipe(`components/shapeWipe.tsx`)는 **다음 씬 카테고리의 도형을 CSS mask로** 써서
중앙에서 확대하며 다음 화면을 연다. 0.6초, spring damping 110.

주의점 두 가지:
- 마스크 data URI는 **base64**여야 한다. `;utf8,`+퍼센트 인코딩은 Chrome이 조용히 무시해서
  마스크가 통째로 안 먹고 전체 화면이 색으로 덮인다.
- 도형 크기는 `800 * p³`. 선형으로 하면 감쇠가 큰 spring 때문에 1~2프레임 만에
  화면을 넘어가 도형이 안 보인다.
- 마스크용 도형은 `SHAPE_PATHS`의 **채워진 패스**다. 다른 곳에서 쓰는 선(stroke) 아이콘을
  마스크로 쓰면 가는 윤곽선만 뚫려서 화면이 안 열린다.

`TransitionSeries`는 앞뒤 시퀀스를 겹치므로 **전체 길이가 전환 시간만큼 짧아진다.**
`calculateMetadata`에서 `totalTransitionFrames()`를 빼줘야 끝에 빈 프레임이 안 생긴다
(card 스타일만 12305 → 12152프레임).

### 진행 표시 점은 상단 1곳만

우상단(에피소드 제목과 같은 줄)에만 있다. 하단 진행 점은 삭제했고,
**하단 구역은 자막 전용**이다.

### 원본과 다르게 간 부분 (의도적)

- **마크는 우리 글리프를 쓴다.** 레퍼런스의 마크는 Anthropic 로고 + `ANTHROPIC · CLAUDE`
  워드마크라 그대로 복제하지 않았다. 대신 씬 종류별 아이콘(물음표/책/전구/화살표/체크)을
  레퍼런스 오렌지로 렌더한다. 아이콘은 `ReferenceContent.icon`으로 교체 가능하다.
- **헤드라인은 위쪽 기준으로 앵커**돼 있다. 우리 문장이 레퍼런스보다 훨씬 길어서,
  가운데 정렬하면 2줄째가 위로 자라 마크를 덮는다. 한 줄일 때는 측정된 중심에 정확히 오고,
  줄이 늘면 아래 빈 공간으로 자란다. 추가로 `fitFontSize`가 밴드에 맞게 폰트를 줄인다.

### 콘텐츠 매핑 (`utils/referenceMapping.ts`)

레이아웃 구분 없이 전부 `마크 + 라벨 + 헤드라인 + 캡션` 한 구조로 통일한다.

- 단어가 있는 씬(quiz/wordList/compare): 헤드라인이 **나레이션 순서대로 단어를 넘어간다**
  (`getActiveWordIndex` — `highlightAt`이 지난 마지막 단어).
- 산문 씬(ruleBox/summary): `content`가 헤드라인으로 들어간다.
- 캡션은 `scene.caption`, 라벨은 씬 종류(`sceneKind`).

### 나레이션 동기화

`useSpeechEmphasis`를 그대로 재사용한다 — 헤드라인이 발화 구간 동안 오렌지로 물들고
1.15배 커졌다가 돌아온다. `highlightAt`이 없으면 첫 단어에서 멈춰 있고 강조는 일어나지 않는다.


**목소리는 `scripts/tts-config.mjs`의 `VOICE` 하나뿐이고 `Object.freeze` 돼 있다.**
에피소드마다 같은 나레이터로 들려야 하므로, 덮어쓰려는 코드는 조용히 다른 목소리로
나가는 대신 크래시한다. Charon / empathetic / natural / ko-KR / gemini-3.1-flash-tts-preview.

style·pace는 API 파라미터가 없다. **텍스트 앞에 자연어 지시를 붙여서** 유도하며
(`styleDirective()`), 그 문장을 config에 둔 것이 에피소드 간 톤 재현의 근거다.

출력은 **24kHz / 모노 / 16-bit PCM**으로 EP6 녹음과 동일하다. 이 포맷이 깨지면
whisper 리샘플링과 씬 길이 계산이 조용히 어긋나므로, 응답의 `rate=`가 다르면 **에러를 낸다.**
(EP6 파일은 헤더의 `byteRate`가 96000으로 틀려 있다. 정답은 48000이고 우리 파일은 올바르다.
프로젝트의 모든 리더가 `dataSize/blockAlign/sampleRate`로 길이를 구하므로 무해하다.)

### ⚠️ TTS 나레이션 작성 규칙 (`scripts/narration-lint.mjs`)

**narration에 접미사만 단독으로 쓰면 안 된다.** `"TION 강세의 비밀"`을 그대로 보냈더니
"비밀"이 **"빌밀"로 뭉개져** 돌아왔다. TION은 단어가 아니라서 모델이 글자처럼 읽으려다
뒤 단어까지 오염시킨다.

`generate-tts.mjs`가 **호출 전에** 모든 narration을 검사하고, 걸리면 **멈춘다.**
돈이 나가기 전에 잡는 게 요점이다 — 생성 후에 발견하면 유료 호출을 다시 써야 한다.

| 패턴 | 처리 |
|---|---|
| `TION` 단독 | → `션` 자동 치환 |
| `TURE` 단독 | → `처` 자동 치환 |
| `IC` 단독 | → `익` 자동 치환 |
| `SION` 단독 | **수동** — 앞글자에 따라 션/전으로 갈려 자동 판정 불가 |
| `A-C-T` 같은 하이픈 나열 | **수동** — 읽는 법을 직접 써야 함 |
| `NATION`·`MISSION` 등 | 통과 — `VERIFIED_WORDS`에 있는 실제 단어는 정상 인식 |

```bash
node scripts/generate-tts.mjs --script=ep06_shortsA               # 검사만, 문제 있으면 중단
node scripts/generate-tts.mjs --script=ep06_shortsA --fix-narration # 치환 후 JSON에 저장
```

`VERIFIED_WORDS`에는 **음성을 직접 들어본 단어만** 추가할 것. 목록의 의미가 "검증했다"이지
"괜찮을 것 같다"가 아니다.

#### 치환은 한국어 문법을 지킨다

"알파벳 자리 앞뒤에 문장 경계를 넣는다"를 그대로 적용하면 `"션,을 붙이면"`이 되어
**오히려 더 나쁘게 읽힌다.** 그래서 경계는 **진짜 붙어버린 경우에만** 넣는다:

- 뒤가 공백/문장부호 → 이미 경계이므로 안 넣음
- 뒤가 조사(`을`/`는`/`의`…) → 명사+조사는 정상 한국어이므로 안 넣음
- 뒤가 한글에 바로 붙음(`TION강세`) → 이때만 쉼표를 넣음

조사 형태도 맞춘다. `IC` → `익`은 받침이 생기므로 `IC가` → **`익이`**로 고친다
(받침 유무는 `(코드 - 0xAC00) % 28`로 판정된다).

### ⚠️ 비용 — 견적 없이, 승인 없이 유료 호출 금지

무료 한도는 **모델당 10회/일**. 넘어가면 과금된다.

| 항목 | 값 (2026-08-02 확인) |
|---|---|
| 입력 | $1.00 / 1M 토큰 |
| 출력(오디오) | $20.00 / 1M 토큰 |
| 환산 | **32 토큰 = 1초** → 약 ₩0.92/초 |

`PRICING`에 단가·환율·`checkedOn`을 함께 박아 뒀다. **프리뷰 모델은 가격이 바뀌므로
확인일 없이 단가를 믿으면 안 된다.** 값을 추측해서 넣지 말고 가격표를 다시 볼 것.

**⚠️ 토큰/초는 문서값을 믿으면 안 된다.** 가격표는 25 토큰/초라고 하는데, API가 돌려준
`candidatesTokenCount`는 EP8 12개 파일 전부 **32.01**이었다(편차 32.00~32.03).
문서값으로 견적하면 **28% 낮게** 나온다. `audioTokensPerSecond`는 실측값 32이고
`audioTokensPerSecondSource`에 근거를 적어 뒀다.

`confirmSpend()`가 규칙이 아니라 **코드로** 막는다:

- 무료 한도 안이면 그냥 진행 (마찰 없음)
- 과금 구간이면 **원화 견적을 띄우고 멈춘다**
- 터미널(TTY)이면 `y/N` 확인, **아니면 하드 스톱** → `--confirm-paid` 필요

비대화형 분기가 핵심이다. **에이전트가 "음성 만들어줘" 한 마디로 사용자 돈을 쓰는 것을
막는 장치**다. 승인은 실행 단위이고 다음 실행으로 이어지지 않는다.

호출 내역은 `.tts-usage.json`에 누적된다(gitignore). 실행할 때마다 누적 금액이 출력된다.
다만 무료/유료 구분은 구글 카운터의 **로컬 근사치**다 — 정확한 청구액은 결제 콘솔이 기준.

## Whisper 타임스탬프 연동

```bash
node scripts/generate-highlights.mjs --episode=07   # 생략하면 06
```

음성 파일은 두 가지 이름 규칙을 모두 인식한다 — 직접 녹음한 EP6
(`ep06_Scene 3. 패턴 확인 ....wav`)과 TTS가 쓰는 `ep07_scene03.wav`.
whisper 캐시도 `ep{NN}_scene{N}_{model}.json`으로 에피소드별로 분리된다.
**분리 전에는 EP7이 EP6 캐시를 잘못 읽었다.**

### ⚠️ 단어 매칭은 원고 타임라인으로 한다 (`buildMatchTimeline`)

`highlightAt` 매칭에 **토큰 패스를 그대로 쓰면 안 된다.** 토큰 패스는 한글을 깨뜨리는데,
손실률이 소스에 따라 다르다:

| 소스 | 토큰 패스 한글 손실 | 단어 매칭률 |
|---|---|---|
| EP6 (직접 녹음) | 16% | 85% |
| EP7 (TTS) | **27%** | **30%** |

TTS 음성에서는 타겟 단어가 통째로 사라졌다 — `텔레비전` → `��������전`.
남은 건 "전" 한 글자라 ratio 0.25로 떨어져 버려졌다.

원고가 있으면 **원고를 보정된 세그먼트 시계에 LCS로 정렬한 타임라인**으로 매칭한다
(자막이 쓰는 것과 같은 타임라인). 원고는 정의상 정확하므로 매칭이 거의 100%가 된다.
원고가 비어 있으면 기존 토큰 패스로 폴백한다.

결과: **EP7 30% → 95%, EP6 85% → 100%.**

`MIN_TARGET_LENGTH`도 소스에 따라 갈린다. 깨진 전사문에서는 3글자 미만이 아무 데나 맞지만,
**원고에는 잡음이 없고 탐색이 앞으로만 진행**하므로 2글자까지 허용한다
(`MIN_TARGET_LENGTH_SCRIPT`). 이게 없으면 `미션`·`텐션`·`픽처` 같은 2음절 단어는
영어 철자로 폴백하는데, **한글 원고에는 영어가 없어서** ratio 0.00으로 영영 매칭되지 않는다.

1. `public/audio/*.wav`를 16kHz mono로 리샘플링 (WAV 파서/라이터 직접 구현, ffmpeg 불필요)
2. whisper.cpp(1.5.5 / small 모델)로 한국어 전사 — `.whisper/`에 자동 설치, gitignore 처리됨
3. **whisper 시계를 오디오 시계에 맞춘다** (아래 참고) — 자막·`highlightAt` 둘 다 여기서 갈린다
4. 전사 결과를 **글자 단위 타임라인**으로 펼친 뒤, 각 단어를 LCS 퍼지 매칭으로 찾는다
5. 매칭 구간의 시작/끝 시각 → 씬 기준 프레임으로 변환해 `highlightAt` / `highlightEnd`에 기록
   (끝 지점은 LCS로 고른 시작점에서 다시 greedy 스캔해 마지막으로 일치한 글자 위치로 잡는다)

### ⚠️ whisper 시계 보정 (`calibrateChars` / `calibrateTimeline`)

**whisper 타임스탬프는 실제 발화보다 이르다.** 보정 없이 쓰면 자막이 전반적으로 먼저 뜬다.

실측: 진짜 쉼(250ms 이상 무음) 뒤에 오는 whisper 세그먼트 시작 99개를 RMS onset과 비교.

| | 평균 오차 | 중앙값 \|오차\| | p90 | 300ms 초과 |
|---|---|---|---|---|
| 보정 전 | **−210ms** (이름) | 200ms | 320ms | 11/99 |
| 보정 후 | +82ms | **120ms** | **220ms** | **4/100** |

회귀식은 `오차 = −277ms + 3.8ms/초`였다. **시간 비례 성분은 40초 씬 전체에서 153ms**뿐이라
문제는 사실상 **상수 오프셋**이다. 그래서 스케일이 아니라 오프셋만 고친다.

오프셋을 상수로 박지 않는다: whisper는 항상 첫 세그먼트를 0.00에서 여는데 실제 발화는
0.26~0.46초에 시작하므로, **측정된 첫 발화 시점으로 타임라인을 밀면** 씬마다 알아서 나온다
(회귀 절편 −277ms와 35ms 이내로 일치).

**일부러 고치지 않는 것**: whisper의 마지막 세그먼트는 오디오 파일 끝보다 최대 1.5초 뒤에서
끝난다(Scene 9: 파일 35.04초인데 whisper 36.14초). 거기엔 소리가 아예 없으니 **청크 경계 패딩**이다.
이걸 없애려고 타임라인을 늘리면 전 구간에 **엉터리 5% 압축**이 걸린다 — 실제로 시도해 봤고
중앙 오차가 오히려 나빠졌다. 두 패스(토큰/세그먼트)의 끝 시각이 **완전히 동일한 것**이 근거다.

매칭 대상은 `narrationCue` → `pronunciation` → `word`(영어) 순으로 다 시도해서 제일 잘 맞는 걸 쓴다.
나레이션이 단어를 한글로 읽을 때도 있고("네이션") 영어로 읽을 때도 있기("information") 때문이다.

- 3글자 미만 타겟은 아무 데나 매칭되므로 제외 (예: "션")
- 매칭률 0.6 미만이면 `highlightAt`을 안 쓴다 (재실행 시 오래된 값은 지워짐)
- 자막 큐는 `CUE_MIN_FRAMES`(12프레임) 미만으로 짧아지지 않는다. onset 스냅이 이웃 큐를
  밀어붙여 **1프레임짜리 자막**이 나온 적이 있다(EP8 Scene 1은 "피, 아이, 씨…"처럼
  글자를 하나씩 읽어 쉼 onset이 촘촘하다). 스냅이 이웃을 굶기면 스냅을 포기한다.
- Whisper가 한글 일부를 깨뜨리는 경우가 있어서 정확 매칭이 아닌 LCS를 쓴다
- 현재 EP6 기준 19개 중 15개가 매칭된다. 실패한 단어(TRANSLATE/TRANSLATION/DECISION 등)는
  Whisper가 해당 한글을 깨뜨린 경우로, 중립 폴백되며 에러는 나지 않는다.
  필요하면 `medium` 모델로 올리거나 해당 단어만 JSON에 수동으로 값을 넣으면 된다.

### 타임스탬프가 화면에서 하는 일

두 겹으로 작동한다. 둘 다 calm/dynamic 공통이다.

**1) 항목 단위 활성화** (`useHighlightStates`)

| layout | 동작 |
|---|---|
| `wordList` | 활성 항목: opacity 1 + scale 1.03 + 테두리 초록→노랑 / 비활성: opacity 0.5, 테두리 초록 |
| `compare` | 언급되는 쪽 opacity 1, 반대쪽 0.5 |

전환은 0.3초 램프(`ANIMATION.highlightRampSec`), 유지 구간은 실제 발음 길이
(`highlightAt`~`highlightEnd`). `highlightEnd`가 없으면 1.2초 고정으로 폴백.

**2) 단어 자체의 발음 강조** (`useSpeechEmphasis`, quiz·wordList·compare 전부)

- 발음 시작(`highlightAt`): scale 1→1.15 (spring, 0.15초) + 글자색 흰색→노란색 (0.15초)
- 발음 구간 동안 그 상태 유지
- 발음 끝(`highlightEnd`): 0.2초에 걸쳐 원래 크기와 **각 부분의 원래 색**으로 복귀
  → 강세 음절은 원래 색이 노란색이므로 **노란색을 유지**하고, 나머지만 흰색으로 돌아간다
- compare의 `causeChar`(빨간 글자)는 의미를 담고 있어 강조 중에도 빨간색 유지

`highlightAt`이 없는 단어는 강조값이 0이라 아무 일도 일어나지 않는다.

**중립 상태**: 아무 단어도 언급 중이 아니면 전부 opacity 1 / 테두리 초록 / scale 1.
`highlightAt`이 아예 없는 씬도 계속 중립이라 기존 순차 등장으로 자연스럽게 폴백된다.
`useHighlightStates(words)`가 씬 단위로 한 번에 계산하므로 "다른 단어가 활성이라 내가 어두워지는" 판단이 가능하다.

## 공통 연출

- **배경**: Composition 레벨의 radial gradient (중앙 `#12203A` → 외곽 `#0A1526`), 20초 주기로 중심이 천천히 이동.
  씬 `<Series>` **바깥**에 있어서 컷이 바뀌어도 끊기지 않는다 — 이게 씬 페이드를 크로스페이드처럼 보이게 한다.
- **씬 전환**: 각 씬이 0.35초 fade + scale 0.98→1로 들어오고 나간다 (`SceneFrame`).
  그래서 `SceneFrame`은 자기 배경을 칠하지 않는다. 여기에 불투명 배경을 넣으면 전환이 검은 화면으로 깜빡인다.
- **좌상단 배지**도 Composition 레벨이라 씬마다 깜빡이지 않는다.
- **강세 음절 glow**: `EFFECTS.accentGlow` (`text-shadow: 0 0 12px rgba(245,197,24,0.2)`)
- **폰트**: `@remotion/google-fonts`로 Noto Sans KR(한글) + Inter(영어), 700/900만 로드.
  `index.css`에서 `-webkit-font-smoothing: antialiased` 적용.


1080x1920. **calm/dynamic/reference/card와 렌더링 경로를 전혀 공유하지 않는다** —
기존 씬 컴포넌트는 16:9 기준이고 세 스타일이 함께 쓰므로 건드리지 않았다.
팔레트·폰트·`useSpeechEmphasis`·`StressedWord`만 재사용한다.

`scripts/ep06_shortsA.json`은 `scenes`가 아니라 `segments`를 갖는다.
두 파이프라인 스크립트 모두 `--script=<이름>`으로 이 구조를 처리한다
(`data.scenes ?? data.segments`). 음성은 **세그먼트별 파일**로 만든다 —
각 세그먼트 화면 길이가 곧 자기 나레이션 길이라 경계 탐지가 필요 없기 때문이다.

### 데이터에서 주의할 점

- `stress`는 **한글 음절**("셀")이라 영어 철자에서 찾을 수 없다. 화면의 영어 단어에
  강세를 칠하려면 `stressEn`("CEL")을 따로 줘야 한다.
- 나레이션이 단어를 **온전히 발음하지 않는 경우**가 있다. seg3은 "정답은 브레이!"라고만
  하므로 `narrationCue: "브레이"`가 없으면 CELEBRATION이 매칭되지 않는다(ratio 0.50).
- `highlightAt`은 세그먼트에 직접 기록된다. 스크립트가 매칭용으로 임시 `words` 배열을
  만들었다가 **끝나면 다시 세그먼트로 옮기고 지운다.**

### 긴 단어는 폭에 맞춰 줄인다 (`wordCharWidthRatio`)

9:16은 좁다. `wordSizePct` 기본값으로 CELEBRATION(11글자)을 렌더하면 **양 끝 글자가
화면 밖으로 잘린다**(실측 폭 1180px > 1080px). `fitWordSize()`가 글자 수로 나눠
가용 폭에 맞춘다. 비율 0.77은 그 렌더에서 측정한 값이다.

### ⚠️ 9초 목표와 실제 길이

기획은 9초였지만 **원고를 그대로 읽으면 19.3초**다(세그먼트별 4.0/5.1/5.4/4.0초).
"음성 길이에 맞게 조정" 지시를 따라 실제 길이로 렌더한다. 9초로 맞추려면
**나레이션을 절반 이하로 줄여야** 한다 — 화면 타이밍만 조여서 될 문제가 아니다.

### 쇼츠 안전영역과 효과음 (`src/shortsLayout.ts`)

플랫폼 UI와 효과음 규칙은 `theme.ts`가 아니라 여기 둔다 — 채널의 **디자인**이 아니라
**플랫폼**(버튼이 어디 있는지, 어느 박자에 어떤 소리가 나는지) 얘기이기 때문이다.
EP06-shortsB, EP07-shortsA/B가 그대로 재사용한다.

**`SHORTS_SAFE`** — 빈 쇼츠 화면 스크린샷에서 측정했다.

| 영역 | 값 | 가리는 것 |
|---|---|---|
| 상단 | 15% | 검색·더보기 아이콘 |
| 하단 | 10% | 핸들 + 설명 블록 |
| 우측 | **18%** | 좋아요/싫어요/댓글/공유/리믹스 레일 |

우측 18%가 핵심이다. 가운데 정렬하면 단어가 **버튼 밑으로 들어간다.**
모든 콘텐츠는 `contentBand()`가 계산한 좌측 밴드 안에 배치하고,
`fitWordSize()`도 이 밴드 폭 기준으로 줄인다(전체 폭 아님).

**`SHORTS_SFX`** — 어느 박자에 어떤 소리가 나는지의 단일 출처.

| 박자 | 소리 | 타이밍 |
|---|---|---|
| 카운트다운 숫자마다 | `uiSwitch` | 각 숫자 등장 프레임 |
| 정답 공개 | `ding` | `highlightAt` (세그먼트 `reveal: true`인 곳만) |
| CTA 등장 | `whoosh` | 세그먼트 시작 |

음원은 `@remotion/sfx`가 노출하는 **원격 URL**이라 첫 렌더에 네트워크가 필요하다.
볼륨은 나레이션의 70%(`SHORTS_SFX.volume`)로 깔린다.

`reveal` 플래그가 없으면 `ding`이 안 울린다. **첫 단어는 조용히 등장해야** 하므로
seg1에는 일부러 넣지 않았다.

**`SHORTS_COUNTDOWN`** — 카운트다운은 **질문 나레이션이 끝난 뒤** 시작한다.
나레이션 밑에서 숫자가 돌면 생각할 시간이 아니라 진행 바처럼 읽히기 때문이다.
그래서 카운트다운 세그먼트 길이 = `나레이션 + 1.8초`이고, **다음 나레이션이 그만큼 밀린다.**

### ⚠️ TTS 목소리가 세그먼트마다 흔들린다

같은 `VOICE`(Charon 고정)로 만들어도 짧은 입력에서는 음높이가 드리프트한다.
쇼츠 1차 생성 실측: **126 → 159 → 180 → 209 Hz**로 계속 올라가, seg04는 여성 음성처럼 들렸다.

**긴 원고(EP6/EP7 씬)에서는 안 나타난다** — 세그먼트가 짧을수록 심하다.
쇼츠를 만들면 **F0를 측정해서 검수할 것.** 재생성하면 값이 달라지므로
목표 범위(120~140Hz)가 나올 때까지 반복한다. seg04는 1회 재생성으로 130Hz가 나왔다.

#### ⚠️ 효과음은 파일 앞 무음만큼 늦게 들린다 (`leadInMs`)

Remotion은 **파일 재생 시작**을 프레임 정확하게 잡지만, 음원 앞부분에 무음이 있으면
**들리는 시점**은 그만큼 늦다. 렌더 결과를 측정해 보니 카운트다운 클릭 3개가
전부 정확히 **+160ms** 늦었다 — 세 개가 동일한 오차라는 게 파일 자체의 지연이라는 증거다
(스케줄링 오차라면 값이 흩어진다).

| 소리 | 앞 무음 | 처리 |
|---|---|---|
| `uiSwitch` | 160ms | 그만큼 앞당김 → 오차 5ms |
| `ding` | 48ms | 앞당김 |
| `whoosh` | ~400ms | **앞당기지 않음** — 클릭이 아니라 상승음이고 세그먼트 맨 앞이라 당길 공간이 없다. 절정이 CTA 안착과 맞는 게 오히려 맞다 |

`sfxStart()`가 목표 프레임에서 `leadInMs`를 빼서 **들리는 순간**을 맞춘다.
새 효과음을 추가하면 렌더한 뒤 실측해서 값을 넣을 것 — 추측하면 안 된다.

검증 방법: 렌더된 mp4에서 오디오를 뽑아(`npx remotion ffmpeg -i ... -vn`)
5ms RMS 포락선의 급상승 지점을 기대 프레임과 비교한다.

### shortsB — compare 레이아웃 (`EP06-shortsB`)

같은 프레임·안전영역·효과음·자막 파이프라인을 쓰고 **비트만 다르다**: 단어 하나 대신
**틀린 읽기 vs 실제 발음**을 좌우로 대조한다.

**좌우가 아니라 세로 스택이다.** 9:16에서 두 컬럼으로 나누면 각 컬럼이 이미 좁은 폭의
절반뿐이라, 오독 텍스트와 실제 단어가 **둘 다 줄어들어** 비트가 죽는다.

위에서 아래로 세 박자 (`SHORTS_COMPARE`):

| 시각 | 일어나는 일 |
|---|---|
| 0~0.8초 | "그대로 읽으면" 라벨 + 오독 텍스트 (표시만) |
| **0.8초** | X 두 획이 그려지고 + 취소선 + ↓ 화살표가 튕기며 낙하 + `uiSwitch` |
| 1.2~2초 | "실제 발음" 라벨 + 영어 단어 + 한글 발음 |

**오독을 먼저 읽히는 게 핵심이다.** X를 텍스트와 동시에 띄우면 무엇이 틀렸는지
읽기 전에 지워진다. 그래서 0.8초를 비워 둔다.

X는 텍스트 **옆에** 놓는다(글자 크기의 60%, `crossSizeRatio`). 위에 겹치면
오독 텍스트 자체가 안 읽힌다.

화살표만 damping 11(임계값 미만)이라 **한 번 튕기고 안착**한다. 나머지는 200이라 정지.

`generate-highlights.mjs`는 `word`뿐 아니라 **`compareRight.word`도 매칭 대상**으로 잡는다.
이게 없으면 `highlightAt`이 비어 정답 공개가 고정 시간에 뜬다.

#### ⚠️ 화면용 오독 텍스트는 절대 narration에 넣지 않는다

`compareLeft.text`("스테이 티온")는 **화면 전용**이다. 나레이션에 들어가면
나레이터가 틀린 발음을 읽어 **영상이 오답을 가르친다.**
`generate-tts.mjs`가 `narration.includes(compareLeft.text)`를 검사해 **생성 전에 막는다.**

#### 강세는 `compareRight.stressEn`이 있어야 칠해진다

`compareRight.stress`는 **한글**("스테이")이라 영어 철자에서 못 찾는다.
`stressEn`("STA")이 없으면 단어가 통째로 흰색으로 나온다 — shortsA의 `stressEn`과 같은 이유다.

| 요소 | y 범위 |

| 헤더 2줄 | 288 ~ 463 |
| compare 스택 | 523 ~ 1090 |
| 자막 | 1473 ~ 1650 |

스택 높이가 567px이라 헤더·자막과 겹치지 않는다. 요소를 추가하면 이 표를 다시 계산할 것.
