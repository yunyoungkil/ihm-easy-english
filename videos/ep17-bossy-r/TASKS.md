### 5. 전체 재검토 중 스스로 발견한 버그 — Frame 6·7·8 단어 카드 seek-비결정성

사용자가 "영상 어떤 것 같아?"라고 물어서 여러 시점을 스냅샷으로 다시 훑어보다가 발견.
Frame 6의 5개 단어 카드(`car, park, star, farm, card`)가 로컬 t=10초·20초 스냅샷에서는
전혀 안 보이는데 t=17초에서는 보이는 이상한 현상을 확인. 원인은 `.f06-word-card`에 남아
있던 `transition: all 0.2s ease;` — GSAP가 seek(임의 시각으로 순간이동) 시 최종 opacity/
transform 값을 즉시 계산해서 넣어주는데, 이 CSS 트랜지션이 그 순간 다시 끼어들어 "이전
DOM 상태 → 새 값"으로 0.2초짜리 실제 시간(wall-clock) 트랜지션을 새로 시작해버림 — 그
결과 화면 캡처가 정확히 언제 일어나느냐에 따라 카드가 보이거나 안 보이거나 하는, **영상
타임라인과 무관하게 결과가 갈리는 비결정성 버그**였음. 이 프로젝트(HyperFrames)는
"단일 paused 타임라인, seek-safe, deterministic"이 핵심 전제인데 이 버그는 그 전제를
정면으로 깨는 것이었고, 실제 렌더 파이프라인이 프레임마다 seek하는 방식이라면 최종
영상에도 카드가 빠진 채로 나갔을 수 있었음. Frame 7·8에도 똑같은 트랜지션이 복사돼 있어
셋 다 제거. 이후 t=10/17/20초 전부 카드가 안정적으로 보이는 것 재확인.

### 검증

- `npx hyperframes@0.8.46 check --timeout=35000` 매 수정마다 재실행 — 0 errors 유지
  (기존부터 있던 대비 경고 8~9건은 이번 세션에서 안 건드림, 최종 렌더 전 별도 정리 필요).
- 스냅샷으로 Frame 1(최소 대립쌍)/3/4(반전 재배치)/9(재생성 타이밍)/11(IR 색상)/6(카드
  안정성)/12/14/15(엔드스크린) 등 다수 지점 육안 확인 완료.

### 다음 영상에도 적용될 일반 교훈 (CLAUDE.md/AGENTS.md로 승격 완료)

- **"영문 알파벳 + 색깔 span"으로 단어를 부분 강조할 때, span 시작 글자가 "f"이고 그
  직전 글자가 없거나 span과 붙어 있으면("fi", "fl" 등 리게이처 조합) 브라우저가 리게이처를
  span 경계 너머로 합성해 앞쪽 색을 따라가 버릴 수 있다** — 강조용 텍스트 요소에는
  기본적으로 `font-variant-ligatures: none`을 걸어두는 걸 표준으로 삼을 것.
- **GSAP로 애니메이션하는 요소에는 절대 CSS `transition`을 같이 걸지 말 것** — HyperFrames는
  seek 기반 렌더링이 전제라, 같은 속성에 CSS transition이 남아있으면 "정확히 언제
  캡처/렌더하느냐"에 따라 결과가 달라지는 비결정성 버그가 생긴다(이번엔 카드 3개 프레임
  전부에 복사·붙여넣기로 퍼져 있었음). 새 프레임 작성 후에는 `grep -n "transition:"
  compositions/frames/*.html`로 GSAP 대상 요소에 남은 CSS transition이 없는지 훑어볼 것.
