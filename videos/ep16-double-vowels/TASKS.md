## 2026-09-17 — 나레이션 누락 구간 전수 감사 + 캡션 보강 (12프레임 전체)

사용자 지시: "영상 제작시 각 프레임의 씬은 나레이션 단어,문자을 빠짐 없이 넣어야해. 16 빠진
부분 있으면 체워 넣고 업데이트해" — 나레이션이 말하는 모든 단어/문장은 화면 어딘가에 텍스트로
반드시 나타나야 한다는 일반 제작 규칙으로 제시됨. 기존 히어로 비주얼/단어 스택이 이미 그 구간을
문자 그대로 커버하면 중복 자막은 넣지 않되, 진짜로 화면에 아무 텍스트도 없이 나레이션만 흐르는
구간(무음 아님 — 소리는 나는데 화면엔 없는 구간)은 전부 캡션으로 채우기로 판단.

**감사 방법**: 12개 프레임 각각의 `assets/voice/NN.words.json`(whisper 실측 전문)을 그 프레임의
HTML/JS가 실제로 화면에 띄우는 텍스트와 문장 단위로 대조. 커버 안 되는 구간마다 정확한 시작
시각(대개 문장/절 경계)을 실측값에서 뽑아 캡션 표시 타이밍으로 사용.

**공통 구현 패턴** — `frame.md`에 이미 명세만 있고 미구현이던 `caption-pill` 컴포넌트(흰 배경
+ `#2B2B2B` 2px 테두리 pill, `border-radius:100px`, 본문 타이포)를 실제로 만들어 12프레임에
동일 적용. 클래스 프리픽스는 프레임별로 분리(`f01-caption-*`~`f12-caption-*`)해 충돌 방지.
텍스트 전환은 기존에 확립된 "딥-스왑-복귀" 패턴(opacity 0.15로 낮춤 → `tl.call()`로
`textContent` 교체 → opacity 1로 복귀) 재사용 — 하드컷 없이 자연스럽게 바뀜. 여러 개의
`tl.fromTo()`가 같은 엘리먼트를 겨냥할 때 `gsap_repeated_fromto_without_baseline` 린트 경고가
뜨는 걸 Frame 2에서 처음 만나 원인 파악(초기 baseline `tl.set(el,{opacity:0},0)` 부재) 후,
이후 모든 프레임에 처음부터 이 baseline을 넣어 재발 방지.

## 2026-09-17 (이어서) — Frame 12 카드 그리드 화면 중앙 재배치

사용자 검수 지적: "마지막 프레인 카드들은 중앙으로 옮겨." 기존 `.f12-grid`는 `top:10cqh`
(화면 상단 10~50%)에 붙어 있어 상단 진행바 바로 아래에 카드가 몰려 있고, 손글씨 태그라인
(`top:58cqh`) 아래로는 캡션 pill까지 화면 하단 40% 가까이가 텅 비어 위로 쏠린 레이아웃이었다.
그리드를 화면 정중앙(`top:30cqh`, 높이 40cqh → 30~70cqh, 중심 정확히 50cqh)으로 옮기고,
태그라인도 그리드 바로 아래 자연스러운 간격을 유지하도록 `top:58cqh`→`74cqh`로 같이
내렸다(캡션 pill과의 간격은 여전히 충분히 확보됨).

**검증**: `hyperframes check` 재실행 — 0 errors, 레이아웃 9개 샘플 이상 없음, WCAG AA 50/50
유지. 절대 시각 367.75/377.75/388초(그리드만 보이는 시점 / 태그라인+캡션 동시 표시 시점 /
캡션 마지막 문구 표시 시점) 3곳 스냅샷으로 카드가 화면 중앙에 놓이고 태그라인·캡션과 겹치지
않음을 확인.

## 2026-09-17 (이어서) — Frame 10 카드에 영문 단어 자체가 없던 문제 수정

사용자 지적: "10프레임 영문 단어가 안 나오고 한글 발음만 나옴." 실제로 `10-practice.html`의
카드는 음절 빌드업(`f10-syllables`)과 병합된 한글 단어(`f10-full`, "보트"/"미트"/"헤드")만
그렸고, 정작 그 발음이 어느 영어 단어("BOAT"/"MEAT"/"HEAD")의 발음인지는 화면 어디에도
없었다 — 코드 주석에도 이미 "the card only ever shows Korean syllables, never the English
word being announced"라고 스스로 적어뒀던 걸 그동안 캡션으로만 우회하고 카드 자체는
안 고쳤던 셈. 카드 맨 위에 `.f10-en` 엘리먼트를 새로 추가해 영문 단어를 표시하도록 수정
(이중모음 부분은 다른 카드들과 같은 규칙으로 강조색 처리: BOAT/MEAT는 `#8A5A12`, 예외
HEAD는 `#D64545`). 각 단어의 `reset` 시점 + 0.1초에 페이드인되어 음절 빌드업보다 먼저 영어
철자가 눈에 들어오게 타이밍을 잡았다.

**검증**: `hyperframes check` 재실행 — 0 errors, WCAG AA 50/50→52/52(신규 텍스트 포함).
절대 시각 284.95/297.85/313.35초(BOAT/MEAT/HEAD 각각 병합 직후 시점) 3곳 스냅샷으로

## 2026-09-17 (이어서) — Frame 8 정답 원 그리기 전 대기 중 점 노출 버그 수정

사용자 지적: "8프레임 원을 그리는 빨간 점이 원을 그리기 전부터 대기(화면에 보임)는데 이걸

애니메이션이 시작되는 순간에만 1로 되돌리는 것이었다. 이 방식을 그대로 적용:

- `.f08-circle path` 기본 `opacity: 0` 추가.
- 각 문제 리셋 시점(`q.qAt`)에 `gsap.set(circle, {opacity:0})`을 명시적으로 다시 걸어(다음

  → 곧바로 `stroke-dashoffset` 드로우 트윈이 이어지도록 순서 정리.

## 2026-09-17 (이어서) — Frame 5 COAT 카드가 아래로 치우쳐 보이던 버그 수정

사용자가 실제 렌더 스크린샷을 보내며 지적: "5프레임 카드가 아래로 치우침 중앙으로 오게

**원인**: `.f05-card`는 `top:50%; transform: translateY(-50%)`로 세로 중앙 정렬돼 있었는데,
등장 애니메이션이 `tl.fromTo(card, { y: 20 }, { y: 0 })`로 GSAP `y`를 직접 애니메이션했다.
GSAP는 `x`/`y`를 "절대 변위 값"으로 다루기 때문에, `y:20`→`y:0`처럼 명시적으로 값을 지정하면
그 트윈이 **transform 전체를 새로 써버려서 CSS의 `translateY(-50%)`가 통째로 사라진다** —
결과적으로 카드의 "박스 중앙"이 아니라 "박스 위쪽 모서리"가 화면 세로 중앙선 근처에 오게
되어, 박스 전체가 그만큼(카드 높이의 절반만큼) 아래로 처져 보였다. (반대로 scale·x만
애니메이션하고 y는 건드리지 않는 다른 프레임들은 GSAP가 최초 1회 CSS의 `-50%` 값을
그대로 내부에 보존하기 때문에 이 버그가 없다 — 실제로 EP16 12프레임 전체를 훑어봤을 때
이 조합(`translateY(-50%)` 중앙 정렬 + 그 요소 자체에 명시적 `y` 트윈)은 Frame 5의
COAT 카드가 유일했다.)

**수정**: CSS에서 `transform: translateY(-50%)`를 제거하고, 대신 GSAP가 처음부터
`yPercent: -50`을 소유하도록 `tl.set(card, { yPercent: -50 }, 0)`을 추가 — `yPercent`는
슬라이드인 오프셋용 `y` 트윈과 올바르게 합성되므로, 중앙 정렬과 슬라이드 애니메이션이
서로 충돌하지 않는다.

**검증**: `hyperframes check` 재실행 — 0 errors. 절대 시각 131.88초(카드 등장 후) 스냅샷으로
