## 2. PHASE 7 — 스크립트 목차 (아웃라인) 설계

1. **소재 고유의 호흡 설계**: 과거 에피소드 목차를 기계적으로 복제하지 않고 이번 소재에 필요한 비트만 새로 설계합니다. 목차를 보고할 때 직전 3편의 프레임 구성을 나란히 보여 주고, 이름과 순서가 같으면 다시 짭니다(2026-11-06 필수. 이 규칙이 있었는데도 EP22·EP24~29가 같은 10칸으로 만들어졌기 때문입니다). 직전 구성은 `videos/<프로젝트>/compositions/frames/` 파일 목록으로 확인합니다. 이전 편의 프레임 생성 스크립트를 복사해 단어만 바꾸지 않습니다.
2. **첫 프레임(F01 훅)의 원칙**:
   - 썸네일 골드 알약 카피가 한 약속을 첫 문장에서 즉시 받아서 시작합니다.
   - 예: 알약 카피가 "다 '드'로 읽으셨죠?" ➔ 첫 대사: "네, 저도 한동안 다 드로만 읽었습니다."
3. **도파민 3단계 공식 검토 (체크리스트)**:
   - 1단계: 게으른 혀의 소리 지름길 (원리 해설)
   - 2단계: 패턴 확장 (본문 반복 연습)
   - 3단계: 반전 꿀팁 / 총정리 요약
4. **하나의 구체적 현실 장면에 모든 예문 바인딩**:
   - 문법책식 낱개 문장 나열 금지.
   - F01에서 제시한 현실 맥락(미드 대사, 일상 안내 방송, 문자 등)을 끝까지 유지.
5. **사람이 만든 흔적 확인 (2026-11-06)**:
   - 실제 시청자 댓글 질문에 답하는 부분이나, 도입·마무리 직접 녹음 중 하나를 넣을 수 있는지 확인합니다.
   - 댓글은 `data/youtube/comments.json`에 실제로 있는 것만 씁니다. 넣기 어려우면 이유를 `BRIEF.md`에 적습니다.
   - TTS를 누가 만들지 물을 때 직접 녹음도 선택지로 함께 묻습니다. AI 음성 자체는 금지가 아니고, 직접 녹음의 효과를 유튜브가 보장하는 것도 아닙니다.
6. **모은 데이터로 목차 채우기 (2026-11-11)**:
   - `BRIEF.md` "기획 근거"의 시청자 고민 항목을 목차의 어느 프레임이 풀어 주는지 표에 한 칸으로 적습니다. 어느 프레임에도 없으면 목차를 다시 봅니다.
   - 나레이션에 쓸 시청자 말투는 `audience-dna.json`의 `question`·`vocabulary` 항목에서 찾습니다. 출처 영상이 발음 강의인 항목만 씁니다.
   - `success-patterns.json`에 `확정` 항목이 있으면 그 `reusableHook`·`reusableAnalogy`를 F01 훅 후보에 넣고, 쓰지 않으면 이유를 한 줄 적습니다. `가설` 항목은 후보로만 둡니다.

## 3. PHASE 8 — 전체 스크립트 및 화면 시각화 규격

### 듣기/반복 콘텐츠 구성 규칙
- **나레이션 배치**: 도입부 설명 프레임과 반복 시작 전 1줄 안내에만 나레이션을 배치합니다.
- **반복 청취 구간**: 단어/문장이 반복되는 동안에는 호스트 나레이션을 넣지 않고 원어민 오디오에 집중시킵니다.

### 컴포지션 시각화 규칙
1. **영어 단어 음절 분리(`·`) 표기 원칙**:
   - 2음절 이상 단어: 영어 철자 자체에 가운뎃점 표기 (`cof · fee [커피]`, `let · ter [레러]`, `wa · ter [워러]`).
   - 1음절 단어: 영어 단어는 그대로 유지 (`sheep`, `ship`), 한글 독음도 자연스러운 1음절(`[쉽]`, `[풀]`)로 표기하되, 쉬운 말 뱃지(`입꼬리 당김` vs `힘 뺌`)로 호흡을 구별.
2. **실전 대화 프레임 타겟 단어 하이라이트 & 바운스**:
   - 문장 내 타겟 짝단어는 `<span class="hl-tense">`, `<span class="hl-lax">` 등으로 고대비 강조.
   - 오디오 발화 타이밍에 맞춰 1.15~1.2배 바운스(scale) 애니메이션 연동.
   - 카드 하단에 소리 팁 필수 배치 (`💡 right (허공 0%) vs light (잇몸 100%)`).
3. **타겟 접미사/음소 분리 컬러 매핑**:
   - 어간: 차콜 블랙 (`#111111`)
   - `[t]` 끝소리 (성대 떨림 0%): 코랄 레드 (`#DC2626`)
   - `[d]` 끝소리 (성대 떨림 100%): 스카이 블루 (`#2563EB`)
   - `[ɪd]` 끝소리 (혀 꼬임 방지 쿠션): 에메랄드 그린 (`#059669`)

## 4. Gemini TTS 직접 제작 표준 규격

사용자가 Google AI Studio 또는 Gemini API를 통해 음성을 직접 생성하므로, 대본 파일(`SCRIPT.md`)은 아래 규격을 엄격히 준수합니다:

1. **복사용 순수 텍스트 코드 블록(` ```text `) 100% 분리**:
   - 마크다운 기호, 해설 괄호, 번호 매김 없이 드래그/복사 즉시 입력창에 넣을 수 있는 독립 블록 제공.
2. **영문 지시문(Directive) 혼합 절대 금지**:
   - 블록 내부에 `Say only...`, `Voice instruction...` 등을 절대 넣지 않습니다 (TTS가 지시문까지 읽는 사고 방지).
3. **문장 첫머리 한국어 필수 & 어휘 다양화**:
   - 영단어로 시작하지 않고 100% 순수 한국어로 시작.
   - 상투적 클리셰인 `솔직히` 남발을 금지하고 다양한 도입부 어휘 사용.
4. **목적격 조사(`을/를`) 누락 금지**:
   - `귀를 뚫어 드리겠습니다`, `소리를 뚫어 드리겠습니다`.
5. **단어 끝소리 급단절 방지 표기**:
   - 단어 나열 시 마침표(`.`) 대신 반드시 쉼표(`,`)나 줄임표(`...`) 사용 (`sheep, ship, feet, fit,`).
6. **오디오 후처리 및 배경 믹싱 기준**:
   - 단어별 분할 시 끝부분에 **0.25초(250ms) 이상의 여운 패딩** + 끝 0.05초 페이드아웃 적용.
   - 영상 배경에 잔잔한 로파이/어쿠스틱 BGM을 8~10% 볼륨으로 믹싱하여 완전 무음(Dead Silence) 방지.

## 5. 대본 팩트 체크 (2026-11-07 신설, 필수)

초안을 쓴 직후 `videos/<프로젝트>/FACT-CHECK.md`를 만듭니다. 이 표가 없으면 멈춤 지점 3을 보고하지 않고, 음성도 만들지 않습니다. 쇼츠 대본도 같습니다.

**확인할 대상과 방법**

| 대상 | 예 | 확인 방법 |
|---|---|---|
| 발음 설명 | 혀끝 위치, 입 모양, 소리 길이 | 음성학 교재, 논문, 발음 교육 자료의 원문 |
| 발음기호, 단어 뜻 | `ʃɪp`, full의 "배부르다" | 사전 |
| 한글 표기 주장 | "한글로 쓰면 전부 풀" | 국립국어원 외래어 표기법 조항을 그 단어에 적용 |
| 우리 학습자에 대한 주장 | "같게 들리기 쉽습니다" | 한국인 학습자 연구 |
| 예문의 실제 쓰임 | 길 안내 문장 | 회화 교재, 사전 예문 |
| 채널 숫자 | 평균 시청률, 댓글 수 | YouTube API 측정값. 기간과 표본 수를 함께 적음 |
| 유튜브 기능과 정책 | 관련 동영상 조건 | YouTube 고객센터 |
| 제목, 날짜, 개수 | 20쌍, 11/9 공개 | `title.txt`, `status.json`, 프로젝트 파일 |
| 재사용 음성 파일 | `m_w03_fool.wav` | 로컬 whisper로 내용 대조, 실제 소리 길이 측정 |
| 그림 프롬프트의 묘사 | 입술, 혀 위치 | 발음 설명과 같은 근거 |
| 화자의 1인칭 경험 | "직접 녹음해 봤다" | 사용자에게 확인 (`CLAUDE.md` 스크립트 원칙 9번) |

대본의 낭독문, 화면 문구, 설명란과 고정 댓글, 그림 프롬프트, `BRIEF.md`의 숫자와 출처를 모두 표에 넣습니다.

**표 형식** (필수 칸)

```markdown
| 위치 | 주장 | 판정 | 근거 | 조치 |
|---|---|---|---|---|
| 3줄 | 한글로는 둘 다 쉽 | 틀림 | 표기법 적용 시 sheep 시프, ship 십 | "흔히 둘 다 쉽이라고 읽지만"으로 교체 |
```

**판정** (다섯 가지만 씁니다)

| 판정 | 뜻 | 조치 |
|---|---|---|
| 확인됨 | 원문을 열어 읽었고 주장과 일치 | 유지 |
| 일부 확인 | 일부만 맞음, 또는 검색 요약으로만 봄 | 근거가 닿는 범위까지만 말하도록 문장을 좁히거나 한계를 적음 |
| 확인 안 됨 | 근거를 찾지 못함 | 시청자에게 말하는 문장이면 빼거나 사용자에게 물음 |
| 틀림 | 근거와 어긋남 | 고침 |
| 청취 필요 | 사람 귀로만 판단 가능 | 파일 이름을 보고서에 적어 사용자에게 요청 |

근거는 원문을 연 자료만 "확인됨"으로 적습니다. 검색 요약, 제 기억, 경쟁 채널의 설명, 프로젝트의 이전 대본은 "확인됨"의 근거가 아닙니다.

**귀로 듣는 점검**: 문장마다 화면 없이 소리만 듣는다고 생각하고, 다른 뜻으로 들리는지 적습니다. 다르게 들리면 "틀림"과 같이 고칩니다.

- "이 소리가 납니다" → 모음 '이' 소리로 들림
- "이 둘도 똑같습니다" → 두 단어의 소리가 같다는 말로 들림

**순서**

1. 초안을 쓰고 표를 만든 뒤 문장을 고칩니다.
2. 6절 한국어 다듬기를 합니다.
3. 다듬기로 바뀐 문장을 표에서 다시 판정합니다.
4. 멈춤 지점 3 보고에 "틀림", "일부 확인", "청취 필요" 항목과 파일 링크를 넣습니다.

## 6. 한국어 다듬기 (korean-skills, 2026-11-06)

팩트 체크를 마친 초안을 아래 순서로 하나씩 실행합니다. 순서가 중요합니다. 말투를 먼저 고치고, 표기를 맞춘 뒤, 마지막에 맞춤법을 봐야 앞 단계 수정이 다시 틀리지 않습니다.

1. **`korean-skills:humanizer`**: AI 말투(번역투, 같은 문장 끝맺음 반복, 쉼표 과다)를 찾아 사람이 말하듯 고칩니다. 습니다체 기본 톤과 `CLAUDE.md` 스크립트 원칙 8번(나레이션은 말이다)을 기준으로 삼습니다.
2. **`korean-skills:style-guide`**: 이전 에피소드 `SCRIPT.md`와 용어·숫자·표기(`반복 듣기`, `짝단어`, 음절 분리 `·` 등)를 맞춥니다.
3. **`korean-skills:grammar-checker`**: 맞춤법, 띄어쓰기, 목적격 조사(`을/를`) 빠짐을 마지막으로 잡습니다.

스킬마다 고친 곳을 "원문 → 수정안" 표로 따로 보여 주고, 사용자가 승인한 것만 `SCRIPT.md`에 반영합니다. TTS 복사용 ` ```text ` 블록 안의 영어 단어 한글 독음(`쉬잎` 등)은 의도된 표기이므로 맞춤법 수정 대상에서 뺍니다.

## 7. 산출물 및 워크플로우

1. **저장 위치**: `videos/<프로젝트>/SCRIPT.md` (기존 파일 확인 후 작성).
2. **체크리스트 표**: 파일명, 화자, 텍스트 요약, 예상 초 수 표를 상단에 배치.
   - **음성을 만들기 전 금지어 검사**: `npm run check-terms -- videos/<프로젝트>`를 실행해 대본 낭독문을 확인합니다. 음성을 만든 뒤에 고치면 그 장면 나레이션을 다시 만들어야 합니다.
3. **멈춤 지점 3 — 대본 확정**: 목차 비교표(직전 3편), 대본, **팩트 체크 표(`FACT-CHECK.md`)**, 한국어 다듬기 표, 금지어 검사 결과를 보고하고 승인을 기다립니다. 음성 제작은 비용과 재작업이 드는 단계라 이 승인 없이 시작하지 않습니다.
