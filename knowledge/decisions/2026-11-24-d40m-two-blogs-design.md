### 6-2. 쿠팡 블로그

- **독자**: 가전·디지털 기기를 쓰다 막힌 사람(오류, 설정, 연결 안 됨, 전환 방법)과 사기 직전에 "이거 확인해야 하나?"를 찾는 사람. 나이를 정하지 않는다(유튜브의 3060 타깃은 영어 블로그에만 해당).
- **글 종류 두 가지**: ① 문제 해결(증상 → 원인 후보 → 순서대로 해 볼 것 → 안 되면 어디로) ② 사기 전 확인(호환·규격·설치 조건·자주 하는 실수). 글 모양은 고정하지 않는다(채널 슬로건의 탈템플릿).
- **반드시 들어갈 것**: 글 맨 위 대가 문구 — `이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.` / 근거 출처(제조사 설명서·고객지원 페이지·공식 공지) 링크 / "직접 써 보지 않았고 제조사 안내와 사용자 질문을 정리했다"는 취지의 한 줄(문장은 매번 자연스럽게).
- **금지 낱말·표현**: 써 보니, 사용해 보니, 직접 써, 내돈내산, 실사용, 후기(제목·본문의 경험 주장), 지어낸 1인칭 경험.
- **다루지 않는 해결 단계 (Claude 판단, 검토 단계 지적 반영)**: 기기 분해, 배터리 교체·충전 개조, 전원·전기 배선, 펌웨어 강제 설치·초기화 우회, 보증이 무효가 되는 조치, 데이터가 지워지는 단계를 경고 없이 안내하기. 이런 단계가 필요한 문제는 "제조사 서비스센터로" 안내까지만 쓰고, 데이터가 지워지는 단계(초기화 등)는 백업 안내를 먼저 둔다. 주제 자체가 이것뿐이면 대기열에 넣지 않는다.
- **글마다 사실 확인표 (Claude 판단)**: 영상의 `FACT-CHECK.md`처럼, 글의 해결 단계 하나하나에 근거가 된 출처 문장(원문 그대로)을 붙인 표를 글 파일 옆에 남긴다. 출처 문장이 없는 단계는 글에서 뺀다. 점검 프로그램은 표가 있는지, 단계 수와 표 줄 수가 맞는지를 본다.
- **주제 고르기 (데이터 순서)**: ① 옛 k-posting.info 서치 콘솔 검색어 중 클릭·노출이 컸던 문제 해결 주제(같은 계정 `/u/0/`) ② 구글·네이버 자동완성과 지식인 질문 ③ 이미 쓴 주제와 겹치지 않기(글 기록 파일). 옛 글 문장은 가져오지 않고 주제만 새로 쓴다.
- **쿠팡 링크**: 해결에 실제로 필요한 물건(교체 부품, 케이블, 호환 액세서리)이 있을 때만 넣는다. 억지 링크를 넣지 않는다. 링크는 **파트너스 공식 API**로 만든다(키 발급돼 있음, 11/24 확인). 새벽 실행에서도 그 자리에서 만들 수 있어 미리 쌓아 둘 필요가 없다. 키는 `.env`에만 두고 클로드에게 넘기지 않는다: 클로드는 "필요한 물건과 검색어"를 글 파일에 적고, 프로그램이 API로 상품을 찾아 클로드가 고른 상품의 링크를 만든다.
- **그림**: 제품 실물 사진처럼 보이는 AI 그림은 쓰지 않는다(써 본 척으로 읽힌다). 순서도·설정 화면 위치 같은 설명 그림이나 쿠팡 파트너스가 제공하는 상품 이미지만.
- **속도(가설)**: 처음 4주 주 3편. 4주 뒤 서치 콘솔 노출·클릭을 보고 조절한다. 하루에 몰아 올리지 않는다.
- **주제 대기열 (Claude 판단)**: 주제 고르기(위 ①~③)는 **대화 안에서** 한다(로그인이 필요한 옛 서치 콘솔 `/u/0/` 화면을 새벽에 열지 않기 위해). 결과를 대기열 파일(예: `data/blog/tech-queue.json`)에 주제·노리는 검색어·참고 출처 후보로 쌓는다. 쿠팡 링크는 대기열에 넣지 않는다(새벽에 API로 만든다). 대기열이 2주 분량(6편) 아래로 떨어지면 시작 브리핑에 "주제 보충 필요" 한 줄을 띄운다.
- **혼자 도는 흐름**: 작업 스케줄러(집 PC, 매일 루프(01:00)가 끝난 뒤인 02:00경, 글 쓰는 날만) → 클로드 대화 없이 실행: 대기열 맨 앞 주제 1개, 허용 도구는 웹 검색·웹 읽기·글 파일 쓰기만(브라우저·로그인 화면·git·게시 권한 없음) → 점검 프로그램(6-4) → 통과하면 구글 블로그 공식 통로(Blogger API)로 게시, 실패하면 게시하지 않고 사유 기록 → 글 기록 파일에 주소·주제·출처·날짜 기록 → 깃에 올림(매일 루프와 같은 방식). 새벽 실행이라 클로드 5시간 사용 창이 아침 전에 끝나 낮 작업(영상 제작) 한도와 겹치지 않는다. 한도에 걸리면 그날은 건너뛰고 다음 글 쓰는 날에 이어 간다(밀린 글을 몰아 올리지 않음).
- **API로 링크를 못 만들 때(오류·호출 한도·맞는 상품 없음)**: 링크가 꼭 필요한 글이면 게시하지 않고 다음 글 쓰는 날로 미룬다. 링크 없이도 완결되는 글이면 링크 없이 올린다(대가 문구는 그대로). 새벽에 쿠팡 화면을 브라우저로 열지 않는다.
- **첫 1편**: 자동 일정을 켜기 전에 대화 안에서 1편을 만들어 사용자에게 보여 주고, 반응을 들은 뒤 일정을 켠다.

### 6-3. 영어 블로그

- **언제**: 롱폼을 예약할 때 마무리 체인(AGENTS.md 0번 12항)에 "복습 글 만들기"를 더한다. 글은 영상 공개 시각에 맞춰 예약 게시한다.
- **글 구성**: 그 영상 임베드 / 영상에 나온 단어·문장(철자 음절 표시는 composition-rules 규칙 그대로) / 단어마다 "다시 듣기" / 짧은 퀴즈 / 같은 소재 쇼츠 링크.
- **소리(제안)**: 별도 소리 파일을 올리지 않고, 페이지의 영상 임베드를 그 단어가 나오는 시각으로 옮겨 재생한다(시각은 `assets/voice/*.words.json` 실측값). 소리 파일을 둘 곳이 필요 없고, 블로그에서 듣는 것이 유튜브 재생으로도 쌓인다. 이 방식이 어려우면 빌더가 다른 방법을 고른다.
- **유튜브 쪽**: 업로드 패키지의 설명란에 그 복습 글 주소를 넣는다(새 영상부터). 글 주소가 미리 정해져야 하므로 글을 먼저 예약 게시하고 주소를 받는다.
- **광고**: 소리·퀴즈 버튼 근처에 광고가 나오지 않게, 자동 광고 대신 글 끝 등 정해진 자리에만 둔다. 글이 거의 없는 화면에는 광고를 켜지 않는다.
- **첫 1편**: 다음 롱폼 예약 때 만들어 사용자에게 먼저 보여 준다.
- **첫 편 검토와 설명란 순서 (Claude 판단)**: 복습 글을 영상 공개 시각으로 예약 게시하면 그때 주소가 정해지고, 글 내용을 나중에 고쳐도 주소는 그대로다. 그래서 순서는 ① 글 예약 게시(주소 받기) → ② 그 주소를 넣어 영상 업로드·예약 → ③ 영상 공개 전에 사용자가 글을 보고 반응 → 필요하면 예약된 글만 고친다. 영상은 공개 전이라 "이미 올린 영상은 고치지 않는다"와 부딪히지 않는다. 공개 시각까지 반응이 없으면 점검을 통과한 그대로 공개된다.

### 6-4. 자동 점검 (게시 전, 하나라도 걸리면 게시하지 않는다)

1. 쿠팡 블로그: 첫머리 대가 문구 원문 일치. 쿠팡 링크가 있으면 문구 필수, 없어도 문구는 둔다(블로그 공통).
2. 써 본 척 낱말·표현(6-2 목록)과 지어낸 1인칭 경험.
3. 출처 링크 1개 이상, 모두 열림(200).
4. 한글 AI 티 검사(`slop-rewrite` 코드 검사기)와 금지어 검사(`check-terms`).
5. 이미 쓴 주제와 겹침(글 기록 파일).
6. 영어 블로그: 소리·퀴즈 버튼과 광고 자리의 거리(화면을 열어 측정), 휴대폰 폭에서 글자 크기.
7. 게시 뒤: 바깥에서 주소를 열어 200, 대가 문구가 화면에 보이는지 확인.

### 6-5. 검색 등록

- 구글: 서치 콘솔 `sc-domain:d40m.com`에 두 블로그 사이트맵 제출(`/u/1/`).
- 네이버 서치어드바이저: 블로그마다 사이트 등록, HTML 태그 확인(구글 블로그 테마에 넣기), 사이트맵·RSS 제출 → **네이버 로그인 필요(사용자)**.
- 다음 웹마스터도구: 블로그마다 등록, 확인 방식은 다음이 요구하는 대로(로봇 파일 PIN 등) → 카카오 로그인(프로젝트 크롬에 이미 있음).

### 6-6. 결과 보고 배우기

- 글 기록 파일(예: `data/blog/posts.json`)에 블로그·주소·주제·출처·게시일.
- 4주마다 서치 콘솔(노출·클릭·순위)과 구글 블로그 통계, 쿠팡 파트너스 수익, 애드센스 하위 주소별 수입을 모아 어떤 주제·글 종류가 됐는지 본다. 숫자는 실제 데이터만, 없으면 "측정 전".
- 영어 블로그는 유튜브 쪽 지표(설명란 링크 유입은 블로그 통계의 유튜브 유입)로 연계 효과를 본다.

### 6-7. 멈춤 조건과 알림 (Claude 판단, 검토 단계 지적 반영)

- **자동으로 멈추는 신호**: 서치 콘솔 "직접 조치"·"보안 문제"(d40m.com), 애드센스 정책 경고, 쿠팡 파트너스 경고·제재, 점검 실패 3번 연속. 하나라도 보이면 쿠팡 블로그 자동 일정이 스스로 멈춘다(새 글만 멈추고 올린 글은 그대로).
- **다시 켜기는 사용자 승인**: 애드센스가 유튜브와 같은 계정이라 수익에 걸린 일(AGENTS.md 🔴 권한선)이다. Claude는 원인과 근거를 보고하고, 사용자가 "다시 켜"라고 할 때만 켠다.
- **누가 어디서 보나**: 서치 콘솔 신호는 매일 루프나 글쓰기 실행 때 서치 콘솔 공식 통로로 확인한다(`/u/1/` 계정 허락 필요, 6-8). 애드센스·쿠팡 경고는 공식 통로가 없을 수 있어 시작 브리핑 때 대화 안에서 화면을 열어 본다(주 1회).
- **알림**: 시작 브리핑에 한 줄 — 지난 브리핑 뒤 올린 글 수, 건너뛴 날과 이유(한도·점검 실패·링크 없음), 대기열 남은 수, 멈춤 여부. 따로 알림 앱은 만들지 않는다.
