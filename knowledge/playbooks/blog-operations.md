# 쿠팡 블로그 운영 지침 (`tech.d40m.com`)

이 문서는 쿠팡 파트너스 연동 블로그(`tech.d40m.com`)의 주간 경고 점검, 긴급 멈춤·재개, 주제 보충 절차를 정리한다.

---

## 1. 주 1회 경고 화면 점검 순서

시작 브리핑에서 `경고 화면 점검 필요`가 뜨거나 일주일에 한 번 아래 세 곳을 순서대로 확인한다.

1. **구글 서치 콘솔** (`sc-domain:d40m.com`)
   - **직접 조치** 메뉴와 **보안 문제** 메뉴에 경고·안내 문구가 없는지 확인한다.
2. **구글 애드센스 정책 센터**
   - 사이트별·계정별 정책 위반이나 광고 제한 경고가 없는지 확인한다.
3. **쿠팡 파트너스 공지 및 이메일**
   - 공지사항과 연결된 이메일함에 제재·대가 문구·링크 위반 경고가 없는지 확인한다.

확인이 끝나면 `data/blog/signal-checks.json` 배열 끝에 아래 형식으로 한 줄을 추가한다.

```json
[
  {
    "date": "2026-11-25",
    "searchConsole": "ok",
    "adsense": "ok",
    "coupang": "ok",
    "note": "특이사항 없음"
  }
]
```

- 이상이 없으면 `'ok'`, 경고나 제한 알림이 있으면 `'warning'`으로 적고 `note`에 화면 문구 요약을 남긴다.

---

## 2. 경고 발견 시 즉시 처리

세 화면 중 하나라도 `'warning'`이 확인되면 **그 자리에서 자동 발행을 멈춘다.**

1. `scripts/blog/blog-store.mjs`의 `writePause`로 `data/blog/tech-paused.json`을 멈춤 상태로 기록한다.
   - `reason`에 어느 화면에서 어떤 경고가 떴는지 구체적으로 적는다.
2. `data/blog/signal-checks.json`에도 해당 항목을 `'warning'`으로 기록한다.
3. 확인한 화면 문구(원인·근거)와 멈춤 사실을 사용자에게 보고한다.

---

## 3. 다시 켜기 규칙 (사용자 승인 필수)

- `tech.d40m.com`은 **유튜브 채널과 같은 애드센스 계정**을 쓴다.
- 따라서 어떤 사유로든(`점검 실패 3회 연속` 또는 `경고 감지`) `data/blog/tech-paused.json`의 `paused`가 `true`가 된 뒤에는, **반드시 사용자의 명시적 승인을 받은 뒤에만** `paused`를 `false`로 바꾸고 다시 켠다.
- AI나 자동화 스크립트가 임의로 멈춤 상태를 해제하지 않는다.

---

## 4. 주제 보충 방법 (대기열 6개 미만일 때)

시작 브리핑에 `대기열 N개(주제 보충 필요)`가 뜨면 아래 순서로 주제를 채워 `data/blog/tech-queue.json`에 추가한다(목표: 2~4주 분량 유지).

1. **옛 서치 콘솔 검색어 내보내기**
   - 프로젝트 크롬 첫 번째 계정(`/u/0/`)으로 서치 콘솔에 들어가 `sc-domain:k-posting.info`·`sc-domain:costcatcher.k-posting.info`의 **실적 → 검색어 → 기간 최대 → 내보내기(CSV)** 를 받아 `data/blog/sources/`에 둔다.
2. **지금도 찾는 문제 해결 주제 고르기**
   - 클릭·노출 상위 검색어 가운데 사람들이 실제로 불편을 겪어 찾는 문제를 고른다.
   - 구글·네이버 자동완성과 지식인 질문으로 현재 검색 수요가 살아 있는지 확인한다.
3. **다루지 않는 위험 주제 제외**
   - 감전·화재·가스·분해 수리·비공식 개조 등 위험 단계만 남은 주제는 뺀다.
   - 안전하게 확인 가능한 자가 점검·설정·소모품/호환 부품 교체 안내 위주로 구성한다.
   - 옛 글 문장이나 표현은 그대로 가져오지 않는다.
4. **`data/blog/tech-queue.json` 추가**
   - `fix`(문제 해결 순서)와 `before-buy`(사기 전 호환·규격 확인) 유형(`kind`)을 섞고, `topicId`가 겹치지 않게 넣는다.
   - 모든 항목에 `sourceHints`(공식 지원/제조사 문서 경로 등 1개 이상)를 채운 뒤 저장한다.

## 5. 블로그 정책·규칙 및 공통 안전선 (2026-11-26 사용자 확정)

상세 근거: `knowledge/decisions/2026-11-26-blog-policy-rules-loop-draft.md`.

1. **유튜브와 분리 및 공통 안전선**:
   - 블로그 고유 규칙(공정위 추천보증 심사지침 대가 문구, 쿠팡 금지행위 11가지 준수, 검색엔진 스팸 방지, 무인 일정 자동화)은 이 문서와 블로그 글쓰기 지침(`scripts/blog/prompts/tech-post.md`)을 원본으로 한다.
   - 유튜브와 공통 안전선(동일 애드센스 계정 보호, 경험 날조 금지, 성과 숫자 실제 데이터 원칙, AI 티 검사 필수, 저작권 준수)은 철저히 함께 지킨다.
2. **글 게시 전 팩트체크 (프로그램 1:1 대조 검사)**:
   - 사람의 수동 검토 피로를 방지하기 위해 사람이 검토하는 대신, 프로그램이 공식 출처 웹페이지 본문을 읽어와 인용문과 1:1 글자 단위로 대조한다(따옴표 정규화 포함).
   - 인용문 대조가 통과된 글만 자동으로 게시된다.
3. **성과 없는 글 수정 허용 (결과 루프)**:
   - 발행 후 4주 동안 검색 노출/유입이 0인 글은 검색 유입 개선을 위해 AI가 제목 및 도입부를 자동으로 보완·수정할 수 있다.
4. **쿠팡 파트너스 공식 서면 회신 보관 및 상품 이미지 미사용 확정 (2026-11-26, 파트너스 ID `AF4472063`)**:
   - 문의(2026-11-25 23:58): 오픈 API `productImage`·상세페이지·상품평 이미지 사용 허용 범위 서면 확인 요청.
   - 쿠팡 파트너스 공식 회신(2026-11-26):
     - 쿠팡 입점 공급사·판매자별 저작권 방침이 달라, 허용되지 않은 곳에 콘텐츠가 게재될 경우 **일부 공급사·판매자가 상표권 등 지식재산권 침해로 법적 조치**를 취할 수 있음.
     - 쿠팡 **상품평 등 게시물 무단 사용의 법적 책임은 파트너스 회원**에게 있으므로 무단 사용 금지.
     - 파트너스 활동은 제공되는 콘텐츠(배너 등) 위주로 안내하며, 상세페이지·제품 이미지 컷도 개별 판매자나 쿠팡으로부터 **블라인드 요청**이 발생할 수 있음.
   - 운영 기준 확정: 쿠팡 상품평·상세페이지·제품 이미지는 블로그 본문에 쓰지 않고, **자체 제작 대표 그림 1장(문제 순간만, 브랜드·로고·인물 추천 연출 없음) + 글자 링크** 원칙을 유지한다.
