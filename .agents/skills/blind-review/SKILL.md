# 백지 눈 패키징·대본 검수 (1회 점검)

> **권장 모델**: **최상위 모델** (`Gemini 4 Neon` / `Claude Opus 5.5`). 초안을 쓴 대화의 변명을 배제하기 위해 **초안 대화와 분리된 문맥**(Claude Code는 `opus-expert` 서브에이전트, 안티그래비티는 새 대화)에서 **정확히 1회**만 실행한다(무한 반복 검수로 개성이 깎이는 함정 방지). 기획 순서상 자리는 `episode-planning` 로드맵 8.5(시트 제출 직전)다.

## 이 검수가 하는 일과 하지 않는 일
- 하는 일: 사람이 처음 보는 눈으로 "멈추게 하는가, 어긋난 곳은 없는가, 귀에 거슬리는 반복은 없는가"를 묻는다.
- 하지 않는 일: 글자 수·문구 틀·특정 칩(예: 영상 길이 칩)·특정 말투를 정답으로 강요하지 않는다. 아래 일곱 기준은 **질문**이지 공식이 아니다. 기준마다 따로 답한다(한 칸에 여러 질문을 몰면 하나만 약해도 묻힌다 — HD-Eval ACL 2024·DeCE EMNLP 2025, 2026-11-28 사용자 확정). 기준을 맞추려고 원하지 않는 장치를 끼워 넣지 않는다(채널 제1 슬로건: 방법 비고정).

## 절차

1. **실물 먼저 열기 (요약만 보고 판단 금지)**
   - 비교 시트(`data/youtube/transform-sheets/<id>.json`)의 제목 후보·썸네일 행·대본 행, 대표 썸네일 **실물 이미지**(시트가 가리키는 `images/...` 파일)를 직접 연다.
   - 대본은 시트 안의 대본 행이 기준이다. 초안 파일(`videos/<id>/SCRIPT.md`)이 이미 있으면 같이 본다. **승인 전에는 음성을 만들지 않으므로** 음성 파일·음성 검수표는 볼 대상이 아니다.
   - 썸네일 시안은 **원래 크기로 한 번, 검색 피드 크기(약 200px)로 한 번** 본다. 시안 전부와 시트 썸네일 근거(`craft`)가 가리키는 참고 썸네일을 **나란히** 놓는다(그림 한 장만 봐서는 한 틀 평균값이 안 보인다).
   - 대표님 1:1 과외방 기록(`data/youtube/creator-study/<id>.json`)이 있으면 대표님이 직접 남긴 질문·막힘·고친 문장만 골라 읽는다(AI가 미리 채운 시청자 질문 초안은 제외). 없으면 건너뛴다.
2. **자동 바닥선 먼저 확인**
   - 한국어 낭독문만 뽑아 `slop-rewrite`(실행 위치는 저장소 `tools/slop-rewrite`, 명령은 `slop-rewrite` 스킬 4번)와 `node scripts/check-narration-naturalness.mjs`를 돌린다.
   - 이 검사는 최소 바닥선일 뿐이다. 같은 진행 멘트 반복(예: 2026-11-27 EP37 "들어 볼게요" 16회)은 검사가 0건이어도 남을 수 있으니, 3단계에서 직접 센다.
3. **일곱 기준 (예/아니오 + 근거 1줄)** — 형식(쇼츠·롱폼·틀어 놓고 듣기 등)과 이번 편의 참고 영상에 맞춰 판단한다.
   - `mobileTitleOk`: 휴대폰 화면에서 제목이 잘리기 전에 핵심(누구의 어떤 고민인지)이 보이는가? 기호 남발·교과서 목차체·내용과 다른 기대(말하기인데 듣기처럼 읽힘 등)는 없는가? 소재 자체가 3060이 굳이 눌러 볼 구체적인 고민인가(교과서 목차가 아닌가)?
   - `thumbOneSecOk`: 썸네일 실물을 1초 봤을 때 감정·상황이 꽂히는가? 강사 용어·정답 스포일러가 없는가? 썸네일이 약속하는 것(내용·형식·길이)이 실제 영상과 어긋나지 않는가?
   - `synergyOk`: 썸네일이 던진 호기심을 제목이 받아 한 방향으로 가는가(같은 말을 두 번 하거나 서로 다른 얘기를 하지 않는가)?
   - `openingOneMinOk` (초반 후킹): 들어오자마자 썸네일·제목이 한 약속을 바로 이어받는가? 사용 설명서·긴 목차 예고로 늘어지지 않고 곧바로 시청자의 귀·눈 체험으로 들어가는가? (얼마나 빨라야 하는지는 형식과 참고 영상의 도입을 보고 정한다. 초 숫자를 정답으로 두지 않는다.)
   - `antiSlopVoiceOk` (대본 귀 검사): 아래가 **없는가**만 본다 — ① 같은 진행 멘트·끝맺음의 기계적 반복 ② 존댓말/반말 어긋남 ③ 화면 글자·자막과 낭독·번역의 불일치 ④ 딱딱한 강의체·사전 문장 나열 ⑤ 글처럼 꾸민 말(예: 대표님이 고친 "귀가 편해져요"→"듣기가 편해져요", "소리 내어"→"소리 내서"). `knowledge/creator-voice-card.md`의 예시는 결을 참고하는 자료이고, 그 말투와 다르다는 이유만으로 `false`를 주지 않는다(흉내 내기 금지).
   - `midVisualLearningOk` (중반 화면·학습 뼈대): 긴 설명 구간마다 화면이 무엇으로 바뀌는지 컷 계획에 있는가(말로만 때우거나 코드 상자만 깔린 구간이 없는가)? 듣고 흘리는 강의가 아니라 시청자가 직접 맞혀 보고 귀로 확인할 틈이 있는가? 대표님 과외방에 막힌 곳이 있으면 대본에서 풀리는가(기록이 없으면 이 부분은 해당 없음)? 실제 화면 멈춤·싱크는 렌더 직전 검수(`knowledge/VIDEO_WORKFLOW.md`)가 본다.
   - `thumbCraftOk` (썸네일 그림 AI 티): 원래 크기와 피드 크기에서 의미 없는 잡소품·어색한 합성·깨진 글자·재생 시간 표시 자리를 가리는 요소가 없는가? 시안들과 참고 썸네일을 나란히 놓았을 때 시안끼리 같은 틀(예: 2026-11-25 EP37 배경 사진+어두운 덮개+글자 두 줄)로 찍혀 있지 않은가? 워터마크는 자동 검사가 막으므로 여기서 다시 보지 않는다.
4. **시트 기록 (`blindReview` 칸)**
   - 비교 시트 최상단 `blindReview`에 아래 구조로 적는다. v4 시트는 이것이 없으면 승인이 막힌다(예외는 잠금 전에 있던 EP31~37 7편뿐이고 작성일로는 예외를 주지 않는다. 이미 다섯 기준으로 검수를 마친 EP37은 다섯 기준으로만 본다. 새 시트는 4판이어야 해서 판 번호를 빼거나 낮춰도 피할 수 없다). `reviewContext`(초안과 어떻게 분리했는지)가 비어도 막힌다 — 초안을 쓴 대화가 스스로 통과를 적지 않는다. 결과는 대시보드 시트 화면의 승인 버튼 바로 위에 보인다.
   ```json
   "blindReview": {
     "reviewedAt": "YYYY-MM-DD",
     "reviewerModel": "실제 검수 모델명",
     "reviewContext": "어떻게 분리했는지 (예: opus-expert 서브에이전트, 안티그래비티 새 대화)",
     "checks": {
       "mobileTitleOk": true,
       "thumbOneSecOk": true,
       "synergyOk": true,
       "openingOneMinOk": true,
       "antiSlopVoiceOk": true,
       "midVisualLearningOk": true,
       "thumbCraftOk": true
     },
     "findings": ["발견한 개선점 또는 수정 반영 요약"],
     "verdict": "pass"
   }
   ```
   - 하나라도 `false`이면 `verdict`를 `"needs_fix"`로 두고 개선안을 낸다. 고친 뒤에는 검수자가 고친 부분만 다시 확인하고, 일곱 개가 모두 `true`일 때만 `"pass"`로 바꾼다. 무엇을 고쳤는지 `findings`에 남긴다.
